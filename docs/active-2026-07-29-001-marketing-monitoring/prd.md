# 营销监控系统 PRD

- 状态：Active（真实授权、搜索报表与百度统计响应已进入白名单数据试点，等待完整生产验收）
- 日期：2026-07-29
- 需求依据：`docs/ideas/marketing-monitoring-system.md`
- 领域术语：`CONTEXT.md` 中的“营销监控语言”

> 定位说明：本 PRD 描述只读市场数据监控系统的百度第一期，不定义整个项目的最终边界。第一期仍受限于百度白名单试点，不代表项目是单一 GEO/SEO 系统，也不代表全链路已经接入。

> 2026-08-03 实现补充：本地正式代码路径已覆盖推广计划、推广单元、投放关键词和独立搜索词四份官方报告，并以同一次刷新原子落库；广告表现严格下钻到投放关键词。搜索词报告没有关键词 ID，因此不进入关键词严格子树，也不得按名称伪造关联。同日已使用服务器现有生产 Token 完成四份真实响应只读验证；第二阶段业务变更仍未推送、部署或完成正式入口验收。

## Problem Statement

市场负责人目前需要分别进入百度营销、官网落地页系统和内部销售系统查看数据。三个系统彼此独立，也没有统一业务 ID，无法在一个项目视角下持续观察广告投入、原始咨询和订单签订结果。

第一期立项时只有百度营销具备已确认的可接入 API，因此本期先解决市场负责人需要登录百度、跨多个搜索账户核对项目投入且外部接口失败时没有本站快照的问题。2026-08-04 官网表单聚合已在本地工作区通过独立 `/api/website-data` 接入并完成线上合同只读核对，但第二阶段业务变更尚未推送、部署或生产验收；销售系统仍没有已确认的稳定 API。第一期百度边界不因该并行接入而扩大，也不通过人工录入、Excel 或假数据模拟尚未接入的数据源。

## 长期愿景

系统的长期产品边界是项目级只读市场数据监控入口，最终联合观察以下链路：

```text
百度广告或自然访问
  → 官网表单或咨询
  → 市场部确认并进入销售线索池
  → 销售从线索池承接并沟通
  → 确认进一步合作意向并形成正式销售机会
  → 沟通完成后建立订单
  → 订单签订金额
```

数据接入只保留决策所需事实：百度营销提供付费广告展现、点击和消费；百度统计提供网站来源、访问次数、UV 和 PV；官网成功表单提供“表单咨询”及其记录级来源关系；53KF 提供访客实际发送过消息的在线客服有效对话；销售侧提供线索入池数、人工关联所需的最小订单标识、成交订单数和成交订单金额。成交订单数用于 CPA 与转化率，成交订单金额用于 ROAS。来源系统没有统一来源键时，由用户为每笔成交订单确认一条主要咨询来源，不建设未经确认的自动身份匹配或多触点归因。完整决策见 `../adr/0001-marketing-funnel-data-source-of-truth.md`。

这是长期目标，不是第一期已交付范围。第一期仍以白名单百度真实数据试点和完整生产验收为边界。

## Solution

在现有单体应用中交付独立的“营销监控”模块：

1. 管理员授权百度营销账户，并把一个或多个百度搜索推广账户绑定到监控项目。
2. 系统只读获取最近 30 个自然日的展现量、点击量和广告消费，保存为本地快照。
3. 页面访问时检查本地快照；快照缺失或达到 10 分钟时按需刷新，否则直接读取数据库，用户也可主动刷新。
4. 一次项目刷新覆盖全部活动绑定：全部读取成功才整体替换快照，任一失败则保留完整旧快照。
5. 市场负责人查看项目汇总、按日趋势，以及账户、推广计划、推广单元和投放关键词明细，并可独立查看搜索词事实、跳转回百度营销处理业务；本地实现已经完成，生产真实响应与入口验收仍是开放门禁。
6. 官网表单咨询由独立官网数据模块接入，不进入百度模块；后续在官网生产合同完成源码同步、最小权限身份与正式入口验收，且 53KF 和销售系统具备稳定只读 API 后，再增加在线客服咨询、线索入池、成交订单数、成交订单金额和来源关系。

本系统只用于观察，不修改百度投放数据，也不承接咨询、销售或订单作业。

## User Stories

1. **US-001**：作为管理员，我希望授权、重新授权和断开百度营销连接，以便控制系统可读取的账户。
2. **US-002**：作为管理员，我希望把百度搜索推广账户绑定到监控项目，以便数据归入正确品牌或业务线。
3. **US-003**：作为市场负责人，我希望进入页面后立即看到最近一次成功快照，以便不等待百度接口。
4. **US-004**：作为市场负责人，我希望访问页面时最多复用 10 分钟数据库缓存，并允许我主动刷新；无人使用时不消耗百度 API，首页不常驻显示陈旧提示。
5. **US-005**：作为市场负责人，我希望查看最近 30 天内的汇总、趋势，以及账户、推广计划、推广单元和投放关键词明细。
6. **US-006**：作为市场负责人，我希望刷新失败时仍能看到完整旧快照及其时间。
7. **US-007**：作为市场负责人，我希望知道当前连接、绑定、快照和刷新分别处于什么状态。
8. **US-008**：作为市场负责人，我希望跳转到百度营销处理投放调整。
9. **US-009**：作为市场负责人，我希望明确知道落地页和销售数据尚未接入，避免把百度数据误认为完整业务漏斗。

## Scope

### In scope

- 在现有应用中增加独立营销监控模块，复用现有用户、管理员和项目权限。
- 第一期只支持百度搜索推广（SEARCH）。
- 管理员发起授权、接收授权结果、重新授权和断开连接。
- 加密保存访问凭据；Token 到期时按已确认的百度契约刷新。
- 一个项目可绑定一个或多个百度搜索推广账户。
- 绑定范围只到整个外部账户，不支持选择部分推广计划。
- 只读获取并展示：
  - 展现量；
  - 点击量；
  - 广告消费；
  - 项目汇总；
  - 按日趋势；
  - 按账户、推广计划、推广单元和投放关键词明细；各层只使用对应官方报告，不从计划数据推断；
  - 独立搜索词事实；百度未返回关键词 ID 时不得用名称补造严格归属。
- 本地只保留当前绑定口径下最近 30 个 Asia/Shanghai 自然日的活动快照。
- 页面日期筛选只查询当前本地快照，不触发历史回补。
- 页面进入时读取本地快照；快照缺失或距最近成功刷新达到 10 分钟时，由该次访问触发刷新并等待结果。同项目并发访问合并为一次上游调用；没有访问时不调用百度。
- 用户可点击“立即刷新”。
- 项目刷新采用全有或全无：所有活动绑定读取成功才替换项目快照。
- 显示数据覆盖范围、最后成功时间、来源健康和刷新状态。
- 断开本地连接后暂停相关绑定并清除 Token 密文；若百度提供正式撤权能力则同时调用，否则明确引导管理员到百度控制台撤权。以后重新授权后由管理员确认恢复或重新绑定。
- 归档项目只读，继续展示归档时保存的快照覆盖范围。
- 提供“前往百度营销”的外部跳转。
- 页面可用静态文字说明未来会接入落地页和销售数据。

### Out of scope

- 修改预算、出价、计划、关键词、创意或任何百度来源数据。
- 百度信息流和创意层级监控；搜索词已作为独立报告接入，不属于创意或关键词严格子层级。
- 选择部分推广计划作为项目绑定范围。
- 自定义同步日期、历史回补或保存无限历史事实。
- 部分账户成功后混合展示新旧数据。
- 在本系统中处理咨询、线索、机会、销售或订单。
- 自动身份匹配、自动归因和多触点归因。
- 有效线索数、销售机会数、毛利、回款或营业收入。
- 用 CSV、Excel 或人工录入模拟尚未开放的来源 API。
- 微服务、消息队列、数据仓库、通用 ETL 或通用连接器平台。

### Later

- 推广计划、推广单元、投放关键词和搜索词四份真实响应已使用生产 Token 完成只读验证；仍需保存新增层级脱敏 fixture，并与百度后台按相同账户、日期、时区和口径核对。完成部署前不得把本地四报表实现描述为生产已生效。
- 对齐官网生产实际源码、schema、迁移和测试后，由 GoodieAI 后端只读接入现有聚合统计 API，获取按来源归属的表单咨询；常规同步不读取联系人明细。
- 接入 53KF 有效对话 API 和销售系统 API，分别获取在线客服咨询、线索入池数、最小订单标识、成交订单数和成交订单金额。
- 缺少统一来源键时，由用户为每笔成交订单确认一条主要咨询来源。
- 建立按来源展示广告投入、展现、访问（点击）、客服咨询、线索入池、成交订单数和成交订单金额的联合观察视图。
- 有明确业务需求、只读权限并完成搜索推广生产验收后，再单独设计百度信息流支持。

## Product Behavior

### 1. 项目与访问

- 页面必须处于用户有权访问的监控项目中。
- 一个项目可绑定多个百度搜索推广账户，页面汇总这些账户的数据。
- 页面明确展示项目、数据覆盖范围和已绑定账户。
- 活动项目可刷新；归档项目只能查看归档时保存的快照。
- 无权限用户不得看到连接信息、绑定信息或营销数据。
- 第一期明确继承现有项目查看权限：能查看项目的用户也能查看该项目的广告账户、推广计划和消费；发布前由业务负责人确认该权限继承符合内部数据授权。

### 2. 授权、连接与断开

- 只有管理员可以新增、重新授权、断开连接和管理绑定。
- 授权前说明读取范围和“只读监控、不修改投放”。
- 普通接口先创建一次性授权尝试，只返回本站同源的一次性启动地址；启动地址再跳转百度。
- 百度回调必须校验一次性状态、有效期、发起管理员、目标连接和授权代次。
- 回调处理完成后只跳转到不带敏感查询参数的本站结果页。
- 页面、浏览器地址、普通接口、代理、APM 和常规日志不得暴露 Token、Secret、授权码或原始 state。
- Token 到期时，系统按联调确认结果处理“不返回、返回相同值、返回新值”三种 Refresh Token 情况。
- 断开连接后立即阻止新目录查询和刷新，清除 Token 密文，并暂停相关绑定。百度侧撤权能力以真实契约为准；不支持 API 撤权时页面提供控制台操作说明。
- 重新授权或重新连接不会自动恢复旧绑定；管理员确认外部账户仍匹配后才能恢复或重新绑定。
- 失败、过期、重放或晚到的授权回调不得覆盖更新的连接状态。

### 3. 项目绑定

- 管理员从已授权连接可读的百度搜索推广账户中选择整个账户绑定项目。
- 同一真实外部账户第一期只能属于一个活动监控项目，不能通过不同连接重复绑定；混合多个品牌的百度账户不适合第一期整账户绑定。
- 未绑定时展示“百度已连接，但尚未绑定项目”。
- 暂停任一绑定后完整项目旧快照仍可查看，并显示受影响账户与来源健康警告；为保持项目口径一致，整个项目都不能刷新，直到管理员恢复、改绑或解除该绑定。
- 恢复或改绑前重新校验连接、外部账户归属和项目状态。
- 绑定变更后，旧口径快照不得继续作为当前活动项目数据；首次新口径刷新成功前展示初始化状态。
- 解除绑定不修改百度来源数据。

### 4. 页面读取与日期筛选

- 页面一次读取同一快照版本的汇总、趋势、推广计划、推广单元、投放关键词、独立搜索词集合和逐绑定健康状态。
- 默认筛选快照覆盖范围内最近 30 个自然日。
- 活动项目的固定同步窗口为当前日期及向前共 30 个 Asia/Shanghai 自然日。
- 用户只能在本地快照覆盖范围内调整起止日期；筛选不会调用百度或改变同步窗口。
- 归档项目默认使用已保存的覆盖范围，不能因为当前日期推进而显示空白窗口。
- 每层明细必须保留百度账户和全部稳定父级 ID；关键词使用关键词 ID，搜索词明确不提供关键词 ID，避免多账户同名或名称关联混淆。
- 指标计数与金额必须保持精确值，页面明确货币和金额口径。

### 5. 按需与手动刷新

- 最后成功更新时间不超过 10 分钟时，页面直接读取数据库快照，不调用百度。
- 没有快照或快照达到 10 分钟时，该次 dashboard GET 创建 `ON_DEMAND` 运行并等待刷新；同项目并发请求共享同一运行。
- 没有用户访问营销入口时不创建刷新运行，也不调用百度。
- 按需刷新失败且已有历史快照时仍返回最后成功快照；从未成功同步时返回明确错误。首页不显示“数据陈旧”或更新时间。
- 有查看权限的活动项目用户可以手动刷新；归档项目不能刷新。
- 同一项目同一时间最多有一个活动刷新。
- 刷新固定读取全部活动绑定的最近 30 天数据，不接受自定义日期。
- 全部账户读取成功后，在同一事务中替换项目活动快照。
- 任一账户读取失败、中断或项目在提交前被归档时，不写入新事实，完整旧快照继续可见。
- 刷新不会突破百度自身的统计延迟。

### 6. 独立状态

页面不得用一个笼统状态混合表达所有问题，而应分别展示：

- 模块状态：未启用、可用、配置或结构异常；
- 项目状态：活动、归档；
- 来源状态：未连接、已连接、需重新授权、已断开；
- 绑定状态：未绑定、活动、暂停；
- 快照内容：无快照、真实零数据、有数据；
- 快照新鲜度：不适用、新鲜、陈旧；
- 刷新状态：空闲、排队、运行、成功、失败、中断；
- 覆盖范围：快照起止自然日和最后成功时间；
- 逐绑定健康：每个账户的连接、绑定、阻断原因和可恢复操作。

读取接口即使来源异常，也应返回本地快照和上述业务状态。只有无权、请求格式错误或写操作冲突等情况使用错误响应。

### 7. 只读与外部跳转

- 页面不出现修改来源数据的控件。
- “前往百度营销”明确提示用户将离开当前系统。
- 落地页和销售系统未接入时仅显示静态说明，不建立假卡片、假状态或假漏斗。

## Acceptance Criteria

- **AC-001**：管理员可从产品内发起百度授权；普通接口只返回本站同源的一次性启动地址。
- **AC-002**：有效回调能建立或更新连接；无效、过期、重放、晚到或管理员已失效的回调不能覆盖当前连接。
- **AC-003**：Token、Secret、授权码和原始 state 不出现在页面、浏览器地址、普通接口、代理、APM 或常规日志。
- **AC-004**：本地断开后 Token 密文被清除，相关绑定暂停，目录查询和刷新不再调用百度；百度侧撤权按已确认能力执行或明确转人工。
- **AC-005**：重新授权后旧绑定不会自动恢复；管理员确认账户后才能恢复或重新绑定。
- **AC-006**：项目可绑定一个或多个搜索推广账户，同一真实外部账户不能重复绑定或同时属于多个活动项目。
- **AC-007**：第一期不存在信息流、推广计划子集绑定或写入百度的能力。
- **AC-008**：有权用户能一次读取同一快照版本的汇总、按日趋势、计划、单元、关键词、独立搜索词集合和逐绑定健康状态。
- **AC-009**：计划、单元和关键词明细包含账户及稳定父级 ID、名称、展现、点击和广告消费；搜索词保留计划/单元 ID、关键词名称和搜索词，但不伪造关键词 ID。
- **AC-010**：活动项目固定同步最近 30 个 Asia/Shanghai 自然日，刷新接口不接受自定义日期。
- **AC-011**：日期筛选只在当前本地覆盖范围内计算，不调用百度、不触发历史回补。
- **AC-012**：dashboard GET 在 10 分钟缓存有效期内纯读数据库；缓存缺失或过期时由该次访问创建一个 `ON_DEMAND` 运行并等待完成，无访问时不产生百度调用。
- **AC-013**：重试退避不改变快照是否陈旧的判断。
- **AC-014**：同一项目最多一个活动刷新；并发访问不造成重复外部刷新。
- **AC-015**：全部活动绑定读取成功后才整体替换快照；任一失败时不产生混合新旧快照。
- **AC-016**：失败或中断时完整旧快照、覆盖范围和最后成功时间保持可见。
- **AC-017**：真实零数据与从未成功同步使用不同快照状态。
- **AC-018**：Refresh Token 未返回或返回相同值时保留原值，返回新值时安全替换；行为以版本化真实契约证据为准。
- **AC-019**：并发 Token 刷新只发生一次外部刷新调用，晚到结果不能覆盖更新代次。
- **AC-020**：指标与外部 ID 全链路保持精确，不经 JavaScript `Number` 丢失精度。
- **AC-021**：计划、单元、关键词和搜索词都按各自稳定事实身份去重，重复同步不产生重复事实。
- **AC-022**：项目归档与快照提交互斥；归档先完成时，晚到刷新不得写入。
- **AC-023**：归档项目默认展示保存的快照覆盖范围且不能刷新。
- **AC-024**：页面不提供任何百度写操作，并提供明确的外部跳转。
- **AC-025**：落地页和销售系统未接入时只显示静态说明，不产生模拟咨询、订单或完整漏斗。
- **AC-026**：真实百度样本在相同账户、日期、时区和统计口径下与百度后台一致。
- **AC-027**：百度暂时不可用时，旧营销快照和现有 GEO/SEO 功能不受影响。
- **AC-028**：生产验收完成一次真实授权、报表读取和 Refresh Token grant，并按已确认契约正确处理返回结果。
- **AC-029**：业务负责人确认现有项目查看权限可以继承广告账户、计划和消费的查看权限。

## Success Criteria

- 至少一个真实百度搜索推广账户完成授权、账户绑定和生产数据获取。
- 市场负责人能在单页核对项目汇总、趋势和推广计划明细。
- 目标市场用户无需进入百度即可完成一次项目广告数据核对；只有需要调整投放时才离开本站。
- 真实样本与百度后台相同口径一致，重复刷新不产生重复数据。
- 外部接口失败时完整旧快照仍可用，用户能判断来源、刷新和覆盖状态。
- 系统未向百度写入数据，也未为未来来源制造假数据。

## Constraints and Contract Gate

- 保持现有单体应用和单进程运行方式，不引入通用数据平台。
- 已按官方文档确认并实现授权、签名 callback、Token、账户目录与搜索计划报告请求；真实响应解析、金额、时区和刷新轮换仍须用获批账户确认。
- 确认结果必须形成版本化契约清单和脱敏样本，并同步更新 Tech Spec、类型、适配器测试和下游验收标准。
- 若真实账户的推广计划数量超过单次安全返回上限，契约门必须重新评估读取接口，不得静默截断。
- 百度回调需要被百度接受的稳定公网 HTTPS 地址；生产域名未具备前可在获批测试地址完成开发联调，但不能视为生产可用。
- 现有 GEO/SEO 正式入口和行为不得因营销模块受到影响。
- 生产验收期间只允许管理员和指定测试项目访问；验收通过后才扩大服务端准入和导航可见范围。
