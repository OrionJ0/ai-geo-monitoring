# AI 平台设置中心 PRD

## Problem Statement

当前监测平台的名称、接口地址、默认模型和 API Key 依赖后端环境配置。管理员只能查看平台是否配置，不能在产品页面中新增、编辑、启停或测试平台。

这带来三个直接问题：

- 平台配置需要修改服务器文件并重启，日常维护成本高。
- 新增 OpenAI 兼容平台需要修改代码，无法由管理员自行完成。
- 问题运行失败时，无启用问题、平台未配置、平台停用等原因可能使用同一提示，管理员和用户难以定位问题。

## Solution

将管理员后台的 `/admin/settings` 升级为设置中心，提供“AI 平台”“AI 分析 API”“运行设置”“站点 SEO”四个页签。

管理员可以在“AI 平台”中维护全局平台配置，包括预设豆包、DeepSeek、千问和腾讯混元，以及自行新增 OpenAI 兼容平台。平台密钥由管理员人工填写，系统不自动导入环境变量中的 AI API Key。

问题、问题集、项目和定时任务统一使用设置中心中已启用且配置完整的平台。运行时根据真实原因返回准确提示，并允许可运行的平台继续执行、不可运行的平台明确跳过。

## User Stories

1. As an 管理员, I want to 在后台配置全局 AI 平台, so that 我无需修改服务器文件即可维护监测能力。
2. As an 管理员, I want to 新增 OpenAI 兼容平台, so that 系统可以接入豆包和 DeepSeek 以外的 AI API。
3. As an 管理员, I want to 主动测试平台连接, so that 我可以在投入使用前自行判断配置是否可用。
4. As an 管理员, I want to 分别查看配置、启用和测试状态, so that 我不会把“未测试”误认为“不可启用”。
5. As an 管理员, I want to 配置全局并发和重试策略, so that 我可以控制平台调用负载与失败恢复行为。
6. As an GEO 用户, I want to 在平台不可用时看到具体原因, so that 我知道应该启用问题、调整平台范围还是联系管理员配置 API。
7. As an GEO 用户, I want to 在部分平台不可用时继续运行其他平台, so that 单个平台配置问题不会阻断全部监测任务。
8. As an 管理员, I want to 从平台 API 选择模型并为 AI 分析单独选模型, so that 我不必手写模型名，也不必让分析任务固定使用平台默认模型。
9. As an 管理员, I want to 在明确操作后查看已保存的 API Key, so that 我可以核对和继续维护现有配置。
10. As an 管理员, I want to 在设置页查看正式使用的 AI 分析提示词, so that 我可以核对模型究竟被要求返回什么结构。
11. As an 管理员, I want to 在 AI 分析 API 中临时刷新所选平台的模型列表但只保存最终选择, so that 模型目录变化不会污染系统配置。
12. As an 管理员, I want to 使用统一命名的 OpenAI 兼容调用类型, so that 平台差异和接口协议差异不会混为一谈。

## Scope

- In scope:
  - 在 `/admin/settings` 增加“AI 平台”和“运行设置”页签。
  - 保留现有“站点 SEO”设置。
  - 预设豆包、DeepSeek、千问和腾讯混元的平台名称、唯一标识、接口类型、Base URL 和默认模型。
  - DeepSeek 预设默认模型为 `deepseek-v4-flash`。
  - 管理员人工填写、替换和清除 API Key。
  - 支持新增 OpenAI Chat Completions 兼容平台。
  - 支持在 AI 分析 API 设置中从所选平台读取临时模型列表并选择分析模型。
  - 支持 AI 分析 API 独立选择平台与模型。
  - 支持管理员主动显示已保存的 API Key。
  - 支持平台启停、连接测试和自定义平台删除。
  - 支持全局并发数、重试次数、默认请求超时和默认最大 Token。
  - 支持平台级请求超时和最大 Token 覆盖。
  - 项目和问题的平台选项改为读取当前全局平台配置。
  - 单问题、问题集、项目运行和定时任务统一使用全局平台配置。
  - 提供准确的运行错误和部分平台跳过提示。

- Out of scope:
  - 普通用户保存自己的 API Key。
  - 自动读取或导入 `.env` 中的 AI API Key。
  - 使用 `.env` AI API Key 作为运行时回退。
  - 在数据库中为一个平台持久化维护多个模型配置。
  - 自定义任意 REST 请求字段映射。
  - 在页面中开放 Temperature、Top P 等高级采样参数。
  - 在线轮换平台配置加密主密钥。

- Later:
  - 单个平台维护多个模型并允许项目选择模型。
  - 用户自带 API Key。
  - 更完整的平台调用成本、延迟和可用性统计。

## Product Behavior

### 1. 设置中心

管理员后台 `/admin/settings` 显示四个页签：

- `AI 平台`：默认页签，管理平台与连接测试。
- `AI 分析 API`：为结构化分析独立选择平台与模型。
- `运行设置`：管理全局运行参数。
- `站点 SEO`：保留现有站点标题、描述、关键词和 Robots 设置。

原管理员“平台自检”入口在新设置中心正式启用后移除，避免两个入口展示不同状态。

非管理员不能访问平台和运行设置。

### 2. 预设平台

系统预设豆包、DeepSeek、千问和腾讯混元：

- 只预设非敏感基本信息。
- 默认启用。
- API Key 初始为空，显示“未配置”。
- 未配置 API Key 时不能参与运行。
- 预设平台不能删除，但可以编辑接口地址、默认模型、API Key、运行参数和启用状态。
- 千问默认使用 OpenAI Responses 兼容协议和 `qwen3.7-plus`；已有 `qwen` 自定义配置升级为预设时保留其接口、模型、密钥和启用状态。
- 腾讯混元默认使用 TokenHub OpenAI Chat Completions 兼容协议和 `hy3`。

系统不自动读取或导入现有环境变量中的平台密钥。管理员必须在页面中人工完成配置。

模型刷新调用供应商 OpenAI 兼容 `/models` 接口。供应商支持该接口时，系统仅去重并完整返回模型 ID，不自行判断“常用”或“最新”；供应商未实现该接口时明确返回读取失败，不用静态清单冒充实时完整目录。模型列表只在当前页面临时使用，数据库只保存最终选择的模型。

### 3. 平台列表

平台列表显示：

- 平台名称与唯一标识
- 接口类型
- Base URL
- 默认模型
- 配置状态：未配置 / 已配置
- 启用状态：已启用 / 已停用
- 测试状态：未测试 / 测试成功 / 测试失败
- 最近测试时间

配置状态、启用状态和测试状态必须独立展示。

### 4. 新增和编辑平台

管理员可以填写：

- 平台名称
- 唯一标识
- 接口类型
- Base URL
- API Key
- 默认模型
- 请求超时
- 最大 Token
- 启用状态

产品行为：

- 新增平台默认启用。
- 唯一标识创建后不能修改。
- 新增时 API Key 可以留空，此时平台显示“未配置”且不能参与运行。
- 编辑时 API Key 留空代表保留现有值，输入新值代表替换。
- 编辑已配置平台时，管理员可以主动点击“显示现有密钥”；平台列表和普通读取接口不返回明文。
- 清除 API Key 使用单独操作并二次确认。
- 默认只显示是否已配置和末尾 4 位，不自动把完整密钥放进表格或编辑框。
- 已保存的平台可以通过模型接口读取可选模型；读取失败时仍可手动填写。
- 自定义平台的产品操作名为“删除”；服务端采用软删除，以保留历史数据含义。

### 5. 连接测试

- 测试连接由管理员主动触发，不是启用平台的前置条件。
- 已停用平台也可以测试连接。
- 测试要求 Base URL、API Key 和默认模型完整。
- 测试成功或失败不自动修改平台启用状态。
- 修改 Base URL、API Key 或默认模型后，测试状态重置为“未测试”。
- 测试失败应区分认证失败、限流、超时、网络异常和平台服务异常。
- 测试结果不得展示密钥、请求认证头或供应商原始敏感响应。

### 6. 运行设置

- 并发问题数：1–5，默认 2。
- 失败重试次数：0–3，默认 3。
- 默认请求超时：10–180 秒，默认 90 秒。
- 默认最大 Token：256–32768，默认 4096。
- 平台单独配置的请求超时和最大 Token 优先于全局默认值。

### 7. 项目和问题的平台选择

- 项目和问题表单从全局平台配置中读取平台选项。
- 已启用但未配置密钥的平台可以展示，但不可选择，并标记“管理员尚未配置”。
- 已停用或已归档的平台不能用于新配置。
- 历史记录继续显示原平台名称和当时使用的模型，不因平台后续改名、改模型或归档而丢失含义。

### 8. 运行与部分成功

运行单问题、问题集、项目或定时任务时：

1. 筛选启用问题。
2. 判断问题平台是否在项目监测范围内。
3. 判断平台是否启用、是否配置密钥、接口地址和模型是否完整。
4. 可运行的问题与平台正常入队。
5. 不可运行的平台明确列出并跳过。

示例：

> 已加入 2 个运行任务；豆包未配置 API Key，已跳过。

如果没有任何可运行任务，则不消耗配额，也不创建等待中的运行记录。

### 9. 错误提示

- 没有启用问题：`问题集中没有启用的问题。`
- 平台范围不匹配：`问题选择的平台不在当前项目的监测范围内。`
- 平台未配置：明确列出未配置 API Key 的平台。
- 平台已停用：明确列出被管理员停用的平台。
- 平台配置不完整：明确指出缺少接口地址或默认模型。
- 密钥暂不可用：`监测平台配置暂不可用，请联系管理员。`
- 认证失败：`平台认证失败，请管理员检查 API Key。`
- 限流：`平台请求过于频繁，请稍后重试。`
- 超时：`平台请求超时，请稍后重试或调整超时设置。`
- 网络异常：`无法连接监测平台，请检查网络或代理设置。`
- 平台服务异常：`平台服务暂时异常，请稍后重试。`

### 10. 安全与网络边界

- API Key 必须加密存储。列表、目录和普通配置读取不得返回明文；只有管理员主动显示单个平台密钥时才通过专用接口返回，并禁止缓存。
- 平台密钥、认证头和供应商原始敏感响应不得进入日志或错误提示。
- 自定义平台默认只允许公网 HTTPS 地址。
- 本机、局域网和其他私网地址默认拒绝。
- 如需连接本地模型，部署人员必须通过环境配置加入精确的主机和端口白名单。
- 管理员不能在页面中自行放宽私网访问范围。
- 连接测试和正式运行使用相同的网络安全规则。

## Acceptance Criteria

- AC-001: 管理员可以从 `/admin/settings` 进入 AI 平台和运行设置，非管理员访问被拒绝。
- AC-002: 首次升级后可看到豆包和 DeepSeek 预设信息，但二者 API Key 均为空，且没有自动导入环境变量密钥。
- AC-003: DeepSeek 预设默认模型显示为 `deepseek-v4-flash`，管理员可以修改默认模型。
- AC-004: 管理员可以新增一个 OpenAI Chat Completions 兼容平台；保存后默认启用。
- AC-005: 未配置 API Key 的平台显示“未配置”，不能用于项目或问题运行。
- AC-006: API Key 默认不回显；管理员可主动显示单个平台现有密钥；编辑时留空保留原密钥；清除密钥必须通过独立操作并二次确认。
- AC-007: 管理员可以自行测试启用或停用的平台；测试结果不自动改变启用状态。
- AC-008: 修改 Base URL、API Key 或默认模型后，平台测试状态变为“未测试”。
- AC-009: 管理员可以保存合法范围内的运行设置；越界值不能保存并显示明确校验提示。
- AC-010: 项目和问题的平台选项来自当前全局配置，不再只显示硬编码平台。
- AC-011: 部分平台不可运行时，其余平台正常入队，响应明确列出跳过平台及原因。
- AC-012: 所有平台都不可运行时，不消费配额、不创建等待记录，并返回准确原因。
- AC-013: 单问题、问题集、项目运行和定时任务使用同一套平台配置与错误语义。
- AC-014: 自定义公网 HTTPS 接口允许保存；未进入部署白名单的本机或私网接口拒绝保存和测试。
- AC-015: 平台读取、测试、运行响应及日志中均不出现 API Key 明文、完整密文或认证头。
- AC-016: 管理员人工配置 DeepSeek 后，可以从 `/geo/prompts` 成功运行单问题和问题集，并记录实际模型。
- AC-017: 正式运行不读取 AI 平台环境变量，也不存在环境变量回退路径。
- AC-018: 新设置中心正式启用后，旧“平台自检”页面和入口被移除，现有站点 SEO 设置仍可使用。
- AC-019: 编辑平台时直接显示并允许手动修改当前默认模型；平台管理表单不读取临时模型目录，避免把接口配置和模型目录刷新混为一项操作。
- AC-020: AI 分析 API 可以分别保存平台和模型，正式结构化分析使用所选模型而非强制使用平台默认模型。
- AC-021: 自定义平台操作显示为“删除”，删除后不再出现在平台列表，历史运行信息仍保留。
- AC-022: AI 分析 API 设置页显示正式运行使用的版本化提示词模板和期望 JSON 结构，展示内容与后端运行时共用同一生成逻辑。
- AC-023: 只有 AI 分析 API 设置可主动刷新模型；列表来自本次供应商请求且不落库，刷新后下拉框立即展示完整临时列表，只有保存表单时选择的模型写入配置。
- AC-024: 调用类型只保留供应商无关的 `OpenAI 兼容 · Chat Completions` 与 `OpenAI 兼容 · Responses`；既有豆包专用类型启动时迁移为 Responses。
- AC-025: AI 平台列表将“接口参数”和“当前模型”拆分为独立列；模型列只显示数据库当前保存的模型。
- AC-026: AI 分析结构化协议必须返回回答中的全部品牌/公司实体、原文短实体词、候选列表顺序、明确推荐关系、目标品牌情绪和可供后续核验的事实声明；提及次数和顺序由服务端扫描原回答确定，模型不得返回任何比例、得分或汇总指标。
- AC-027: 服务端根据结构化实体和关系确定性计算目标品牌提及次数、是否推荐、候选排名及有竞品时的 SOV；结构化结果不重复保存完整逐字句子。
- AC-028: 引用次数、来源清单、官网引用次数和是否引用官网必须来自监测平台原始响应或回答中的可核验 URL，不由 AI 分析模型生成。

## Metrics / Success

- 管理员可以在 3 分钟内完成一个预设平台的密钥配置并发起连接测试。
- 平台配置、启停、测试和运行过程中 API Key 明文泄露事件为 0。
- 已定义的运行前失败场景均返回唯一原因，不再出现“没有启用问题，或平台不可用”这类合并提示。
- 当至少一个平台可运行时，其他平台配置问题不会阻止可运行任务入队。
- 正式入口中 AI 平台环境变量读取次数为 0。

## Constraints

- 平台配置为管理员全局配置，不提供用户级覆盖。
- 数据库是 AI 平台运行配置的唯一正式来源。
- API Key 必须由管理员人工添加，不自动导入。
- 系统必须保留一个环境级加密主密钥；缺失时不能保存或使用平台密钥。
- 预设平台可以停用但不能删除。
- 每个平台第一版只有一个默认模型。
- 自定义接口只支持预定义适配器，不支持任意请求格式。
- 私网访问权限只能由部署环境控制。
