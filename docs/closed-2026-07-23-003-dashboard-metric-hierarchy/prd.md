# 项目看板指标分级 PRD

## Problem Statement

项目可见度看板已经提供品牌表现、运行质量、来源、竞品、趋势和优化机会等指标，但当前大量指标以同等大小的卡片连续平铺。用户进入页面后难以快速判断应该先看什么，也容易把运行数量、来源变化等诊断数据与品牌核心表现理解为同等重要的结论。

本需求不改变任何现有指标的计算方式，只优化同一页面内的信息优先级、分组和口径说明，让用户先看到核心表现，再逐层查看运行质量、来源表现、变化诊断和行动建议。

## Solution

将项目可见度看板重组为五个层级：

1. 核心表现：品牌提及率、平均声量占比（SOV）、推荐率、平均品牌排名。
2. 运行质量：总运行数、有效分析数、失败数。
3. 来源表现：引用率、自有来源覆盖率、总引用来源、来源域名数。
4. 变化与诊断：新增、流失和保留的引用域名与 URL，以及现有趋势、平台、分类、来源、竞品和最近指标明细。
5. 行动建议：现有优化机会列表。

全部指标仍保留在项目可见度看板同一页面。层级通过区块顺序、标题说明、卡片尺寸、颜色和留白体现，不新增导航层级，也不要求用户跳转后才能看到现有数据。

## User Stories

1. As an 品牌项目负责人, I want 进入看板后优先看到品牌核心表现, so that 我可以快速判断当前 GEO 表现。
2. As an 运营人员, I want 将运行质量与品牌表现区分展示, so that 我不会把样本失败误解为品牌表现下降。
3. As an 分析人员, I want 在同一页继续查看来源、平台、竞品和趋势明细, so that 我可以解释核心表现变化的原因。
4. As an 普通用户, I want 查看容易误解指标的计算口径, so that 我能正确理解推荐率、SOV 和平均品牌排名。
5. As an 执行人员, I want 在完成诊断后看到优化机会, so that 我可以把分析结果转化为后续动作。

## Scope

- In scope:
  - 重组项目可见度看板的指标卡片和现有内容顺序。
  - 为五个层级增加清晰的分区标题和简短说明。
  - 提升核心表现区的视觉优先级，降低运行、来源和变化指标的视觉权重。
  - 为品牌提及率、平均 SOV、推荐率和平均品牌排名提供可查看的现有计算口径说明。
  - 保留现有周期选择、项目选择、趋势图、平台图表、表格、空状态和加载状态。
  - 保持桌面端和移动端可阅读。
- Out of scope:
  - 新增事实正确率、推荐入选率、Top 1、Top 3、Top 5 等新指标。
  - 修改现有指标算法、分子、分母、权重或历史数据。
  - 修改后端 API、数据库结构、定时任务或报告快照结构。
  - 删除现有指标、来源明细、竞品明细或最近指标。
- Later:
  - 在存在稳定评价规则和验证数据后，再评估新的业务指标。
  - 根据真实用户反馈调整默认展开状态或增加个性化看板。

## Product Behavior

- 用户进入项目可见度看板后，首先看到“核心表现”区，四项现有品牌指标保持同等核心权重。
- 核心指标提供简短口径说明；说明不得暗示系统具备当前没有的事实核验或语义评价能力。
- “运行质量”和“来源表现”紧随核心表现展示，但使用更紧凑、较低对比度的样式。
- 新增、流失和保留的域名与 URL 汇总进入“变化与诊断”区，不再与核心表现并排。
- 趋势、平台、问题分类、来源、竞品和最近指标继续在“变化与诊断”区展示。
- “优化机会”移动到页面末尾，作为从分析到行动的收口。
- 未选择项目、无数据、加载中和请求失败时，继续沿用现有反馈，不显示虚构数据。
- 小屏幕下各层级保持顺序，指标卡自动换行，标题和口径说明不遮挡数值。

## Acceptance Criteria

- AC-001: 页面顶部只展示品牌提及率、平均 SOV、推荐率和平均品牌排名四项核心表现，不再混入运行、来源或变化数量。
- AC-002: 总运行数、有效分析数和失败数集中展示在“运行质量”区。
- AC-003: 引用率、自有来源覆盖率、总引用来源和来源域名数集中展示在“来源表现”区。
- AC-004: 新增、流失、保留引用域名及 URL 的六项汇总集中展示在“变化与诊断”区。
- AC-005: 现有趋势、平台、分类、来源、竞品、最近指标和优化机会均未被删除。
- AC-006: 优化机会位于所有分析与诊断内容之后。
- AC-007: 四项核心指标均提供不会改变当前计算结果的口径说明。
- AC-008: 页面不新增后端请求，不修改现有看板 API 返回契约。
- AC-009: 桌面端和移动端均能按照核心表现、运行质量、来源表现、变化与诊断、行动建议的顺序阅读。
- AC-010: 现有项目选择、周期切换、加载、空状态和错误处理行为保持不变。

## Metrics / Success

- 用户无需浏览全部卡片即可在页面首屏识别四项核心表现。
- 页面中不存在核心、运行、来源和变化指标视觉同权的连续卡片墙。
- 针对页面层级、指标归组和内容保留的自动化测试通过。
- 前端构建、静态检查和项目看板入口级验证通过。

## Constraints

- 必须复用现有指标和现有 API 数据，不新增或重新解释计算逻辑。
- 必须保留同一页查看全部指标的能力。
- 必须沿用现有工作台的 Ant Design 组件体系和蓝色品牌基调。
- 不得覆盖或混入当前工作区中与本需求无关的改动。
