# 市场数据监控前端信息架构与市场总览 PRD

## 1. 文档状态与裁决

本版自 2026-08-03 起取代该需求目录中旧版首页口径。现行全局视觉与组件标准以 `../visual-design-spec.md` 为准，最终设计参考图为 `assets/market-overview-home-final-2026-08-03.png`。

必须区分以下状态：

- 已确认：产品结构、视觉方向、来源链路和指标公式。
- 已部署：完整工作台导航、默认市场总览路由、新版首页、广告表现、关键词分析、网站流量、原始咨询和订单结果页面。百度营销、百度统计及既有 AI/GEO 数据已从正式入口 live verified；相关测试、lint 和 38 路由生产构建已通过。
- 已部署但生产未启用：官网表单聚合与 `/api/consultations` 脱敏记录 adapter。它们已用独立只读凭据完成本地真实逐日、列表和详情对账，但生产仍缺专用官网项目与只读账号凭据，因此模块保持 `DISABLED`。
- 尚未完成：官网最小权限生产身份、53KF 在线客服咨询、线索池与订单数据合同、可信跨系统来源关系、ROAS/CPL/CPA 真实计算。订单结果没有生产数据源，完整界面只允许非生产 fixture。
- 生产运行态：2026-08-04 workflow `30876793311` 已部署 `f265bd3`；正式关键词页显示截至 2026-08-03 的 863 条真实关键词，广告表现、百度统计、市场总览与 AI/GEO 页面均已登录后验证。官网、53KF 和销售字段分别保持 `DISABLED`、`NOT_CONNECTED` 与 `UNAVAILABLE`。

## 2. Problem Statement

市场负责人进入首页时，需要用尽量少的信息判断：各来源从流量到成交走到了哪里、付费投放是否有效、某个链路指标在所选日期内如何变化。旧版首页把广告和网站数据拆成孤立卡片，重复展示趋势与漏斗，把未接入状态和更新时间长期占据首屏，并且没有“官网表单咨询 / 在线客服咨询 → 线索入池 → 成交订单”的完整链路。

目标首页遵循奥卡姆剃刀和最小充分原则：不做说明型首页，不堆叠功能入口，不重复同一数字，只保留投放判断、来源横向链路和单指标每日趋势。

## 3. Product Solution

### 3.1 首页结构

市场总览按以下顺序展示：

1. 面包屑与全局日期范围；
2. 投放效率；
3. 来源全链路；
4. 每日趋势。

一级页面不重复显示“市场总览”大标题和介绍段。正常状态不显示更新时间、“最新”或“实时”。未接入提示、连接状态和复杂异常进入数据接入或相应下钻页，不作为首页常驻卡片。

### 3.2 来源全链路

首页按来源为行、阶段为列横向展示：

```text
来源 / 广告投入 → 展现 → 访问（点击） → 官网表单咨询 → 线索入池 → 成交订单 → 整体转换率
```

当前已经能以真实数据证明的来源粒度：

- 百度推广；
- 直接访问；
- 搜索引擎；
- 外部链接。

百度自然搜索、必应自然搜索、Google 自然搜索、必应广告等更细来源只有在来源系统提供可信的来源键后才能单独成行。官网 `organic_search` 聚合百度、必应、Google、搜狗、360 等搜索引擎，没有引擎级键时只能显示“搜索引擎”，不得按比例或同期数据拆分。未来来源沿用同一数据合同，不为每个来源设计不同首页结构。

字段规则：

| 列 | 展示值 | 比例口径 | 备注 |
|---|---|---|---|
| 广告投入 | 周期广告消费 | 无 | 仅付费来源适用；自然来源显示不适用，不显示 0。 |
| 展现 | 展现数 | 无 | 来源平台可验证的曝光事实。 |
| 访问（点击） | 访问或点击数 | 访问（点击）÷ 展现 | 付费广告的点击与官网访问属于同一链路阶段，不重复成两列。 |
| 官网表单咨询 | 官网可归因成功提交会话数 | 覆盖门禁满足后才可除以访问（点击） | 不包含 53KF，也不等于表单记录总数。 |
| 线索入池 | 人工转换进入销售系统线索池的数量 | 合同完成后按已确认咨询基数计算 | 是必须监控的人工转换阶段。 |
| 成交订单 | 成交订单数 + 成交订单金额 | 成交订单数÷线索入池 | 订单数与金额同时展示，不互相推导。 |
| 整体转换率 | 百分比或诚实缺失状态 | 成交订单数÷展现 | 不显示微型漏斗；缺失真实成交数量时显示 `—`。 |

每个百分比必须能通过 info Tooltip 读取分子、分母、时间范围和缺失值规则。阶段分母为 0 或缺失时显示“—”，不得显示无穷、100% 或推测值。

各列唯一主数据源和事件语义以 `../adr/0001-marketing-funnel-data-source-of-truth.md` 为准：百度营销负责广告展现、点击和消费，百度统计负责来源、访问、UV 和 PV，官网成功表单负责表单咨询，53KF 有效对话负责在线客服咨询，销售系统负责线索入池与成交订单。官网一方流量不得替代百度统计，也不得与百度统计相加、平均或补差。

### 3.3 可信来源关系

“按来源展示完整链路”不等于把同期总量直接拼接：

- 记录只有在具备可信来源键、可审计的来源映射或经确认的人工关联时，才进入对应来源行。
- 百度推广点击不得自动等同于百度统计的全站访问；需要同一来源链路的已确认口径。
- 客服咨询手动转入销售线索池时，必须保留可审计的关联事实。
- 缺少统一来源键时，每笔成交订单只能确认一条主要咨询来源；不得未经确认重复计入多个来源。
- 关系不完整时显示缺失状态，不用同期数据、比例或订单金额补齐。

### 3.4 投放效率

投放效率只面向付费来源，跟随全局日期范围和板块内的付费来源选择，不与来源全链路表格或每日趋势联动。

固定展示四个指标：

| 指标 | 公式 | 用途 | 有利方向 |
|---|---|---|---|
| ROAS | 成交订单金额÷广告投入 | 每 1 元广告投入产生的成交订单金额 | 越高越好 |
| CPL | 广告投入÷线索入池数 | 获得一条入池线索的广告成本 | 越低越好 |
| CPA | 广告投入÷成交订单数 | 获得一笔成交订单的广告成本 | 越低越好 |
| CPC | 广告投入÷访问（点击）数 | 获得一次访问（点击）的广告成本 | 越低越好 |

每张卡显示本期、等长紧邻上一周期以及“较上一周期”的变化。公式和两个周期的起止日期放在 info Tooltip。卡片不展示日折线，不添加自定义指标，不使用毛利、预期毛利、P、R、V 等派生口径。

视觉结构固定为：四张 KPI 卡直接位于浅灰页面背景；“投放效率”没有外层白色板。

### 3.5 每日趋势

每日趋势用于查看一个来源、一个指标在当前日期范围内的逐日数据，并与等长紧邻上一周期对比。

- 卡片左上只保留“来源”和“指标”两个下拉。
- 点击来源全链路的可选表头只更新趋势指标，不修改趋势来源，也不修改投放效率。
- 不再提供平铺指标按钮；下拉和表头是同一指标状态的两个入口。
- 当前周期使用来源主色实线，上一周期使用中性虚线。
- Tooltip 展示完整日期、指标、单位、本期值和上期对应值。
- 图表提供等价数据表或可访问摘要。

可选指标来自真实数据合同，包括广告投入、展现、访问（点击）、客服咨询、线索入池、成交订单数和成交订单金额；不适用于所选来源的指标应禁用或不显示。

### 3.6 关键词分析

关键词分析只分析投放关键词，不混入用户实际搜索词。页面按以下顺序组织：日期与数据来源、`有展现关键词 → 有点击关键词｜点击覆盖率`、单独的未获点击风险、任务筛选、效率四象限与当前关键词详情/行动分布、关键词明细表。

- 关键词事实只存在于直接所属推广单元中；页面不提供账户或推广计划层级筛选。
- 筛选固定为推广单元、优化建议、消费区间、CTR/CPC 异常和投放关键词搜索，不保留通用“更多筛选”。
- 四象限只允许当前数据中位数和账户平均值两种判断基准，不提供人工目标线。
- 散点大小代表点击，颜色代表显式优化标签；不显示额外散点图例。大数据量可切换密度视图。
- 选中散点持续高亮并联动右侧完整指标和表格行，不把“选中”误作表格筛选条件。
- 表格固定关键词和标签列；关键词下方只显示直接所属单元名，不显示“推广单元”前缀，完整父级路径进入 Tooltip。

## 4. Information Architecture

侧边栏保持当前代码中的完整分组，桌面端默认展开：

```text
市场总览
投放与流量
├── 广告表现
├── 关键词分析
└── 网站流量
转化结果
├── 原始咨询
└── 订单结果
AI 品牌监测
├── AI 搜索表现
└── 引用来源分析
网站诊断
└── SEO 健康检测
监测任务
├── 问题库
└── 运行报告
常用网站
设置
├── 系统通知
└── 个人中心
```

页面内容规则：

- 侧边栏图标约 16px，图标与文字间距约 8px。
- 一级页面使用“首页 / 当前页”面包屑，不重复 H1；分组内页面使用“首页 / 分组 / 当前页”。
- 对象详情页可在面包屑下显示对象名 H1。
- 页面可见不等于来源 API 已授权或正式开放。
- 系统保持只读；来源数据的创建、调整和处理仍在来源系统完成。

## 5. Data Semantics and States

所有指标必须携带或可访问以下语义：指标定义、日期范围、单位、分子/分母、数据来源、缺失规则和统计口径版本。

状态至少区分：

| 状态 | 展示原则 |
|---|---|
| 加载中 | 保留结构的骨架屏，不显示伪数字。 |
| 真实零值 | 显示 0；转化率按分母规则处理。 |
| 缺失 | 显示“—”及可访问原因，不当作 0。 |
| 不适用 | 如自然来源的广告投入，显示“—”并标记不适用。 |
| 缓存回退 | 保留最后可用数据，首页不显示“数据陈旧”或更新时间；诊断证据保留在接口元数据和运行记录。 |
| 来源错误 | 说明来源错误；不影响其他独立来源显示。 |
| 无权限 | 不泄露数据存在性，提供权限说明。 |

首页不显示更新时间或“数据陈旧”。只有来源真实不可用、权限阻断或时间范围无法解释时，才显示相应错误证据。

## 6. Scope

### In scope

- 当前完整工作台导航与默认项目上下文。
- 新版市场总览的四段结构和全部指标口径。
- 来源表格、整体转换率、投放效率卡、每日趋势和表头联动。
- 桌面 1440px 设计，以及必要的窄屏适配和无障碍状态。
- 将数据健康和接入状态从首页移到对应下钻或数据接入页面。

### Out of scope

- 修改百度预算、出价、计划、关键词、咨询、线索或销售订单。
- 用 mock、Excel 或手工常量填充生产首页。
- 未经确认的自动身份匹配、多触点归因或同期数据拼接。
- 首页自定义拖拽、保存个人看板、添加任意 KPI。
- 在首页加入 AI 搜索、SEO、数据连接卡、说明型 Hero 或异常建议列表。
- 在本 PRD 中补造 53KF、记录级官网咨询、线索池或销售订单的后端事实；这些能力必须先有独立真实合同和验收证据。

## 7. Responsive and Accessibility

- `≥1280px`：224px 展开侧栏；四张效率卡单行；来源表完整显示。
- `992–1279px`：效率卡可两列；来源表只在自身容器横向滚动。
- `<768px`：侧栏覆盖式展开，不挤压内容；效率卡单列或两列；来源表保留冻结来源列并允许容器滚动。
- 页面本身不产生横向滚动；组件不为填满截图而拉伸高度。
- 所有表头、下拉、Tooltip 和下钻操作支持键盘及清晰焦点。
- 图表颜色之外必须有线型、标签或文本；整体转换率缺失原因可通过键盘读取。
- 支持 `prefers-reduced-motion` 和 400% 缩放下的核心内容访问。

## 8. Acceptance Criteria

- AC-001：市场总览只有面包屑/日期、投放效率、来源全链路和每日趋势，不显示重复页标题。
- AC-002：投放效率固定为 ROAS、CPL、CPA、CPC，显示本期、上期和周期变化，没有日折线和外层白色板。
- AC-003：来源全链路按来源为行，当前展示广告投入、展现、访问（点击）、官网表单咨询、线索入池、成交订单和整体转换率；未来在线客服咨询独立接入。
- AC-004：点击与官网访问只保留一个“访问（点击）”阶段，不重复计数。
- AC-005：成交订单同时展示订单数和订单金额；CPA 以订单数为分母，ROAS 以订单金额为分子。
- AC-006：成交率为成交订单数÷线索入池数；整体转化率为成交订单数÷展现数。
- AC-007：每个来源行末只显示整体转换率，页面不存在微型漏斗或第二个大型漏斗。
- AC-008：每日趋势左上只有来源和指标两个下拉；点击可选表头只改变趋势指标。
- AC-009：投放效率不受全链路表格和每日趋势的局部状态影响。
- AC-010：正常和缓存回退状态均不显示更新时间或陈旧提示；来源不可用时显示错误。
- AC-011：未接入、错误、缺失、不适用和真实零值有不同呈现，不在首页放未接入提示卡。
- AC-012：只有可信来源键或确认映射的记录进入来源链路，测试证明同期总量不会被自动拼接。
- AC-013：一级页面显示面包屑但不重复 H1，桌面侧边栏默认展开。
- AC-014：1440px 页面无组件拉伸和页面级横向滚动；窄屏只允许表格容器滚动。
- AC-015：图表提供等价数据，交互可通过键盘完成，状态不只靠颜色表达。
- AC-016：实现验收必须从真实 `/geo/market-overview` 入口证明新版被调用、旧版未被调用；生产状态另从 `https://insight.guangtuo.com` 验证。
- AC-017：关键词分析只暴露推广单元层级筛选，摘要、四象限、完整选中详情、行动分布和明细表同时存在；表格次级信息只有所属单元名。
- AC-018：关键词分析的散点/密度、两种判断基准、搜索、重置、选点和表格联动均可操作，不存在人工目标线或额外散点图例。

## 9. Metrics / Success

- 用户可在 10 秒内指出各来源的主要链路损耗、百度推广投放效率和当前趋势指标变化。
- 首页不重复同一指标，不以未接入状态或说明文字占据首屏。
- 任一百分比都能回答“谁除以谁”，任一订单指标都能区分订单数和订单金额。
- 来源关系不完整时宁可显示缺失，也不制造不可审计的归因结果。

## 10. Implementation Handoff

现有 `TECH-SPEC.md` 保留部分旧版 V1 首页技术基线；新版页面视觉与交互已经实现，但不能替代缺失的数据合同。营销漏斗主数据源与官网无侵入接入边界已经在 `../adr/0001-marketing-funnel-data-source-of-truth.md` 批准；继续接入下游数据前仍必须完成：

1. 官网生产实际源码/schema/迁移/测试与线上聚合合同的对齐、最小权限只读服务身份，以及已完成本地实现的部署验收；
2. 53KF 有效对话、咨询转线索、订单去重与人工映射的数据合同；
3. 成交订单数和成交订单金额 API；
4. 指标语义版本、覆盖门禁、缺失和分母为零规则；
5. 下游字段接入后的加载、部分覆盖、缺失、陈旧和错误状态；
6. 正式域名 OAuth、真实 API 和页面入口验收。

在这些合同完成前，只能报告“市场工作台页面实现已完成、可用真实来源已接入、下游数据全链路未完成”；不得把缺失字段、隔离 fixture 或完整页面外观描述为已打通。生产是否生效必须以正式域名验收为准。
