# 市场数据监控前端信息架构与市场总览 PRD

- 状态：Active
- 日期：2026-07-31
- 需求依据：`docs/ideas/marketing-monitoring-frontend-ia-v2.md`
- 相关需求：`docs/active-2026-07-29-001-marketing-monitoring/prd.md`
- 领域术语：`CONTEXT.md` 中的“营销监控语言”

## Problem Statement

当前前端仍沿用 GEO/SEO 工具时期的信息架构：登录后先进入“品牌项目”，侧边栏按“品牌项目、SEO 检测、问题库、运行报告、来源分析、项目看板”等功能平铺。对于只服务广拓内部、且只有一个品牌的实际使用场景，这套结构存在以下问题：

1. 市场负责人进入系统后不能立即看到最近 30 天的投入、网站流量和需要处理的异常。
2. “项目看板”“来源分析”等名称依赖历史产品语境，无法准确表达 AI 品牌监测能力。
3. 百度营销与百度统计已经进入白名单真实数据试点，但现有合并页面不能承载未来“广告投放—网站访问—原始咨询—订单签订金额”的全链路联合观察。
4. 原始咨询和订单签订金额的来源系统尚无稳定 API，但内部用户仍需要从完整导航理解最终数据结构；页面必须明确区分“入口已开放”和“来源已接入”。
5. 当前 GEO 页面依赖 `project` 数据边界，但内部用户不应为了查看广拓数据反复理解和选择“项目”。

系统需要在不虚构数据、不暗示跨来源归因、不破坏现有 GEO/SEO 正式工作流的前提下，建立面向市场负责人和管理层的新信息架构，并为后续转化来源接入留下清晰位置。

## Solution

将前端重组为“市场总览—业务下钻—专项监测—系统管理”的分层结构：

1. 立即以“市场总览”作为默认首页，用一个紧凑页面回答投入和流量表现、全链路接入状态、主要异常及下钻方向；未开放来源显示中性状态。
2. 将已接入的广告与网站访问数据拆分到“投放与流量”分组中的“广告表现”和“网站流量”页面。
3. 为原始咨询和订单签订金额建立“转化结果”分组与占位页；未接入时入口仍显示，页面不展示模拟数据。
4. 将原“项目看板”归入“AI 品牌监测”并改名为“AI 搜索表现”；将原“来源分析”改名为“引用来源分析”。
5. 将原“SEO 检测”改名为“SEO 健康检测”，独立归入“网站诊断”。
6. 保留后端 `project` 实体作为数据归属和权限边界，通过管理员显式配置的默认监控项目自动解析广拓上下文；普通用户不再手动选择项目。
7. 导航结构和数据能力分离：完整导航与市场总览默认入口立即开放，来源能力和发布状态只控制真实数据读取、刷新及状态文案，不隐藏页面结构。
8. 页面遵循奥卡姆剃刀原则：侧边栏已经表达页面位置时，主内容不重复页名和介绍；常驻界面只保留数据、操作、状态、错误和必要口径。

## User Stories

1. As a 市场负责人, I want 登录后立即看到最近 30 天的广告投入和网站流量, so that 我能快速判断当前市场表现。
2. As a 市场负责人, I want 在首页看到最多三条最重要的异常及其下钻入口, so that 我知道下一步应该查看什么。
3. As a 管理层用户, I want 在一个页面看到全链路的核心结果和接入状态, so that 我能区分已有事实与尚未具备的数据能力。
4. As a 市场负责人, I want 分别查看广告账户、推广计划和网站流量明细, so that 我能解释首页变化而不被大量明细淹没。
5. As a GEO 运营人员, I want 继续访问 AI 搜索表现、引用来源、问题库和运行报告, so that 新市场首页不会中断现有正式工作流。
6. As a 网站运营人员, I want 独立访问 SEO 健康检测, so that 网站技术诊断不会与市场投入或 AI 品牌指标混淆。
7. As an 管理员, I want 显式设置广拓的默认监控项目, so that 所有依赖项目的数据页面使用同一、可审计的上下文。
8. As an 内部用户, I want 始终看到完整菜单并在页面内了解来源状态, so that 我能理解最终全链路结构且不会把未接入误认为零数据。
9. As a 市场负责人, I want 广告与网站数据在视觉和交互上保持独立, so that 我不会把它误读为跨来源归因。
10. As a 市场负责人, I want 在转化来源未来接入后直接下钻原始咨询或订单签订金额, so that 全链路概览中的结果有对应证据页面。

## Scope

### In scope

- 新的 GEO 工作台侧边栏分组、名称、顺序和固定可见规则。
- 立即启用的“市场总览”默认首页。
- 市场总览中的全链路概览、投入与流量趋势、需要关注三个模块。
- 广告表现和网站流量两个独立下钻页面。
- “转化结果”分组、未接入占位页及来源状态规则。
- AI 搜索表现、引用来源分析、SEO 健康检测的改名和重新归组。
- 问题库、运行报告、系统通知和个人中心的重新归组，以及工作台管理设置跳转的移除。
- 管理员显式配置默认监控项目；普通页面自动使用该上下文。
- 数据状态、异常优先级、异常合并和下钻规则。
- 百度试点、正式开放和转化来源接入的数据能力规则。
- 桌面端和移动端的可读性、折叠侧栏和键盘可访问性。

### Out of scope

- 修改百度预算、出价、推广计划或任何来源系统数据。
- 自定义、拖拽或按用户保存个性化看板。
- 多品牌、业务线或项目切换界面。
- 自动身份匹配、自动归因或多触点归因。
- 把百度点击归因成百度统计访问。
- 用零值、假数据、人工 Excel 或模拟卡片填充未接入来源。
- 把有效线索、销售机会、订单数量、回款、营业收入或毛利作为必须监控的结果指标。
- 在市场总览首屏展示 AI 搜索或 SEO 指标。
- 修改现有 GEO 指标算法、来源口径或历史数据。
- 为本需求建设数据仓库、消息队列、通用 ETL 或通用连接器平台。
- 在本需求中接入落地页或销售系统。

### Later

- 落地页系统提供稳定只读 API 后，在现有原始咨询页展示真实数据。
- 销售系统提供最小稳定订单标识和订单签订金额 API 后，在现有订单结果页展示真实数据。
- 两个转化来源都可用后，为每笔订单签订金额人工选择一条主要原始咨询。
- 真实使用数据充足后，校准异常阈值和异常合并规则。

## Product Behavior

### 1. 侧边栏信息架构

目标结构如下：

```text
市场总览

投放与流量
├── 广告表现
└── 网站流量

转化结果
├── 原始咨询
└── 订单结果

AI 品牌监测
├── AI 搜索表现
└── 引用来源分析

网站诊断
└── SEO 健康检测

监测任务
├── 问题库
└── 运行报告

常用网站

设置
├── 系统通知
└── 个人中心
```

可见性规则：

- 八个一级结构和全部菜单项始终显示，不因来源无数据、未接入或试点状态隐藏。
- 市场总览和常用网站作为直接入口，常用网站固定在设置上方；其余六个一级分组及全部子项静态展开，不提供分组下拉或手风琴交互。
- 未接入页面使用“来源暂不可接入”及具体依赖，不显示零值、模拟数字或虚构完成时间。
- 百度试点和正式状态继续控制真实数据 API 与刷新能力；页面可见不代表来源授权可用。
- 工作台“设置”分组不提供“管理设置”跳转；管理员仍从独立管理员后台进入设置中心。

常用网站集中展示百度营销、上海广拓官网后台、基木鱼、百度巧舱、百度 Agent 对话页、营销通、爱番番、百度爱采购和百度统计。分类标题独占完整内容行，网站卡片排列在标题下方，不显示用途说明或独立“打开”链接。已知入口整张卡片可点击并在新标签页打开；百度爱采购的买家平台和商家后台拆为两张目的地卡片。每张卡片显示对应站点 favicon 或官方品牌图，并提供文字回退。百度 Agent 对话页没有明确完整地址时只显示“完整地址待补充”，不得拼接或猜测链接。

页面内容规则：

- 主内容区不重复侧边栏当前页名称，也不显示“内部工作入口”等眉题或功能宣传段落。
- 说明性内容优先由分组、控件标签、状态、禁用态、整卡点击和选中态表达；必要口径收进 Tooltip 等按需交互。
- 空页面只显示最短的来源状态或错误，不重复展示“数据范围”“只读说明”等静态卡片。
- 页面内部仍可使用“全链路概览”“投入与流量趋势”等数据模块标题，它们用于区分内容，不属于重复页名。

### 2. 默认项目上下文

- 后端继续以 `project` 作为数据归属、权限和历史边界。
- 管理员必须显式设置唯一的“默认监控项目”，其当前业务含义为广拓。
- 市场总览、广告表现、网站流量和现有 GEO 页面自动使用该默认项目。
- 普通用户不看到项目选择器，也不因页面跳转丢失项目上下文。
- 默认项目未配置、已归档、无权访问或不可用时，页面不得猜测其他项目；应显示阻断状态并引导管理员完成配置。
- 不使用项目列表第一项、浏览器最近访问记录或本地缓存作为正式回退路径。
- 项目管理降级为管理设置中的管理员能力，不再作为普通用户一级导航。

### 3. 市场总览

市场总览只包含三个一级模块：

1. 全链路概览；
2. 投入与流量趋势；
3. 需要关注。

页面顶部展示“最近 30 天”、数据覆盖范围和各来源最后成功时间。不同来源更新时间不一致时必须分别展示，不得用一个时间冒充全部数据均已同步。

#### 3.1 全链路概览

全链路固定按以下业务顺序展示：

```text
广告投放 → 网站访问 → 原始咨询 → 订单结果
```

各阶段内容：

| 阶段 | 核心指标 | 当前来源 |
|---|---|---|
| 广告投放 | 广告消费；点击量作为辅助信息 | 百度营销 |
| 网站访问 | 访客数；访问次数作为辅助信息 | 百度统计 |
| 原始咨询 | 原始咨询数量 | 落地页系统，尚无稳定 API |
| 订单结果 | 订单签订金额 | 销售系统，尚无稳定 API |

展现量、PV、账户、推广计划和其他明细进入下钻页，不在首页重复堆叠。

当前未接入阶段只显示来源状态和原因，不显示 `0`、`N/A` 或模拟数字。全链路区域必须显示“同期联合观察，不构成跨来源归因”。

#### 3.2 投入与流量趋势

- 趋势区域展示核心指标随时间的变化，不再次陈列周期汇总数字。
- 广告趋势与网站流量趋势使用独立的图表或清晰分离的指标切换，不共用一个容易暗示归因的漏斗或连续折线。
- 单张图最多同时比较两个量纲可解释的序列；不同量纲需要明确坐标轴、单位和图例。
- 无数据、真实零数据、数据陈旧和来源异常必须使用不同状态。
- 环比、同比和转化率只有在数据窗口与业务口径得到确认后才能出现。

#### 3.3 需要关注

- 首页最多展示三条需要关注的事项。
- 选择优先级依次为：数据健康异常、连续趋势异常、单日显著波动。
- 同一优先级内，优先展示对广告消费、网站访客或订单签订金额等核心结果影响更大的事项，再按变化幅度排序。
- 同一来源、同一时间窗口、相同方向且具有共同解释入口的关联异常可以合并；不同来源或不同原因不得强行合并。
- 每条事项必须展示对象、时间范围、触发原因和下钻入口。
- 数据不足以形成稳定基线时不生成趋势异常。
- 第一版只使用可解释、可复现的确定性规则，不生成无法说明依据的 AI 建议。

### 4. 数据状态

用户可见状态至少区分：

| 状态 | 含义 | 展示要求 |
|---|---|---|
| 已接入 | 来源能力已开放且存在可读状态 | 显示真实数据及更新时间 |
| 待接入 | 来源已有稳定能力，但本系统尚未完成接入 | 中性说明，不视为故障 |
| 来源暂不可接入 | 来源系统尚未提供本需求所需稳定 API | 说明依赖条件，不承诺日期 |
| 数据陈旧 | 存在历史数据，但超过确认的新鲜度要求 | 保留旧数据并明确时间 |
| 来源异常 | 已接入来源当前读取失败 | 保留可用快照并说明异常 |
| 授权失效 | 需要管理员重新授权 | 提供有权限用户可执行的恢复入口 |

原始咨询和订单结果当前使用“来源暂不可接入”，不得写成“即将接入”或运行故障。

### 5. 下钻页面

#### 5.1 广告表现

展示广告消费、展现、点击、日期趋势、账户表现、推广计划明细、覆盖范围、最后刷新时间和来源健康。页面可提供“前往百度营销”的外部跳转，但不得提供来源写操作。

#### 5.2 网站流量

展示访客数、访问次数、PV、日期趋势、站点范围、最后更新时间和来源健康。页面不得把网站访问自动归因到广告账户或推广计划。

#### 5.3 原始咨询

仅在落地页来源正式接入后提供。展示原始咨询事实及必要来源信息，不把未经市场确认的咨询称为有效线索。

#### 5.4 订单结果

仅在销售来源正式接入后提供。核心业务指标为订单签订金额；最小稳定订单标识只用于展示、去重和后续人工关联，不把订单数量或其他销售过程字段升级为必须监控指标。

#### 5.5 现有能力

- “AI 搜索表现”沿用原项目看板的全部指标和周期、平台筛选能力。
- “引用来源分析”沿用原来源分析的域名、URL、来源类型和变化证据。
- “SEO 健康检测”沿用现有全站与单页检测能力。
- “问题库”和“运行报告”保留现有功能。

### 6. 分阶段切换

#### 当前阶段

- 市场总览是工作台默认入口，完整侧边栏结构可见。
- GEO/SEO 继续是正式可用的数据工作流。
- 百度营销与百度统计仅对白名单用户和默认项目开放试点页面。
- 市场来源未开放时，对应页面显示来源状态，不越过 API 能力门读取数据。
- 转化结果显示原始咨询和订单结果占位页，明确来源尚无稳定 API。

#### 百度正式开放

只有百度合同达到 `VERIFIED`、试点限制关闭并完成真实入口验收后：

- 市场总览和投放与流量从占位或试点状态切换为正式数据状态；
- AI 品牌监测、网站诊断和监测任务继续保留；
- 原合并营销页不再作为推荐入口，现有正式调用方迁移到新的总览和下钻页面；
- 不保留指向旧合并页面的静默回退或第二套正式导航。

#### 转化来源接入

- 每个来源单独完成合同、权限、数据质量和入口验收后，在现有页面开放真实数据。
- 首页对应阶段从来源状态切换为真实指标。
- 两个来源均可用前，不开放咨询与订单签订金额的人工关联。

### 7. 响应式与可访问性

- 桌面端首屏应完整展示全链路概览、趋势主体和需要关注，不出现横向页面滚动。
- 小屏幕按“全链路—趋势—需要关注”的顺序纵向排列，不改变信息优先级。
- 侧边栏折叠后仍提供可访问名称和当前页面状态。
- 图表必须提供等价数据表或可访问摘要，不能只靠颜色表达变化。
- 状态颜色同时配合文字或图标；中性未接入状态不得使用故障红色。
- 所有异常和菜单均可通过键盘访问，并具备明确焦点状态。

## Acceptance Criteria

- AC-001：正式侧边栏按市场总览、投放与流量、转化结果、AI 品牌监测、网站诊断、监测任务、常用网站和设置的结构展示。
- AC-002：当前导航始终显示市场总览、投放与流量和转化结果；未开放来源只在页面内显示中性状态。
- AC-003：AI 搜索表现对应原项目看板，引用来源分析对应原来源分析，SEO 健康检测对应原 SEO 检测，原有功能未因改名丢失。
- AC-004：系统只有一个品牌上下文，普通用户进入数据页面时不需要选择项目。
- AC-005：默认监控项目必须由管理员显式配置；未配置或不可用时页面阻断并给出处理指引，不自动猜测其他项目。
- AC-006：市场总览只包含全链路概览、投入与流量趋势、需要关注三个一级模块。
- AC-007：全链路按广告投放、网站访问、原始咨询、订单结果的顺序展示。
- AC-008：广告投放以消费为核心指标，网站访问以访客数为核心指标，订单结果以订单签订金额为核心指标。
- AC-009：未接入阶段不展示零值、模拟数字或虚构转化率。
- AC-010：原始咨询和订单结果当前明确显示“来源系统尚无稳定 API”或同义中性状态，不显示为运行故障。
- AC-011：首页通过独立卡片和独立趋势区呈现广告与网站访问，不使用连接线、换算关系或常驻解释段暗示跨来源归因。
- AC-012：不同来源最后成功时间分别可见，不使用一个更新时间代表全部来源。
- AC-013：趋势图不重复展示首页周期汇总数字，且广告和网站数据不会通过视觉连接暗示归因。
- AC-014：首页最多显示三条需要关注事项，并按数据健康、连续趋势、单日波动的顺序选择。
- AC-015：同类异常只有在来源、时间窗口、方向和下钻入口一致时才能合并。
- AC-016：每条异常均展示触发原因、时间范围和可用下钻入口。
- AC-017：数据不足以形成稳定基线时不生成趋势异常。
- AC-018：广告表现页提供账户、推广计划和趋势明细，但不提供百度写操作。
- AC-019：网站流量页展示百度统计指标，但不把访问量归因到广告账户或推广计划。
- AC-020：“转化结果”分组及两个菜单项始终显示；每个页面按其来源能力独立切换占位或真实数据。
- AC-021：销售来源未来接入时，订单签订金额是唯一必须同步的销售结果指标；订单数量不作为必接 KPI。
- AC-022：页面可见不等于数据能力开放；直接路由和数据接口仍受能力与权限判断保护。
- AC-023：市场总览立即成为工作台默认入口，百度未开放时显示数据来源状态。
- AC-024：百度正式开放后只切换真实数据状态，GEO/SEO 功能仍可从新分组访问。
- AC-025：正式切换后，旧合并营销页不再作为推荐入口，也不存在静默回退到旧页面的正式路径。
- AC-026：桌面端首屏无横向页面滚动；移动端保持全链路、趋势、需要关注的阅读顺序。
- AC-027：图表具有等价数据或可访问摘要，菜单、异常和下钻操作支持键盘访问。
- AC-028：管理员后台提供返回数据工作台、后台总览和历史记录直接入口；账号与权限、系统管理使用与工作台一致的静态展开分组和移动端覆盖式侧栏。
- AC-029：顶部栏和侧边栏固定在视口内，页面根节点不产生纵向滚动，长内容只在主内容区滚动。
- AC-030：一级直接入口保持中性灰，不能点击的一级分组标题使用更浅灰色；同级一级字号和字重一致且不使用常驻底框。二级菜单不使用分组底板、关系线或伪元素，只通过统一缩进和较轻字号区分层级，当前项只通过统一浅蓝选中态增强。
- AC-031：数据看板 section 不使用 `::before` 或 `:before` 绘制装饰性色条。
- AC-032：侧边栏在“设置”正上方提供“常用网站”直接入口，页面完整展示九个指定系统、十张目的地卡片；分类标题独占一行，每个网站显示站点图标；已知目的地整卡在新标签页安全打开，未知 Agent 地址不生成链接。
- AC-033：原“系统”分组改名为“设置”，仅包含系统通知和个人中心，不提供管理设置跳转；一级基础文字使用中性灰而非近黑色。
- AC-034：正式工作台与管理员页面不在主内容区重复侧边栏页名，不显示非必要的常驻介绍、眉题、用途说明或操作链接；必要口径通过按需交互访问。

## Metrics / Success

- 市场负责人能在进入市场总览后 10 秒内指出最近 30 天的广告投入、网站访问和首要异常。
- 管理层能正确区分“已接入”“来源暂不可接入”和“来源异常”，不会把百度试点误解为完整营销漏斗。
- 普通用户完成日常查看无需进入项目列表或手动选择项目。
- 首页一级模块不超过三个，不出现第二组重复的周期汇总指标。
- 每个首页异常都能下钻到对应证据或恢复入口。
- 菜单始终可见，但普通用户不能通过页面或直接 API 越过百度试点的数据访问限制。
- 新导航上线后，现有 AI 搜索、引用来源、SEO、问题库和运行报告入口均可正常访问。

## Constraints

- 必须沿用现有 Next.js、Ant Design、Express、Sequelize 和 `project` 数据边界。
- 必须复用现有百度营销快照、刷新和百度统计读取能力，不为界面重构复制第二套业务逻辑。
- 市场模块保持只读；所有业务调整回到来源系统完成。
- 百度真实数据正式开放仍必须晚于 `VERIFIED` 合同、试点关闭和真实入口验收；导航与空状态页面不受此门禁控制。
- 落地页与销售系统没有稳定 API 前，不得以人工文件或模拟数据替代正式来源。
- 产品文案、指标和状态必须遵循 `CONTEXT.md` 的现役术语。
- 本 PRD 不批准具体异常阈值；阈值必须基于真实历史数据评估并在实现前形成可审查口径。
