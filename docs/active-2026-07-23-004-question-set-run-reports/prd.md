# 问题集运行报告与历史 PRD

> 状态：重新激活，正在修复失败分流重试、配额原子性与运行恢复一致性。

## Problem Statement

当前系统以品牌项目和时间周期汇总可见度数据。用户运行一次问题集后，只能进入项目看板查看与其他运行混合后的结果，无法回答“这一次问题集运行得怎么样”，也无法回看同一问题集历次运行的差异。

现有项目看板、来源分析和项目报告仍有长期汇总价值，但它们不符合当前“以问题集为中心，每运行一次问题集形成一份报告”的主要工作方式。现有报告 CSV 也是分段汇总文本，不是可稳定交换和重新导入的标准明细表。

## Solution

把“问题集运行”升级为一等历史对象。每次运行问题集时创建一个独立运行实例，并以该实例为边界持续展示状态、汇总指标、逐问题逐平台结果和原始回答。用户可以查看同一问题集的运行历史，导出一行一个问题平台结果的标准 CSV，也可以把符合当前版本契约的 CSV 重新导入为只读历史报告。

指标识别从不可审计的文本启发式判断升级为“AI 结构化语义、程序确定性计算”：管理员在设置中心选择一个已配置的 AI API 作为分析 API；分析 API 返回回答中出现的全部品牌/公司、目标品牌与竞品实体映射、原文短实体词、明确候选顺序、推荐关系、情绪和待核验事实声明，但不能自报提及次数、是否推荐、排名、百分比或综合分数。服务端校验实体引用和短实体词确实存在于原回答，再扫描原回答确定提及次数和顺序，并按关系计算其他指标。引用数量、来源清单及官网归属直接从监测平台原始响应和可核验 URL 提取，不交给分析模型猜测。分析失败时不静默回退到旧文本规则，也不把该回答计入有效样本。

新增“问题集报告”作为问题库之后的主要入口。项目看板、来源分析和原项目报告保留，但移动到侧边栏较低优先级的“更多分析”分组中。

## User Stories

1. As an GEO 运营人员, I want 每次运行问题集都生成独立报告, so that 我能判断本次运行的表现而不受其他运行影响。
2. As an 项目负责人, I want 查看问题集历次运行历史, so that 我能追踪相同问题集在不同时间的变化。
3. As an 分析人员, I want 按统一明细表导出报告数据, so that 我能在 Excel、BI 或脚本中继续分析。
4. As an 系统管理员, I want 将系统导出的标准数据重新导入, so that 我能迁移或恢复问题集历史报告。
5. As an 日常使用者, I want 左侧导航优先突出项目和问题集工作流, so that 我不会被多个相似的汇总分析入口干扰。
6. As an 数据使用者, I want 每个指标都能追溯到结构化实体、关系、顺序和来源清单, so that 我能判断结果是否可信而不是接受一个不可解释的分数。
7. As an 系统管理员, I want 单独指定用于结构化分析的 AI API, so that 监测模型和分析模型职责分离且可以独立更换。
8. As an 系统管理员, I want 联网能力测试展示本次输入和 API 输出, so that 我能判断平台是否真的联网而不是只看一个成功标签。

## Scope

- In scope:
  - 每次手动运行问题集时创建独立运行实例。
  - 问题集运行接口返回运行实例标识和报告入口。
  - 按项目分页查询问题集运行历史，并查看单次运行报告。
  - 从报告页工具栏打开右侧历史报告抽屉，不在主报告旁固定占用一列。
  - 历史抽屉默认展示全部历史，并支持通过可搜索下拉框按问题集筛选。
  - 问题集筛选和分页由服务端执行，结果总数与当前筛选条件一致。
  - 报告展示运行状态、问题集名称、运行时间、完成/失败数量、现有核心指标和逐问题逐平台结果。
  - 运行中的报告可刷新或自动更新，完成后保留历史。
  - 在浏览器中直接生成并下载 A4 竖版 PDF，不打开系统打印对话框。
  - 导出带版本号的 UTF-8 CSV；一行对应一个问题与一个平台的运行结果。
  - 将符合当前版本契约的 CSV 导入为当前项目下的只读历史报告。
  - 导入前校验文件类型、版本、必要列、行数和字段类型；错误时不写入半份报告。
  - 在问题库后新增“问题集报告”主入口。
  - 将项目看板、来源分析和原报告中心下沉到“更多分析”。
  - 移除项目看板核心指标卡顶部蓝色装饰线。
  - 报告首页按“有效样本、品牌提及率、推荐率、平均品牌排名”的固定顺序展示，其他指标默认折叠。
  - 未配置竞品时隐藏 SOV；配置竞品后才展示 SOV。
  - 每个报告指标提供可聚焦的问号说明，明确业务含义、分子、分母和特殊口径。
  - 汇总展示已有的品牌官网引用率和官网引用次数；不新增第二套引用识别逻辑。
  - 单问题编辑时可以在当前品牌项目的可用监测平台中调整该问题的平台范围。
  - 左侧导航按品牌项目、SEO 检测、问题库、问题集报告、来源分析、项目看板排序；告警设置、系统通知和个人中心归入“其他”。
  - 设置中心新增“AI 分析 API”配置：从已配置且可用的 AI 平台 API 中指定一个分析 API，并提供结构化测试。
  - AI 分析只返回实体、实体映射、提及、候选顺序、推荐关系、待核验事实声明与情绪结构；服务端从结构化原料派生原子字段并计算指标，分析模型不得直接返回提及次数、是否推荐、排名或指标分数。
  - 联网能力检测返回本次测试输入、模型文本输出和供应商响应体；这些临时测试内容不写数据库。
  - 来源类型中“媒体内容”由维护的媒体域名规则命中；未命中自有、竞品及各已知内容类型的外部来源显示为“其他第三方来源”。
- Out of scope:
  - 导入后自动创建或覆盖问题集、问题、项目、AI 平台配置。
  - 导入后重新执行 AI 请求或把导入数据计入实时项目指标。
  - 自动比较两次报告或生成 AI 解读。
  - 让 AI 直接计算提及率、推荐率、平均排名、SOV 或任何综合分数。
  - 让 AI 直接输出最终排名数字、推荐率或综合分数。
  - 删除现有项目看板、来源分析和原项目周期报告。
  - 把历史单问题运行追溯为问题集运行。
- Later:
  - 问题集报告版本对比和变化解释。
  - XLSX、多工作表或压缩包导出。
  - 定时任务按问题集生成同类报告。

## Product Behavior

- 用户点击“运行问题集”后，系统先创建该次运行所需的任务记录，再创建一个包含这些任务记录标识的问题集运行实例。
- 问题集运行以当前项目配置的平台为范围，为每个启用问题分别创建任务，不受单个问题历史平台选择限制；普通 API 配置不可用时明确列入跳过项，任一所选 Web 平台实时预检失败时整次运行不创建任务。
- 单问题独立运行仍保留该问题自己的模型范围，不因问题集语义而改变。
- 运行成功入队后，页面跳转到该运行实例的独立报告，而不是项目汇总看板。
- 报告状态由实例内任务状态决定：仍有待处理任务为“运行中”；全部成功为“已完成”；成功和失败并存为“部分完成”；全部失败为“失败”。
- 报告只统计本次运行关联的回答，不混入同一项目、同一问题集或同一时间段的其他运行。
- 报告的核心指标不新增无法稳定计算的事实正确率等指标。
- AI 分析 API 对每条原回答返回固定结构：全部品牌/公司实体、目标品牌与竞品实体映射、原文短实体词、候选列表、明确推荐、待核验事实声明和情绪；提及次数和顺序由服务端扫描原回答确定，不由模型返回，也不返回推荐布尔值、排名数字或任何汇总指标。
- 服务端必须验证结构、长度、枚举、实体引用和短实体词顺序；每个实体必须至少有一个能在原回答定位的短实体词，目标品牌和竞品必须由分析模型显式映射，程序不得再按名称相似度猜测。结构无效时本条分析失败。
- 新运行不再使用关键词邻近、Markdown 列表位置等启发式规则作为静默后备。分析 API 未配置、调用失败或结构无效时，原回答仍保留，但该条不计入有效样本并显示分析失败。
- 品牌是否提及由程序根据目标实体是否存在至少一条提及派生；品牌提及率 = 已提及的有效分析数 ÷ 有效分析数。
- 品牌是否推荐由程序根据目标实体是否存在明确推荐关系派生；推荐率 = 已明确推荐的有效分析数 ÷ 有效分析数。
- 品牌列表排名由程序取目标实体在首个明确有序候选列表中的数组序号；平均品牌排名只统计存在明确有序列表的回答。普通项目符号或正文顺序不是排名。
- 配置竞品时，程序按目标品牌提及行数 ÷ 目标品牌与已映射竞品提及行数总和计算单条 SOV，再对有效分析求平均；未配置竞品时不计算也不展示。
- `claims` 只是回答中的“待核验事实声明”，没有连接已审核事实库前不能据此计算事实正确率。
- 品牌官网引用沿用现有引用来源归属结果：引用域名等于品牌官网域名或其子域名时计为官网引用。
- 首页核心指标固定按有效样本、品牌提及率、推荐率、平均品牌排名排序。SOV、引用、官网引用和执行状态放在默认折叠的“更多指标”中；无竞品时 SOV 不出现。
- 所有指标名称旁显示问号，悬停或键盘聚焦后说明含义与计算口径。
- 逐条结果至少展示问题、平台、状态、品牌是否提及、是否推荐、声量占比、品牌排名、引用数量、情绪和原始回答；失败项显示安全错误信息。
- 逐条结果中的进行中状态使用持续旋转图标，明确表示任务仍在处理。
- 历史列表按创建时间倒序分页展示，可按项目查看，并区分系统运行和导入报告。
- 历史列表从右侧抽屉拉出，关闭抽屉后主报告保持完整宽度。
- 历史抽屉默认展示当前项目的全部问题集运行；用户可搜索并选择一个问题集，只查看该问题集的历次报告。
- 切换问题集分类或历史分页只更新抽屉内容，不切换主区域当前打开的报告；只有点击“查看报告”才切换并关闭抽屉。
- 排版报告点击“导出 PDF”后直接下载 A4 竖版文件；导出内容隐藏工作台操作区，完整输出指标和明细表，不打开打印对话框。
- 管理员在设置中心选择一个已配置、已启用且具备 API Key 的 AI 平台作为分析 API。分析调用不继承该平台用于监测回答的联网参数。
- AI 分析 API 未配置或不可用时，运行结果明确显示分析失败；系统不得回退到旧规则并伪装成有效分析。
- 联网能力检测使用可见测试问题调用目标平台，并在结果弹窗展示测试输入、模型文本输出、供应商响应体和证据结论。输入和输出只随本次 HTTP 响应返回，数据库只保存测试状态、时间和简短消息。
- 千问 OpenAI Chat Completions 兼容接口即使接受 `enable_search` 和 `forced_search` 参数，也不能据此证明本次实际联网；没有供应商搜索证据时显示“无法验证”，不能标为“测试成功”。
- “媒体内容”是第三方来源的已知子类型，由维护的域名规则识别；其他未命中已知分类的外部来源显示为“其他第三方来源”，避免与“全部第三方引用数”混淆。
- 标准 CSV 首行是固定英文列名，包含 schema version；复杂数组使用合法 JSON 单元格保存，以保证可逆导入。
- 导入报告只用于查看、导出和历史保存，并明确标记“导入”。导入不会进入项目看板、来源分析或告警计算。
- 不符合契约的文件返回具体错误，例如版本不支持、缺少列、CSV 语法错误、JSON 字段错误或行数超限。
- 项目看板、来源分析和原报告中心仍可通过“更多分析”访问，不再占据左侧导航前部。
- 移动端报告优先展示运行摘要和逐条结果，宽表允许横向滚动。

## Acceptance Criteria

- AC-001: 每次问题集运行成功入队后，后端持久化一个唯一运行实例，并返回其 ID。
- AC-002: 两次运行同一问题集产生两个不同报告，彼此数据不混合。
- AC-003: 单次报告状态和完成、失败数量与关联任务的当前状态一致。
- AC-004: 报告汇总指标只使用本次运行的有效指标记录计算。
- AC-005: 报告包含本次运行的逐问题逐平台明细和可用的原始回答。
- AC-006: 用户可以分页查看当前项目的完整问题集运行历史，并重新打开任意报告。
- AC-007: 用户可以直接下载当前排版报告的 A4 竖版 PDF；过程不调用浏览器打印，内容不包含工作台导航和操作区。
- AC-008: 导出的 CSV 是统一单表，一行对应一个问题平台结果，包含版本、运行元数据、结果和指标字段。
- AC-009: 系统导出的 CSV 可以重新导入并生成内容等价的只读历史报告。
- AC-010: 非当前版本、缺少必要列、非法字段、跨运行混入或越权项目的导入被拒绝，且不产生残缺记录。
- AC-011: 运行问题集后前端进入问题集报告，不再跳转项目看板。
- AC-012: “问题集报告”位于问题库之后；项目看板、来源分析和报告中心位于低优先级分组。
- AC-013: 项目看板核心指标卡不再显示顶部蓝色装饰线。
- AC-014: 现有单问题运行、项目看板、来源分析和项目周期报告仍可使用。
- AC-015: 历史报告通过报告页右侧抽屉展示，主页面不保留固定历史侧栏。
- AC-016: 历史抽屉提供可搜索、可清空的问题集下拉框，默认查看全部问题集历史。
- AC-017: 选择问题集后，接口按 `questionSetId` 在服务端筛选并返回对应分页总数；非法 ID 被拒绝。
- AC-018: 切换历史分类和分页不会改变当前主报告，点击历史项的“查看报告”后才切换报告。
- AC-019: 运行问题集时，每个启用问题都覆盖当前项目配置的全部可用模型；单问题保存的平台范围不限制问题集运行。
- AC-020: 单问题独立运行仍使用该问题自己的模型范围。
- AC-021: 报告级和逐模型结果的进行中状态均显示旋转图标。
- AC-022: 报告首页按有效样本、品牌提及率、推荐率、平均品牌排名展示，其余指标默认折叠且可由用户展开。
- AC-023: 每个可见和折叠指标都提供问号说明，明确其计算口径。
- AC-024: 问题集报告汇总展示官网引用率和官网引用次数，且 CSV 导出再导入后两项汇总保持一致。
- AC-025: 编辑单问题时可以修改监测平台，并只允许选择当前项目已配置且启用的平台。
- AC-026: 左侧导航顺序与本 PRD 约定一致；原报告中心不再出现在侧边栏，但路由和功能保留。
- AC-027: 管理员可以在设置中心选择一个已配置且可用的平台 API 作为 AI 分析 API，并可以用示例回答验证结构化输出。
- AC-028: AI 分析模型返回全部品牌/公司、目标品牌与竞品实体映射、原文短实体词、推荐关系、候选列表、待核验事实声明和情绪结构；服务端扫描原回答确定提及次数和顺序；模型不返回提及次数、推荐布尔值、排名数字、提及率、推荐率、SOV 或综合得分。
- AC-029: 服务端拒绝字段非法、越界、实体没有对应提及、短实体词不在原回答或目标映射引用不存在实体的结构化结果；失败时不回退旧文本规则，也不计入有效样本。
- AC-030: 新运行的品牌提及率、推荐率、平均品牌排名和有竞品时的 SOV 均由服务端根据通过校验的结构化字段计算。
- AC-031: 无竞品项目的报告汇总和逐条结果均不显示 SOV。
- AC-032: 联网能力测试结果弹窗展示本次测试输入、模型文本输出、供应商响应体和判断依据；输入输出不写数据库。
- AC-033: 仅因请求中配置了强制联网参数不能判定联网测试成功；缺少供应商可验证证据时显示“无法验证”。
- AC-034: 来源分类页明确说明媒体域名规则；未知外部来源显示为“其他第三方来源”。
- AC-035: 失败项重试接受持久幂等键；重复提交同一个运行和同一个键不得重复创建记录或重复扣减配额。
- AC-036: 已保存完整原回答的结构化分析失败项只重做分析；监测失败或缺少原回答的失败项才重新调用当前监测平台。
- AC-037: 监测配额按完整监测重试数在同一数据库事务中原子扣减；分析重试不消耗监测配额。
- AC-038: 重试保留原回答及监测平台引用元数据快照；报告与 CSV 保留失败阶段、分析诊断和重试链路。
- AC-039: 单进程重复调度和多进程并发调度都不能对同一记录重复调用平台；超时中断记录具有可诊断失败状态。
- AC-040: 报告读取不修改运行状态；只有执行完成方可以通过运行修订号写入终态快照，旧执行器不能覆盖新重试结果。
