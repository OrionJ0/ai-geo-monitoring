# 营销数据 AI 分析报告 PRD

## Problem Statement

市场负责人已经可以分别查看百度广告、百度统计网站流量和官网表单咨询，但仍需要人工在多个页面之间汇总数据、核对周期并组织结论。现有 GEO 报告和 GEO AI 结构化分析服务于 AI 搜索监测，不适合承载营销数据分析；直接让模型自主调用接口、计算指标或持续对话，又会引入不必要的 Agent 状态、数据漂移、成本和审计风险。

用户需要的是一份可信、可复查且生成后不再变化的营销分析报告：系统在用户指定的完整历史周期内重新读取当时可用的数据，由程序计算权威指标，再由 AI 用简明语言解释事实、提出建议并选择必要图表。

## Solution

在站内新增“AI 数据分析”页面。项目所有者或管理员选择分析周期并主动生成报告；系统异步读取固定来源、构建经过程序校验的有界证据包，通过一次结构化模型调用生成报告 JSON，并由前端使用受控组件和图表渲染器展示。

每次成功运行只产生一份不可变报告。报告保存当次数据覆盖、程序计算指标、AI 结论、建议、图表意图和最小固定数据集；后续来源数据变化不会改写历史报告。用户只有重新运行时才会重新取数并形成新报告。

## User Stories

1. As a 项目所有者, I want to 选择一个完整历史周期生成营销分析报告, so that 我可以快速理解投放、网站访问和表单咨询的主要表现。
2. As a 市场负责人, I want to 在报告中同时看到程序计算的指标、AI 解释和必要图表, so that 我可以区分事实、推测和行动建议。
3. As a 市场负责人, I want to 查看每个来源的实际覆盖和缺失原因, so that 我不会把未接入或读取失败误认为零。
4. As a 项目所有者, I want to 离开页面后任务仍继续运行并可查看状态, so that 长时间取数或模型调用不会占用当前页面会话。
5. As a 项目所有者, I want to 对失败运行按原数据和原配置重试, so that 临时错误不会迫使我创建语义不同的新任务。
6. As a 项目所有者, I want to 重新运行并形成新的固定数据基线, so that 我可以在来源数据更新后获得一份新报告。
7. As a 项目所有者, I want to 查看和删除历史成功报告, so that 我可以回顾当时结论并管理不再需要的报告。
8. As an 管理员, I want to 为营销分析单独选择 AI 平台、模型和请求参数, so that 营销报告配置不会被 GEO AI 结构化分析的配置变更静默影响。

## Scope

### In scope

- 新增站内“AI 数据分析”页面和工作台导航入口。
- 仅分析当前用户有权访问的一个监控项目。
- 默认分析最近 30 个已经结束的上海自然日；允许选择最长 90 个自然日，截止日不得包含上海当日。
- 系统同时读取所选周期和紧邻的等长上一周期。
- 首版固定来源：
  - 百度广告：推广计划、推广单元、关键词、搜索词四份独立官方报告。
  - 百度统计：网站访问、UV、PV、可用的质量指标、来源与趋势。
  - 官网表单咨询：可归因成功提交会话的汇总、来源和逐日趋势。
- 程序负责精确指标、周期对比、排序、样本量、覆盖状态和数据健康校验。
- AI 负责核心摘要、对事实的解释、待验证假设、营销建议和可选图表意图。
- 固定报告骨架：报告身份与周期、数据覆盖、核心摘要、关键指标、来源洞察、营销建议和口径限制。
- KPI 卡片、折线图、分组或堆叠柱状图、数据表格四类受控展示。
- 异步运行、一个项目最多一条未结束运行、幂等创建、取消、失败重试和重新运行。
- 当前报告、成功报告历史、历史查看与删除。
- 独立的营销分析 AI 配置；复用已有 AI 平台凭据和请求基础设施。
- 保存固定证据、最终报告和轻量调用元数据。

### Out of scope

- Agent Runtime、模型工具调用、MCP、LangChain、LangGraph、Pi、Codex CLI、OpenCode 或其他 Coding Agent。
- 自定义分析重点、自由提问、连续聊天、会话记忆或交互式“问数据”。
- 模型直接调用来源 API、内部 HTTP API、数据库或任意 URL。
- 模型计算权威指标、补零、外推缺失数据或把同期变化写成因果归因。
- GEO 报告、GEO AI 结构化分析结果或两类报告的联合分析。
- 单条咨询记录、咨询正文、联系人信息、电话、邮箱、IP、访客标识或记录标识。
- 自动定时生成、邮件发送、公开分享、匿名访问、PDF/CSV 导出。
- 两份历史报告之间的比较。
- 编辑历史报告、编辑 AI 文字、人工改写图表或修改固定证据。
- 把营销建议派发为负责人、截止日期、完成状态或可追踪任务。
- 在系统内修改广告投放、处理咨询或执行 AI 建议。

### Later

- 独立的交互式“问数据”功能；届时再评估无会话、有限步、只读的轻量工具循环。
- 53KF 在线客服咨询、线索入池和订单来源在真实只读接口接通后的报告章节。
- 经单独评审后的报告导出、站内分享或报告间对比。
- 经产品确认和版本化的异常识别规则。

## Product Behavior

### 1. 页面入口与空状态

- 工作台新增“AI 数据分析”入口，页面名称使用“营销数据 AI 分析”，不得与“GEO 报告”或“GEO AI 结构化分析”混用。
- 页面默认使用当前默认监控项目；只有项目所有者和管理员可以访问。
- 没有成功报告时，页面展示功能说明、数据覆盖提示、日期选择器和“生成报告”按钮，不展示伪造示例报告。
- 营销分析 AI 未配置或配置不可用时，生成按钮不可用，并提示项目所有者联系管理员；管理员可以进入设置页完成配置。

### 2. 周期选择

- 默认周期为最近 30 个已经结束的上海自然日。
- 用户可以选择 1 至 90 个连续自然日；结束日期最晚为生成日前一个上海自然日。
- 页面在发起前明确展示系统会同时读取的紧邻等长上一周期。
- 报告固定记录所选周期、上一周期、时区、各来源实际覆盖和取数时间。

### 3. 生成与运行状态

- 用户点击“生成报告”后，系统创建异步运行并立即返回任务状态，离开页面不取消任务。
- 同一项目同时不允许运行两份分析。重复提交同一个幂等请求返回原运行；不同参数的新请求在已有运行未结束时返回冲突，并展示现有运行。
- 页面显示排队、取数、生成、校验、成功、失败和已取消等用户可理解的状态，不把运行中或失败任务称为报告。
- 已有当前报告时，新运行期间继续显示原当前报告，并在页面显示新任务进度；只有新运行成功后才切换当前报告。
- 服务重启时未结束运行变为失败，不自动恢复；用户可以按规则重试或重新运行。

### 4. 数据读取与覆盖

- 每条新运行都重新读取全部已接入来源，不复用旧报告证据，也不直接使用主看板旧快照。
- 来源读取失败时不得静默回退旧数据。
- 百度广告四份报告在一次来源读取中全成全败；不得用计划汇总反推单元、关键词或搜索词。
- 百度统计和官网表单分别表达自身覆盖、取数时间和错误状态，不伪造跨来源统一 revision。
- 至少一个来源在所选周期内具有完整、可分析的 `DATA` 或 `ZERO` 事实时，可以生成部分覆盖报告；所有来源均不可分析时运行失败且不产生报告。
- 未接入、无数据、读取失败、覆盖不完整和真实零值必须使用不同状态呈现。
- 只有同一来源的当前周期与上一周期都完整覆盖且口径一致时才展示周期变化；否则明确显示“不可比较”。

### 5. 报告内容

- 程序计算并展示权威数值；AI 不负责求和、除法、汇总或定义公式。
- AI 的解释、假设和建议必须与程序指标分区展示，不得伪装成已证明事实。
- 支持的来源即使没有明显变化，也必须保留对应报告章节和覆盖状态。
- 未接入的 53KF、线索和订单只进入覆盖缺口或口径限制，不生成空分析章节。
- 跨来源内容只能描述同期现象或待验证假设，不得使用“导致”“带来”等因果归因表述，也不得计算没有可信关联键的跨来源转化率。
- 图表是可选辅助内容。单张图表在纠正后仍无效时，页面标记该图表未能生成，正文和其他有效图表仍可形成成功报告。
- 报告整体 JSON、固定章节或必要字段在一次纠正后仍无效时，运行失败且不产生半成品报告。

### 6. 搜索词与数据最小化

- 完整原始搜索词列表不发送给外部模型，也不进入报告证据。
- 只允许按固定规则选择有限代表样本；发送前必须限制数量和长度、清理控制字符、遮蔽明显手机号、邮箱和身份证号，并移除内部标识。
- 报告明确说明搜索词分析基于有限样本，不得表述为覆盖全部搜索词。
- 官网表单只使用聚合与逐日数据，不读取记录级联系人或咨询正文。

### 7. 重试、重新运行与取消

- 失败运行的“重试”继续同一运行，保留原运行标识、周期、模型、Prompt/Schema 版本和历史调用尝试。
- 数据基线尚未锁定时，重试丢弃来源部分结果并重新读取同一组来源；基线已锁定时，重试只继续未成功的后续阶段。
- 用户创建更新运行后，旧失败运行保留审计记录但永久失去重试资格。
- “重新运行”始终创建新运行并重新取数，即使日期与上一份报告相同。
- 取消是不可重试终态。已经发出且无法立即中断的外部调用结果必须丢弃；再次分析只能重新运行。

### 8. 当前报告、历史与删除

- 当前报告是最近成功且尚未删除的报告。
- 历史列表只展示成功且尚未删除的报告，支持查看和删除，不展示失败、取消或运行中的任务。
- 删除当前报告后，最近剩余的成功报告自动成为当前报告；没有剩余报告时回到空状态。
- 删除操作移除报告正文、图表数据和固定证据，只保留报告标识、项目、生成时间、删除人和删除时间等最小审计信息。
- 成功报告默认长期保留，不自动过期，也不被重新运行覆盖。

### 9. 调用记录

- 调用记录只保存阶段、状态、尝试次数、耗时、Token 用量、模型、平台、Prompt 版本和错误摘要。
- 不保存完整 Prompt、模型原始响应、上游接口原始报文或聊天历史。
- 失败运行只有在数据基线已经锁定时保留有界证据包，以支持同一运行重试；基线形成前的来源部分结果不持久化。

## Acceptance Criteria

- AC-001：Given 用户进入 AI 数据分析页且没有报告，When 页面加载完成，Then 展示默认 30 个上海完整日、对应上一周期和生成入口，不展示示例数据。
- AC-002：Given 用户选择合法的 1 至 90 日周期，When 发起生成，Then API 以幂等方式创建异步运行，并且离开页面不终止运行。
- AC-003：Given 同一项目已有未结束运行，When 用户用不同请求再次发起，Then 系统拒绝创建第二条运行并返回现有运行状态。
- AC-004：Given 同一个幂等请求被重复提交，When 后端处理请求，Then 返回同一运行，不产生重复来源调用或报告。
- AC-005：Given 新运行开始，When 构建数据基线，Then 所有已接入来源均重新读取，且来源失败时不使用旧报告或旧缓存兜底。
- AC-006：Given 百度广告任一层级报告失败或合同无效，When 汇总来源状态，Then 百度广告整体不可用，上一份完整广告快照不进入本次报告。
- AC-007：Given 一个来源可分析而其他来源未接入或失败，When 模型和报告校验成功，Then 生成部分覆盖报告并准确展示各来源状态。
- AC-008：Given 所有来源都不可分析，When 运行完成取数，Then 运行失败且不产生报告。
- AC-009：Given 当前周期或上一周期覆盖不完整，When 展示变化，Then 对应来源显示“不可比较”，不补零、不外推、不暗中裁剪日期。
- AC-010：Given 程序计算广告、流量或表单指标，When 报告展示，Then 精确数值、公式和零分母语义与现有权威口径一致。
- AC-011：Given 证据包含搜索词，When 构建模型输入，Then 仅发送有限、脱敏、无内部标识的样本，并在报告中标注样本范围。
- AC-012：Given 模型没有识别出明显变化，When 报告生成，Then 所有可分析的首版来源章节仍然存在。
- AC-013：Given 模型返回一张无效可选图表但核心报告有效，When 完成一次纠正后图表仍无效，Then 丢弃该图表、显示未生成提示并保留成功报告。
- AC-014：Given 模型返回的报告核心结构无效，When 一次纠正后仍无效，Then 运行失败且不产生半成品报告。
- AC-015：Given 项目已有当前报告，When 新运行处于运行中、失败或取消，Then 原当前报告保持可见且不被改写。
- AC-016：Given 新运行成功，When 用户刷新页面，Then 新报告成为当前报告，旧报告仍可从历史列表查看。
- AC-017：Given 失败运行尚未被更新运行取代，When 用户点击重试，Then 继续同一运行并遵守基线是否锁定的重试规则。
- AC-018：Given 用户已经创建更新运行，When 尝试重试旧失败运行，Then 系统拒绝重试但保留旧运行审计。
- AC-019：Given 用户取消未结束运行，When 外部调用稍后返回，Then 结果不进入基线或报告，运行保持已取消。
- AC-020：Given 服务在运行过程中重启，When 服务恢复，Then 未结束运行变为失败且不会自动恢复。
- AC-021：Given 用户删除当前报告，When 删除成功，Then 报告正文和固定证据不可再读取，当前报告回退到最近剩余成功报告或空状态。
- AC-022：Given 非项目所有者且非管理员持有报告或运行 ID，When 请求相关接口，Then 返回无权访问且不泄露报告是否存在。
- AC-023：Given 营销分析和 GEO 分析配置不同，When 任一配置被修改，Then 另一类后续运行的模型和请求参数不被静默改变。
- AC-024：Given 查看数据库调用记录，When 运行成功、失败或取消，Then 只能看到轻量元数据，不存在完整 Prompt、原始模型响应、上游原始报文或聊天历史。
- AC-025：Given 查看任一历史成功报告，When 上游数据、Prompt 或当前模型配置已经变化，Then 报告数值、文字和图表仍与生成当时完全一致。

## Metrics / Success

- 产品正确性：全部验收标准通过，特别是单项目防重、历史不可变、部分覆盖和取消结果隔离。
- 数据可信度：报告中不存在把缺失表示为零、跨来源无依据归因、模型自行计算权威指标或搜索词完整外发的情况。
- 可复查性：任一成功报告都能从保存的版本、固定证据和轻量调用元数据说明其生成周期、来源覆盖与模型配置。
- 使用结果：项目所有者可以从空状态完成生成、查看、失败重试、重新运行、历史查看和删除的完整站内流程。
- 轻量性：首版不新增 Agent/工具调用依赖、聊天会话存储、长期原始营销数据仓库或重复原始响应归档。

## Constraints

- 系统继续保持只读；任何建议都不得自动修改来源系统。
- 项目同时支持 SQLite 与 PostgreSQL，新增持久化合同必须在两种方言下保持一致。
- 新功能必须复用现有来源模块的内部读取能力，不得通过后端自调用 `/api/marketing` 或 `/api/website-data`。
- 百度营销、百度统计和官网表单继续保持各自主数据源、凭据、缓存、合同和错误语义；分析模块只能在应用层汇总经过验证的结果。
- 新运行必须主动刷新来源，但不得改变主看板现有快照的默认覆盖或用报告取数污染主看板当前快照。
- 报告使用独立 Evidence、Report、Prompt 和 Chart Intent 版本；不得复用 GEO `ai_structured_v4` 合同。
- 模型请求必须关闭联网搜索和工具能力。
- 不新增 Zod、AI SDK 或 Agent 框架作为首版必要依赖；结构验证沿用当前 CommonJS 后端的显式校验模式。
- 生产真实入口、迁移、配置和端到端验收完成前，只能称为文档或本地实现，不能称为正式生效。
