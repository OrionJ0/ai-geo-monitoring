## What to build

交付第一条可演示的营销报告完整链路：项目所有者从工作台进入“营销数据 AI 分析”，使用默认最近 30 个上海完整日生成报告；系统重新读取百度推广计划、单元、关键词和搜索词四份报告，程序构建有界证据包并计算权威广告指标，模型在无工具、无联网条件下一次生成固定结构 JSON，前端展示来源覆盖、指标、AI 解释、建议和受控图表。

本切片同时建立营销分析运行、调用尝试和不可变报告的基础持久化及迁移入口。范围只覆盖成功生成的基本路径和百度广告来源；并发强化、用户控制、其他来源及历史管理由后续切片补齐。

## Acceptance criteria

- [ ] 已登录的项目所有者或管理员可以从新增导航进入页面；无报告时只显示说明、默认 30 个上海完整日和生成入口，不展示示例报告。
- [ ] 生成请求异步创建持久运行并返回可查询标识；页面可以观察取数、生成、校验和成功状态，离开当前请求不会把任务当作同步失败。
- [ ] 默认周期排除上海当日，并同时固定紧邻的等长上一周期、时区、取数时间和来源覆盖。
- [ ] 百度推广四份独立报告在一次来源读取中全成全败；任一合同、分片或层级失败时，不使用计划汇总反推其他层级，也不使用旧广告快照生成报告。
- [ ] 报告取数不改写主看板当前快照、最新刷新记录或现有页面的默认缓存语义。
- [ ] 程序负责金额、计数、CTR、CPC、排序、零分母和比较资格；模型输出不能覆盖或重新计算这些权威事实。
- [ ] 模型请求使用独立营销 AI 配置，显式不携带 tools、联网搜索、GEO 分析合同、凭据、项目 ID 或上游账户 ID。
- [ ] 模型核心结构无效时最多纠正一次；两次均无效则运行失败且报告表没有半成品。单个可选图表纠正后仍无效时，仅丢弃图表并记录可见问题。
- [ ] 成功运行原子写入且只写入一份不可变报告；刷新页面后报告完全从保存内容渲染，不重新查询百度来源。
- [ ] 调用尝试只保存模型、平台、版本、阶段、耗时、Token 用量和归一化状态或错误，不保存完整 Prompt、模型原始响应或上游原始报文。
- [ ] 未授权用户持有项目、运行或报告标识时无法读取资源，也不能判断资源是否存在。
- [ ] SQLite 与 PostgreSQL 的迁移审计、基础 API、完整生成路径、报告校验、前端空状态和成功状态均有自动化测试。
