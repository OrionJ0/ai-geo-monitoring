# 失败重试、重新运行与取消隔离

## Parent

- [PRD](../prd.md)
- [Tech Spec](../TECH-SPEC.md)

## What to build

为失败或未结束运行提供语义明确的用户控制。重试必须继续原运行并保留原周期、模型、参数及所有版本：基线锁定前丢弃部分来源结果并重新读取同一组来源，基线锁定后只复用原证据继续后续阶段。重新运行始终创建新运行并重新取数。取消是不可重试终态，晚到的来源或模型结果不得提交。

页面、API 和审计记录必须始终使用“重试”“重新运行”“取消”三个不同动作，不用新任务冒充原任务重试，也不复活已经取消或被更新运行取代的任务。

## Acceptance criteria

- [ ] 失败运行在尚无更新运行时可重试，重试返回同一 runId 并追加调用尝试，不创建第二条运行记录。
- [ ] 基线锁定前重试完整重读同一组来源且不保留部分结果；基线锁定后复用原证据包并只继续未成功阶段。
- [ ] 重试始终保留原周期、平台、模型、请求参数、Prompt、Evidence、Report 和 Chart Schema 版本，不静默切换当前配置。
- [ ] 项目创建任何更新运行后，旧失败运行永久返回不可重试，但继续保留轻量审计。
- [ ] 重新运行即使日期相同也创建新 runId、重新读取来源并形成新基线；同项目防重仍然生效。
- [ ] 取消只适用于未结束运行，成功后进入不可重试终态；再次分析只能重新运行。
- [ ] 来源或模型调用无法立即中断时，执行令牌和条件提交阻止晚到结果写入证据包、报告或成功状态。
- [ ] 失败、重试、重新运行和取消期间，已有当前报告始终保持不变。
- [ ] 三类操作都需要权限与幂等保护，未授权调用不能探测运行是否存在。
- [ ] 基线前后重试、更新运行使旧任务失效、配置版本固定、重新取数、取消竞争和晚到结果隔离均有自动化测试。
