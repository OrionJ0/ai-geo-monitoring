# SEO 技术健康分 v4：正式切换与验证

## 交付结果

SEO 检测正式入口 `/geo/seo-audit` 的单页和全站新报告均已切换到 `technical-health-v4`。主指标统一为“技术健康分”，不再把检查通过率或旧版“技术健康度”作为并列主分数。

旧报告不重算、不覆盖，仍按报告 JSON 中保存的原始分数和版本查看、导出和回导。新报告的正式评分路径为：

```text
SeoAuditService / SeoSiteAuditService
  → SeoHealthScoreService
  → 四阶段得分、覆盖率扣分、确定性阻断封顶
  → 历史 JSON / 标准 CSV / 前端技术健康分报告
```

旧的“通过检查权重 ÷ 全部检查权重”只用于解释既有 v1–v3 历史，不再作为新报告的 fallback。

## v4 评分事实

- 访问与发现 30 分、索引资格 25 分、内容理解 30 分、展示与增强 15 分。
- 规则配置权重只决定规则在所属阶段中的份额。
- 全站同类问题按规则聚合，扣分使用受影响页面的加权覆盖率；首页权重 3、普通页面权重 1。
- Sitemap 是访问与发现阶段的高风险问题，空内容、无有效 `loc`、无效 XML 或不可访问均不能通过，但不单独触发封顶。
- 首页不可用或全部主要传统搜索爬虫被明确禁止时最高 20 分；首页或大范围 `noindex` 时最高 39 分；大范围空正文时最高 59 分。
- 无法确认关键证据时分数为 `null`、状态为 `unknown`，但报告仍保留已经发现的问题、覆盖率和事实，不伪造精确分数。
- Google、Bing、百度验证标签继续展示；缺失标签不扣技术健康分。

唯一评分配置入口仍为 `backend/config/seoAuditRules.js`。`defaultSeoHealthScoreConfig` 维护评分版本、阶段预算、规则归属、首页权重、站点级规则和封顶阈值，并在服务创建时校验预算、重复归属和阈值范围。

## 全站范围与确定性

- 全站任务无论从首页还是子路径启动，都会把同域首页纳入检测。
- 发现来源包括输入 URL、首页、同域链接、默认 Sitemap、robots 声明的 Sitemap 和递归 Sitemap index。
- 站点级问题只计分一次，但报告中的适用范围扩展为本次全部已检测页面，避免“覆盖率 100% 但仅影响 1 页”的展示矛盾。
- `noindex` 和空正文覆盖率只以能够判断对应事实的页面为分母，不会被网络失败页面稀释。
- 并发抓取完成后按发现顺序稳定整理页面和检查实例，相同输入与版本产生稳定报告顺序。

## 历史、比较与数据往返

- 新历史摘要保存 `scoreVersion`、`scoreModel`、状态、原始分、封顶值和四阶段得分。
- 历史列表只在 URL、检测模式、评分版本相同且两次都有有效分数时显示“较上次”变化；旧版报告明确标记“旧版评分”。
- SQLite 的旧 `score NOT NULL` 列继续兼容：无法判断报告在索引列使用内部占位值 `0`，完整报告 JSON 和历史 API 始终返回 `score: null`，前端不会把占位值显示为真实分数。
- 标准 CSV 的 `record_json` 完整保存评分版本、阶段、状态、阻断、覆盖率和实际扣分；回导后恢复相同报告事实，并作为当前账户的新历史保存。

## 前端信息层级

- 单页和全站共用 `TechnicalHealthOverview.tsx`，只展示一个主分数。
- 主分数旁展示状态、主要瓶颈和原始小数分；四阶段使用独立阶段轨道解释扣分来源。
- 检查总数、通过数、失败数、页面范围和评分版本进入“检测范围”明细，不生成第二个通过率分数。
- 问题默认按阻断、阶段、实际扣分、首页影响和覆盖率顺序展示，并分别显示问题、检测事实、示例 URL、覆盖率、实际扣分和小字建议。
- 确定性阻断、关键证据不足和达到页面上限均有独立醒目说明；桌面和窄屏均有响应式布局。
