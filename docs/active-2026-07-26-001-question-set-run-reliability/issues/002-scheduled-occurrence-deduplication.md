# 实现定时计划时槽唯一领取与防重

## Parent

- [PRD](../prd.md)
- [Tech Spec](../TECH-SPEC.md)
- 覆盖用户故事：US-1、US-6

## What to build

为每个定时计划的到期时槽建立持久执行账本，并同时提供进程内 single-flight 与数据库级唯一领取。取得持久时槽所有权后才能创建任务、消耗配额和调用平台；长执行跨越后续 interval 时不得被重复拾取。

该账本表达一次调度执行，不改变问题集报告模型。执行成功、失败或进程退出后都应留下可查询、可恢复、可告警的状态。

## Acceptance criteria

- [ ] 同一个进程中的前一轮 tick 未结束时，后续 tick 不会并行进入扫描和执行。
- [ ] 同一计划、同一到期时槽只能存在一个有效执行实例。
- [ ] 两个进程同时领取同一时槽时，只有一个进程取得执行权；唯一冲突被视为已由其他执行器领取。
- [ ] `next_run_at` 的推进与时槽实例创建处于同一事务，不会出现重复领取窗口。
- [ ] 执行时长超过 30 秒或多个 interval 后，平台调用、任务批次和配额变化仍只有一份。
- [ ] 进程在取得时槽后退出时，执行实例保持可诊断，并能按恢复规则进入明确终态。
- [ ] 项目级监测和单问题计划分别使用自己的 schedule kind，不被错误包装为问题集运行。
- [ ] SQLite 和 Postgres 都通过同一时槽并发领取测试。
- [ ] 可观测数据包含领取成功、重复领取被拒绝、执行终态和最近错误。
