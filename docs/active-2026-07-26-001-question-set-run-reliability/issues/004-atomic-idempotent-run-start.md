# 原子且幂等地提交问题集运行

## Parent

- [PRD](../prd.md)
- [Tech Spec](../TECH-SPEC.md)
- 覆盖用户故事：US-3

## What to build

把问题集运行启动重构为 plan、commit、dispatch 三段式正式入口。客户端以稳定幂等键提交，服务端在同一事务中完成幂等占位、运行实例、配额预留、全部任务和稳定槽位；事务提交后才允许 worker 开始执行。

该切片必须彻底替代“先创建空 run、后逐条建任务、再回写 IDs”的旧路径。重复请求返回同一运行回执，异常不留下空运行、孤儿任务或配额变化。

## Acceptance criteria

- [ ] 前端初次提交生成合规幂等键，网络重试和重复点击复用相同键。
- [ ] 相同用户、项目、问题集和幂等键的并发请求返回同一 run ID。
- [ ] 同一幂等键用于不同请求指纹时返回稳定 409，不错误回放其他运行。
- [ ] 运行实例、配额预留、全部任务和当前槽位在一个事务内同时提交。
- [ ] 在配额后、任务中部或关联阶段注入异常时，run、任务和配额均零残留。
- [ ] 不可用平台及原因随运行计划持久化，并能在最终报告读取。
- [ ] 事务提交后 dispatch 失败不会丢失任务；未领取 pending 可被后续 dispatcher 发现。
- [ ] 正式运行接口只调用新的原子启动入口，不再直接创建空 run。
- [ ] 幂等回放响应明确标识 replay，前端随后重新读取真实报告状态。
- [ ] 入口级测试证明新入口被调用、旧启动路径未被调用。
