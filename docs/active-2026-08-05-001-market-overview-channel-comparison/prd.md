# 市场总览渠道对比与真实数据修复 PRD

## Problem Statement

市场负责人进入市场总览时，需要快速看清广告投入、展现、网站访问、官网咨询、线索入池和成交结果，以及不同访问渠道的规模与变化。当前首页的总体结构和全链路表格已经符合这一目标，但仍存在以下问题：

- 百度推广已有真实投入和展现，首页却可能显示 `—`；
- 百度推广在渠道表中有访问总数，每日访问趋势却可能为空；
- 每日趋势一次只能查看一个来源，不能直接比较全部渠道；
- “官网全站（百度统计）”容易被理解成官网数据源，实际含义只是百度统计全部访问；
- “官网表单咨询”需要简化为“官网咨询”，同时保持当前仅包含官网成功表单、不包含 53KF 的真实边界；
- 系统接口和数据链路故障不应成为市场负责人的首页行动项。

本需求需要修复已有真实数据的显示和一致性，并在尽量保留现有首页与全链路表格的前提下，增强全部访问渠道的横向及趋势对比。

## Solution

采用“完整经营链路 + 渠道对比”的首页方向：

1. 保留现有页面结构、投放效率指标卡和全链路表格；
2. 修复广告投入、展现及百度推广访问趋势的真实数据链路；
3. 将每日趋势默认来源改为“全部”，在同一张图比较全部访问和各个百度统计渠道；
4. 支持通过图例隐藏或恢复渠道，并通过全链路表格渠道行切换单渠道趋势；
5. 增加渠道访问占比和上一等长周期变化；
6. 调整首页展示名称，但不改变数据来源和事实口径；
7. 系统级诊断留在管理侧日志或监控，首页只在受影响指标位置诚实显示简洁状态。

## User Stories

1. As a 市场负责人, I want to see accurate advertising spend and impressions on the overview, so that I do not mistake existing delivery for missing data.
2. As a 市场负责人, I want to compare all website traffic channels in one daily trend chart, so that I can identify channel structure and movement quickly.
3. As a 市场负责人, I want to click a channel in the full-chain table and inspect its trend, so that I can move from comparison to diagnosis without rebuilding filters.
4. As a 市场负责人, I want channel share and period-over-period change, so that I can distinguish absolute growth from a shift in traffic mix.
5. As a 市场负责人, I want missing, zero, not-applicable and not-connected states to remain distinct, so that I do not make decisions from fabricated completeness.
6. As a 市场负责人, I want data-source labels to match their real meaning, so that I understand which system produced each metric.

## Scope

### In scope

- 保留并修复现有市场总览正式入口；
- 保留现有投放效率卡和全链路表格的结构、渠道顺序和主要视觉；
- 修复首页广告投入、展现、点击及 CPC 的周期汇总；
- 核验并修复百度推广访问的每日趋势；
- 每日趋势默认选择“全部”；
- 同图展示全部访问和所有内置百度统计渠道；
- 图例隐藏/恢复渠道；
- 表格渠道行与每日趋势联动；
- 展示渠道访问占比和上一等长周期变化；
- “官网全站（百度统计）”改为“全部”；
- 首页“官网表单咨询”改为“官网咨询”，并明确当前不包含 53KF；
- 补齐相应的自动化、响应式、无障碍和正式入口验收。

### Out of scope

- 重做或替换现有全链路表格；
- 首页异常行动中心、系统错误排行榜或数据运维工作台；
- 把全部访问与已分类渠道的差额新增为业务渠道；
- 接入 53KF、销售系统、线索或订单数据；
- 新增或推断跨系统归因关系；
- 使用广告点击代替百度统计访问；
- 使用模拟数据、同期数据、比例或差额填补未知值；
- 保存个人看板、自定义 KPI、导出或渠道排序。

### Later

- 53KF 接入后的在线客服咨询；
- 销售系统接入后的线索、订单和真实渠道转化；
- 基于可信归因合同的渠道效率排名；
- 保存常用筛选、导出渠道对比和渠道排序。

## Product Behavior

### 1. 页面结构

首页继续按以下顺序展示：

1. 设备与日期筛选；
2. 投放效率；
3. 现有全链路数据表格；
4. 每日趋势。

不新增异常中心、第二套全链路组件或说明型首屏。

### 2. 指标与数据来源

| 指标 | 唯一主数据源 | 产品边界 |
| --- | --- | --- |
| 广告投入、展现、点击 | 百度推广 | 点击只用于广告指标，不冒充访问。 |
| 访问及访问渠道 | 百度统计 | 所有渠道访问使用同一百度统计口径。 |
| 官网咨询 | 官网成功表单记录 | 当前不包含 53KF；只按可信来源证据进入渠道行。 |
| 在线客服咨询 | 53KF | 尚未接入，不并入官网咨询。 |
| 线索入池、成交订单与金额 | 销售系统 | 尚未接入，不使用其他指标反推。 |

ROAS、CPL、CPA、成交率和整体转化率只有在真实分子、分母及其关系均成立时才计算。

### 3. 投放效率

- 保留现有卡片布局、顺序、数量和样式；
- 保留本期、上一等长周期和周期变化；
- 已存在的真实广告投入、展现和点击不能因为零投放日未单独返回而显示为缺失；
- 接口失败、合同无效或覆盖无法证明时仍显示缺失，不能按零处理；
- 线索、订单及依赖它们的指标保持缺失，直到销售系统真实接入。

### 4. 全链路表格

- 保留现有列、渠道行、顺序、动态官网来源行和主要视觉；
- 百度推广的投入和展现来自百度推广，访问来自百度统计；
- 其他渠道的访问来自百度统计；
- 不适用、未知、读取失败和真实零值保持不同语义；
- 表头“官网表单咨询”改为“官网咨询”；
- 表头提示说明“当前仅包含官网成功表单记录，不包含 53KF 在线客服咨询”；
- 点击可精确对齐百度统计的渠道行后，每日趋势切换到该渠道；再次点击当前渠道或选择“全部”后恢复全部渠道对比；仅存在于官网表单的 UTM、未知来源等动态行不提供虚假的访问趋势联动；
- 渠道名称原有的下钻链接继续有效，不被行联动拦截。

### 5. 每日趋势

- 来源选择器默认值和展示名为“全部”；
- “全部”表示百度统计全部访问渠道，不表示官网表单数据源；
- “全部”模式只提供“访问”指标；
- 图中使用一条较粗的全部访问线，并展示百度推广、直接访问、百度自然搜索、必应自然搜索、Google 自然搜索、其他搜索和外部网站引荐；
- 图例支持隐藏或恢复渠道；
- 悬停某日时，先展示全部访问，再按当日访问量从高到低展示渠道；
- 当前周期渠道曲线显示在图中；上一周期通过摘要和变化率展示，不再叠加第二组全部渠道曲线；
- “全部”模式展示全部访问总量、日均、峰值、较上一周期变化、渠道占比和渠道变化；
- 百度推广单渠道可以切换广告投入、展现和访问；
- 其他单渠道只提供访问；
- 单渠道模式继续显示当前周期和上一等长周期趋势；
- 真实零值绘制到零轴；未知或不可用值显示 `—`，对应曲线断开。

### 6. 状态与错误

| 状态 | 用户可见行为 |
| --- | --- |
| 真实零值 | 显示 `0`。 |
| 缺失或未知 | 显示 `—`，不参与推算。 |
| 不适用 | 显示 `—`，提示“该渠道不适用此指标”。 |
| 未接入 | 显示 `—`，简要说明对应来源尚未接入。 |
| 读取失败 | 受影响位置显示“暂不可用”，其他独立来源继续展示。 |

首页不展示面向市场负责人的接口错误列表、缓存异常列表或修复建议。

### 7. 响应式与无障碍

- 桌面端在一张图中完成全部渠道比较；
- 图例支持键盘操作，不能只通过颜色表达选择状态；
- 表格行联动支持键盘，且不破坏表格语义和原有链接；
- Tooltip 提供等价可访问文本；
- 移动端不改变统计范围，可缩减日期标签或在图表容器内浏览；
- 页面本身不能产生横向溢出。

## Acceptance Criteria

- AC-001：相同项目、设备和日期范围下，首页广告投入、展现和点击汇总与广告表现页一致。
- AC-002：零投放日未单独返回时，首页仍正确展示周期广告汇总；接口失败或覆盖未知时不按零补齐。
- AC-003：百度推广存在访问汇总时，每日趋势返回可解释的逐日序列，逐日加总与同口径汇总一致。
- AC-004：来源选择器默认显示“全部”，正式页面不再出现“官网全站（百度统计）”。
- AC-005：“全部”模式同图展示全部访问及七个内置百度统计渠道，图例可隐藏和恢复渠道。
- AC-006：“全部”模式只允许访问；百度推广单渠道允许广告投入、展现和访问；其他单渠道只允许访问。
- AC-007：“全部”模式展示渠道访问占比和上一等长周期变化，不在图中叠加上一周期的全部渠道曲线。
- AC-008：点击可精确对齐百度统计的全链路表格渠道行后趋势切换到该渠道；再次点击或选择“全部”后恢复全部渠道对比；官网表单专属来源行不提供趋势联动，原有渠道下钻链接仍正常工作。
- AC-009：全链路表格的结构、渠道顺序、动态官网来源行和主要视觉保持不变。
- AC-010：首页展示名统一为“官网咨询”，并明确当前只包含官网成功表单、不包含 53KF。
- AC-011：渠道占比只使用同一百度统计口径，不通过差额反推未知来源。
- AC-012：真实零值、缺失、不适用、未接入和读取失败保持不同语义，不以模拟数据掩盖未知状态。
- AC-013：首页不新增异常行动中心或系统错误排行榜。
- AC-014：桌面和移动端没有页面级横向溢出；图例、表格联动和趋势摘要支持键盘及可访问文本。
- AC-015：从正式入口验证首页实际使用新链路，旧趋势行为和旧标签没有静默 fallback。

## Metrics / Success

- 市场负责人可在 30 秒内识别当前主要访问渠道、渠道占比和周期变化；
- 首页与广告表现页在相同范围的广告汇总一致率为 100%；
- 百度统计渠道逐日访问与对应汇总在可用状态下保持一致；
- 正式页面不再出现已知的“汇总有值但趋势为空”静默矛盾；
- 正式页面不出现未知值被展示为 0、广告点击被展示为访问或未接入指标被模拟补齐的情况。

## Constraints

- 当前正式入口固定为 `https://insight.guangtuo.com`；
- 百度推广、百度统计、官网、53KF 和销售系统继续保持独立数据边界；
- 现有全链路表格是用户确认保留的核心组件；
- 新行为必须使用真实公开入口验收，不能只凭 fixture、单元测试或独立模块测试宣称完成；
- 替换首页旧趋势链路时执行正式硬切，不保留静默 fallback 或第二套兼容路径；
- 不修改已应用数据库迁移；若实现不需要新持久化结构，不新增迁移。
