# ADR 0001：营销漏斗数据主数据源与官网无侵入接入边界

## 决策状态

本决策自 2026-08-03 起生效，约束市场总览、网站流量、后续官网/客服接入、指标计算、测试和文档。`accepted` 只表示数据合同已经确认；当前官网表单咨询已完成本地实现，但这不表示改动已经提交、部署、设为生产默认或通过正式入口验收。

## 主数据源

| 事实 | 唯一主数据源 | 当前用途 |
| --- | --- | --- |
| 百度广告展现、广告点击、消费 | 百度营销 | 百度推广行和 CPC |
| 网站来源、访问次数、访客数（UV）、浏览量（PV） | 百度统计 | 网站流量及非付费来源的访问事实 |
| 官网表单咨询 | 官网数据库中成功写入的全部表单记录 | 独立“官网表单咨询”列，不与 53KF 自动合计；来源缺失的记录计入 `UNKNOWN` |
| 官网访问到表单咨询的来源关系 | 官网一方埋点随表单提交保存的来源上下文 | 官网表单来源归属与数据质量核验 |
| 53KF 在线客服咨询 | 53KF 中访客实际发送过消息的有效对话 | 客服咨询中的“在线对话”部分 |
| 线索入池 | 内部销售系统的有效线索入池事实 | 线索入池数、CPL 分母 |
| 成交订单数和成交订单金额 | 内部销售系统的成交订单事实 | CPA、成交率、整体转化率、ROAS |

不得把多套流量数据相加、取平均、互相补差或选择“看起来更好”的数字。官网一方访问会话是来源关联和对账证据，不替代百度统计的来源、访问、UV、PV 主数据源。

## 百度统计与百度营销的职责边界

百度统计与百度营销都可能展示展现、广告点击、消费、CTR、CPC、推广计划、推广单元、关键词、创意或搜索词，但两者不是可互换的双主数据源：

- 百度营销回答“广告投给了谁、投放结构与状态是什么、产生了多少展现/点击/消费”；稳定广告 ID、层级、状态、出价、匹配、质量和投放效果以百度营销为准。
- 百度统计回答“访问从哪里来、用户进入网站后看了什么、访问质量和站内行为如何”；访问次数、PV、UV、新访客、来源、设备、地域、入口页、受访页、跳出率、平均访问时长和平均访问页数以百度统计为准。
- 百度统计的“搜索推广”页面是广告账户维度与网站维度的联表分析视图。它适合诊断某个计划、单元、关键词、创意、搜索词或推广 URL 带来的站内行为，不构成完整广告对象合同，也不能替代百度营销。
- 同一名称不证明同一语义。百度统计的站点目标/事件转化与百度营销的目标转化、深度转化、线索或订单转化必须分字段保存；在定义、归因窗口、去重、日期、时区和覆盖全部确认前，不得合并或相互补齐。

### 数据重叠裁决

| 数据域 | 百度统计能力 | 百度营销能力 | 唯一主数据源与用法 |
| --- | --- | --- | --- |
| 展现、广告点击、消费、CTR、CPC | 搜索推广报表可见 | 官方投放事实 | 百度营销；百度统计副本只作对账 |
| 计划、单元、关键词、创意 | 可作站内行为分析，但字段与稳定键不完整 | 稳定 ID、层级、状态及投放属性 | 百度营销 |
| 搜索词 | 页面可作访问分析；公共 API 能力须逐项验证 | 搜索词、触发、匹配、状态等广告证据；官方响应没有关键词 ID | 百度营销保存独立搜索词事实，不按文本伪造关系 |
| 访问次数、PV、UV、新访客 | 网站访问事实 | 不提供等价网站访问事实 | 百度统计 |
| 来源、设备、地域、入口页、受访页、访问质量 | 完整网站分析能力 | 仅有有限投放切片 | 百度统计 |
| 网站目标/事件转化 | 依赖百度统计目标或事件配置 | 不等价 | 百度统计独立字段，未验证配置时缺失 |
| 目标转化、深度转化、线索、商品订单 | 不构成同一推广转化合同 | 依赖百度营销转化追踪 | 百度营销独立字段，未验证口径时缺失 |
| 出价、匹配、质量、排名、胜出率、无效点击/线索 | 无完整合同 | 有专门属性或报告 | 百度营销 |

重叠数据只能对账，不能合计。对账至少对齐账户、日期范围、时区、设备、投放产品、网站覆盖和数据刷新时间；门禁不齐时记录“不可比”，不得通过补差制造一致。当前页面展示和正式快照中的广告事实仍以百度营销为准，百度统计侧的广告副本只保存为诊断或一致性证据。

## 相关 API 合同与建议采集范围

两套产品在 API 网关中使用不同服务、凭据和数据合同，没有可以互换的“同一个 API”：

| 平台 | 统一报告入口 | 报表区分方式 | 当前项目正式采集 |
| --- | --- | --- | --- |
| 百度营销 | `OpenApiReportService/getReportData` | `reportType` | 计划 `2290316`、单元 `2284618`、关键词 `2602783`、搜索词 `2307838` |
| 百度统计 | `ReportService/getData` | `method` | 趋势、来源、入口页、受访页与访问质量 |

百度统计当前应正式采集：

- 整体及分时趋势：PV、访问次数、访客数、新访客及已验证的质量指标。
- 来源结构：百度付费、直接访问、百度自然搜索、其他搜索和外部引荐；来源拆分必须服从本 ADR 的证据与九键合同。
- 访问质量：跳出率、平均访问时长、平均访问页数。
- 页面表现：入口页、受访页及其已验证指标。
- 只有在目标/事件已经由业务确认并完成真实响应验收后，才采集网站转化。

百度统计官方 `getData` 目录中与本项目相关的候选方法包括 `trend/time/a`、`trend/latest/a`、`pro/product/a`、`pro/hour/a`、`source/all/a`、`source/engine/a`、`source/searchword/a`、`source/link/a`、`custom/media/a`、`visit/toppage/a` 和 `visit/landingpage/a`。网页能切换某个维度不代表公共 API 返回相同字段；推广层级、创意、搜索词、推广 URL、设备、地域、实时和事件数据在接入前都必须用官方文档及真实响应验证 method、稳定键、分页、日期上限和口径。未通过验证的能力只属于候选诊断数据，不进入正式合同。

百度营销继续以四份报告同次原子刷新为最小正式集合。只有明确产品用途并建立字段合同、预算、分页、去重和真实响应测试后，才增量引入创意、落地页、出价、匹配、质量、排名、胜出率、转化、无效点击或无效线索等报告；不得因为官方字段很多而一次性全量采集。

- 百度营销账户报表在 2026-07-29 至 2026-08-04 显示消费 1,534.57、点击 104；2026-08-05 账户概览显示消费 263.49、点击 23。

## 指标与事件语义

- 官网 `contact_click_sessions` 或同义字段只表示点击“联系我们/服务申请”入口的去重会话，是意向诊断指标，不是客服咨询。
- 官网 `submission_sessions` 或同义字段表示能关联到访问会话的成功表单提交会话，可用于归因覆盖诊断，但不再作为首页和咨询页的表单咨询总数。表单咨询总数以联系人列表中的全部成功入库记录为准。
- 53KF 咨询必须以有效对话为单位，至少证明访客实际发送过消息；仅打开客服窗口、加载脚本、机器人自动问候或点击浮窗不计为咨询。
- 官网表单的 `pending`、`processing`、`done` 是处理状态，不是线索入池、销售机会或成交状态。
- 联系人记录若带有经严格 URL 校验的原始 `referrer`，按主机名精确拆成对应搜索来源或外部引荐；没有可信来源证据的记录仍计入表单咨询总数，并归入 `UNKNOWN`。不得按同期比例拆分来源。
- 只有记录级可信来源键、可审计映射或确认过的人工关联成立时，下游事实才进入具体来源行；来源缺失的历史记录保持“来源未知”或缺失状态。

## 首页取数规则

```text
百度推广：
  展现 / 广告点击 / 广告投入 <- 百度营销
  官网访问 <- 百度统计付费搜索来源
  表单咨询 <- 官网中 source=baidu_paid 的成功表单提交
  在线客服咨询 <- 53KF 中可信归属为百度推广的有效对话

其他访问渠道：
  访问 / UV / PV <- 百度统计
  表单咨询 <- 官网中对应 source 的成功表单提交
  在线客服咨询 <- 53KF 中对应 source 的有效对话
```

跨系统计算咨询率前必须同时满足来源映射、日期、时区、统计粒度和数据覆盖门禁。门禁不满足时展示缺失或部分覆盖，不能把同期总量直接相除。

## 官网无侵入接入合同

2026-08-03 从 `https://gato.com.cn` 生产入口只读验证到以下现有能力：

- `POST /api/v1/auth/login`：返回后台 JWT；真实凭据不得写入文档、前端、日志或 fixture。
- `GET /api/v1/admin/contact/list`：按日期分页返回全部联系人记录；首页和咨询统计由 GoodieAI 后端从此列表计算，不再读取官网聚合统计接口。
- `GET /api/v1/admin/contact/:id`：仅供已登录用户按需查看单条咨询审计详情，不参与首页或咨询页统计。
- 归因相关字段包括 `sourceChannel`、`firstSourceChannel`、`referrer`、UTM 字段和百度点击标识；统计还使用 `id` 去重、使用 `createdAt` 按 `Asia/Shanghai` 归日。

GoodieAI 后端允许为首页和咨询统计分页读取 `/admin/contact/list`，但统计服务只使用日期与归因字段，立即聚合为九键数量；姓名、电话、邮箱、IP、咨询内容、访客 ID、会话 ID、原始 `referrer` URL 均不得写入统计快照、日志或公开统计响应。单次统计最多读取 10,000 条，超过预算必须整体失败，不能返回部分统计。咨询页的记录列表和单条详情仍须经过服务端严格校验、脱敏并通过独立审计合同输出；浏览器不能收到官网后台凭据、JWT、访客 ID、会话 ID 或联系点击 ID。接入凭据只能由 GoodieAI 后端环境或密钥管理注入，JWT 只在服务端缓存并在过期或 401 后重新获取。

本地实现固定采用以下边界：官网表单统计使用 `backend/modules/websiteFormConsultations`、`/api/website-data`、`website_data_schema_migrations` 和前端 `src/lib/websiteData`；按需咨询记录使用 `backend/modules/consultationRecords` 和 `/api/consultations`；百度营销/百度统计继续使用 `backend/modules/marketing`、`/api/marketing` 和 `marketing_schema_migrations`。三条数据链路不得共用服务、公开响应合同、模块状态或迁移账本，只共享登录鉴权、项目所有权校验等通用基础设施。统计快照只保存日期范围、九键来源与表单记录数，不保存联系人、会话标识或原始 URL。

正式来源目录固定为九键：`BAIDU_PAID`、`DIRECT`、`BAIDU_SEARCH`、`BING_SEARCH`、`GOOGLE_SEARCH`、`OTHER_SEARCH`、`EXTERNAL_REFERRAL`、`UTM_CAMPAIGN`、`UNKNOWN`；`ALL` 只是查询哨兵，不是来源键。旧 `ORGANIC_SEARCH`、`REFERRAL`、`CAMPAIGN`、`SOCIAL`、`UNATTRIBUTED` 不再属于公开合同。

记录级归因按证据优先级执行：可信百度点击标识或百度付费 UTM → `BAIDU_PAID`；任一其他有效 UTM → `UTM_CAMPAIGN`；有效外部 `referrer` 依次识别百度、必应、Google、其他已识别搜索引擎或普通外部网站；无外部证据时，仅允许首次/当前来源明确为 `baidu_paid` 或 `direct` 的记录回退到 `BAIDU_PAID` 或 `DIRECT`，其余全部为 `UNKNOWN`。咨询详情保留上游返回的原始 `referrer` URL 作为重新核验键的证据。

首页和咨询页使用同一份记录级九键归因规则：后端对所选区间的联系人列表逐条分类，再只返回 `formConsultationRecords` 总数、九键 `sourceBreakdown` 及最多 31 日的逐日拆分。全部记录都计入总数；无效、缺失或无法识别的来源进入 `UNKNOWN`。前端只调用 GoodieAI 的 `/api/website-data`，不得直接调用官网后台，也不得用咨询记录详情重新计算页面统计。

## 已知风险与完成门禁

1. 用户提供的官网本地仓库 `/Users/gato/Developer/product_gato_website_full_stack` 的 `main`/`origin/main` 在核验时为 `c4cd5dc`，本地源码不包含生产接口已经返回的来源归因字段和 `conversion` 聚合结构。正式依赖该合同前必须找回并同步生产实际源码、schema、迁移和测试；否则下一次从旧仓库部署可能退役这些能力。
2. 使用共享官网管理员账号只适合无侵入试点。正式长期同步应改为最小权限的只读服务账号或专用 API 密钥；完成前不得把全权限后台账号描述为稳定外部合同。
3. 53KF 官方公开说明支持来源/访问/对话统计与开放 API，但具体账户权限、接口字段、去重规则和历史覆盖尚未验证。完成真实 API 验收前，53KF 咨询保持缺失。
4. 官网适配器、缓存和以联系人列表统计全部记录的 `v3` 快照合同已部署，但生产尚未注入专用官网项目与只读账号凭据，因此模块保持 `DISABLED`；正式页面不会产生真实官网统计。
5. 2026-08-04 九键分类器、联系人归因字段校验、原始 `referrer` 证据展示、首页与咨询页全部记录九键统计合同已完成本地实现、测试并随 `6894789` 通过正式 Git Bundle workflow `30900162256` 部署。2026-08-05 公开健康接口已验证该 revision；由于模块禁用，本轮无法完成登录后的真实官网数据验收。

## 被否决的做法

- 用官网一方 PV/UV/访问数替换百度统计。
- 把百度统计和官网一方流量相加、平均或按差额补齐。
- 把联系入口点击、53KF 窗口打开或表单处理完成状态当作客服咨询/线索入池。
- 把联系人列表中的个人信息、咨询内容、会话标识或原始 URL 写入统计快照、日志或首页统计响应。
- 把 `organic_search` 按同期比例拆成百度自然、必应自然或其他搜索引擎。
- 在生产源码尚未同步、合同测试尚未建立时宣称官网 API 已形成稳定正式依赖。
