# DeepSeek Flash 结构化分析可靠性改造 PRD

## Problem Statement

当前 GEO 监测可以成功采集完整回答，但同一批记录仍可能在后续“AI 结构化分析校验”阶段全部失败。用户看到的典型现象是：原回答内容完整、结束原因是 `stop`、模型也返回了 JSON，但系统提示 `invalid_analysis_output`，并因 `mentions[].surface_forms` 无法在原回答中定位而不写品牌指标。

2026-08-05 使用真实问题“**大工业园区用什么安防设备比较好？**”、用户提供的完整豆包回答和正式指定模型 `deepseek-v4-flash` 复现后确认：

- 原回答没有提及目标品牌“广拓”，当前 v4 分析却连续把“广拓”生成为实体和原文表面词；严格校验因此正确拒绝输出。
- 当前正式 v4 把实体抽取、别名归一、目标映射、逐实体竞品关系、候选集合与顺序、明确推荐、品牌主张、目标情绪及全部原文证据放在一次请求中完成。任务间相互污染时，任何一个必填字段错误都会使整份结果失败。
- 当前分析服务对 DeepSeek 没有显式发送温度，通用请求层会补入 `temperature=0.7`。把同一真实请求显式改为 `temperature=0` 后仍然失败，说明采样温度会放大波动，但不是根因。
- 本地已有 45 条相关单元测试全部通过，但真实 Flash 请求仍稳定复现失败，说明现有测试主要证明“校验器会拒绝坏数据”，没有证明“生产提示和请求参数能让 Flash 稳定产生好数据”。

因此，这不是单纯的 JSON 语法问题，也不能靠放宽 `surface_forms` 校验解决。JSON mode 只能提高输出为合法 JSON 的概率，不能保证字段值真实、跨字段引用一致或文本证据确实存在。若放宽校验，系统会把模型虚构的目标品牌写成“已提及”，直接污染品牌提及率、推荐率、排名和 SOV。

本需求要解决的产品问题是：在**必须继续使用 `deepseek-v4-flash`** 的前提下，让有效完整回答稳定地产生可审计的目标品牌指标；竞品发现属于尽力而为的开放式增强，允许遗漏并明确记录覆盖状态，但任何进入指标的事实仍须可证明，不以伪造数据换取表面成功率。

## Solution

提供一条面向 Flash 的分阶段结构化分析能力，并把原来的单一“成功/失败”结果拆成三条互不拖累的事实轨：

1. **目标事实轨**：程序直接用项目已配置的目标名称/别名扫描完整原回答，确定目标是否出现、出现次数和原文位置；不依赖开放竞品抽取是否完整，也不由 AI 补证据。
2. **目标语义轨**：Flash 只判断目标品牌的推荐、排名和情绪；每个字段独立返回 `assessed`、`not_applicable`、`unresolved` 或 `invalid`，未知不得伪装成 `false`、`neutral` 或“无排名”。
3. **开放竞品轨**：Flash 尽力发现回答中的其他组织，并在封闭实体 ID 上判断关系；允许漏掉竞品或关系，漏掉只降低该轨覆盖状态，不使目标事实或已证明的目标语义失败。

系统先把原回答转换成带稳定编号的原文片段。目标事实轨直接在原文上工作；开放竞品轨只保留能够逐字定位的实体；程序生成封闭实体目录后，语义阶段只能引用实体 ID 和原文片段 ID。最终指标由程序依据各字段状态分别计算。

核心产品原则如下：

1. **事实先于语义**：只有已经在原回答中精确定位的实体，才有资格进入后续语义判断。
2. **开放抽取、封闭判断**：第一阶段可发现未知品牌；第二阶段只能引用第一阶段生成的实体 ID 和原文片段 ID，不能再创造新实体或新证据。
3. **目标品牌独立识别**：实体抽取阶段不向模型提供目标品牌，避免模型把任务上下文误当成回答事实。目标品牌是否出现由程序直接使用已配置名称/别名扫描原回答，不以第一阶段是否抽到该实体为前提。
4. **程序计算指标**：提及次数、品牌是否提及、排名和 SOV 继续由程序从已验证事实计算，模型不得直接输出这些指标。
5. **字段级状态与修复**：重试只修复失败阶段或失败字段，不重新生成已经通过校验的事实；重试仍失败时，把对应字段标为 `unresolved` 或把开放竞品项隔离，不把未知值改写成业务否定值。
6. **核心失败关闭、增强允许部分成功**：无法证明的实体、关系或证据不得进入指标；竞品没抽到或关系没判出时记录为未解决，不得拖累已经可证明的目标品牌指标，也不得回退 v4、Pro、旧提示词或宽松规则。
7. **先比较、后切换**：先用冻结的真实回答对当前 v4、降温 v4 和分阶段候选方案做同题、同模型、重复对比；只有候选方案通过预先定义的质量、稳定性和成本门槛，才允许进入正式入口硬切。

新分析版本拟使用 `ai_structured_v5` / `geo_metric_input_v5`，结构合同修订号为 `three_track_partial_v1`。原有 SOV 计算公式可以保留，但含义必须显式带范围：开放发现模式使用新的 `contextual_competitor_mentions_sov_v2_scoped`，状态为 `observed_only`、范围为 `open_discovery`、完整性为 `not_proven`。它只表示“本次已发现且已证明的上下文实体中的提及份额”，不是完整市场竞品份额。历史 `contextual_competitor_mentions_sov_v1` 保持只读，不与 v2 静默拼接趋势。

## User Stories

1. As a GEO 监测用户, I want 完整回答能够稳定完成结构化分析, so that 报告不会因分析模型的小幅波动整批失去品牌指标。
2. As a 报告阅读者, I want 目标品牌未在回答出现时一定显示为未提及, so that 系统不会制造虚假曝光、推荐或排名。
3. As a 数据审查人员, I want 每个实体和语义结论都能追溯到原文片段, so that 我可以复核模型为什么得出该结论。
4. As a 产品负责人, I want 用同一批真实回答对比当前方案和新方案, so that 上线决策基于可重复证据，而不是少量演示样例。
5. As a 运维或开发人员, I want 失败记录能指出具体阶段和字段, so that analysis-only 重试与后续修复不需要重新采集回答。
6. As a 成本负责人, I want 在可靠性提高的同时看到 Token、延迟和重试次数对比, so that 分阶段方案的成本是透明且受控的。

## Scope

### In scope

- 正式结构化分析固定使用 DeepSeek API 的 `deepseek-v4-flash`，关闭思考模式和 Web 搜索，显式使用确定性请求参数。
- 把完整回答确定性切分为带稳定 ID 的原文片段，并保留原文偏移映射。
- 第一阶段仅抽取回答实际出现的品牌、公司和其他具名组织及其精确表面词。
- 程序校验原文定位、归并实体、生成稳定实体 ID，并在模型调用之外匹配目标品牌别名。
- 第二阶段只用实体 ID 和原文片段 ID 判断场景竞品关系、候选分组及顺序、明确推荐和目标情绪。
- 为目标事实、推荐、排名、情绪和开放竞品分别保存状态；聚合分母只纳入对应字段的 `assessed` 结果。
- 对开放发现 SOV 增加 `observed_only / open_discovery / not_proven` 元数据，并与历史 v1 指标版本隔离。
- 保持目标品牌未提及时情绪不参与统计；传输或数据库兼容占位不得进入聚合。
- 把没有现行 KPI 用途且没有证据绑定的自由文本 `claims` 移出核心完成门禁；v5 新记录标记为未采集，历史 v4 主张保持只读。
- 增加分阶段、有界、可审计的错误与运行诊断。
- 建立冻结真实回答语料、人工真值和可重复的 A/B/C 对比报告。
- 从单问题、问题集、自动监测和 analysis-only 重试四类正式入口验收新版本实际生效。
- v5 通过门禁后硬切为唯一新分析路径；v4 仅保留历史结果读取，不作为运行时 fallback。

### Out of scope

- 改变目标品牌提及、推荐、排名和情绪的业务含义；本需求只补充“已判断/不适用/未解决/无效”的状态语义。
- 把开放发现 SOV 宣称为完整竞品市场份额，或在本需求中建立一个保证完整的全行业竞品知识图谱。
- 建立项目级封闭竞品全集。若后续业务需要可跨周期严格对比的 SOV，须另行维护版本化竞品清单与别名，并使用不同的范围和指标语义版本。
- 放宽精确原文证据校验，或使用模糊匹配把不存在的表面词“修好”。
- 使用 DeepSeek Pro、多模型投票、模型自动升级或其他模型兜底。
- 把项目人工竞品清单作为生产实体抽取或竞品关系判断输入。
- 重新访问豆包或 DeepSeek 网页来完成 analysis-only 重试。
- 批量改写历史 v4 指标、原回答、引用或证据。
- 仅以 JSON parse 成功率作为方案质量证明。
- 在本需求中恢复或扩展自由文本品牌主张分析。

### Later

- 在核心指标链路稳定后，单独设计带原文片段 ID 的可选品牌主张审计阶段。
- 若 DeepSeek 的严格工具调用接口在独立能力试验和完整基线中均通过，可通过新需求评估是否替换普通 JSON mode；不得在当前运行时静默双轨切换。
- 根据生产累计数据建立长期漂移监测与周期性人工抽样复核。

## Product Behavior

### 分析前置条件

- 只有采集质量有效、问题和完整原回答均存在的记录进入结构化分析。
- 系统必须使用管理员配置的 DeepSeek API 凭据，但正式分析模型固定为 `deepseek-v4-flash`；模型不匹配时明确报告配置错误，不自动改用 Pro。
- 同一条冻结回答在对比实验中不得重新向监测平台提问，以排除网页回答变化对实验的干扰。

### 实体抽取

- 系统先给原回答的每个稳定片段编号，例如 `L001`、`L002`。
- 第一阶段 Flash 只能返回片段 ID、片段中的精确组织表面词、标准显示名和实体类型。
- 第一阶段不接收当前问题、目标品牌、目标别名、项目竞品或人工真值，只处理待分析回答本身。
- 程序逐项确认表面词确实存在于对应片段；不在原文中的实体项进入隔离清单，不进入第二阶段，也不使其他有效实体或目标事实失败。
- 同一实体的多个有效表面词可归并；提及次数由程序扫描有效表面词和非重叠位置计算。
- 模型给出的 `canonical_name` 只作显示候选。未经项目注册或原文证明的派生短名、中英文别名不得参与提及扫描、目标映射或 SOV 计算。

### 目标品牌识别

- 程序只使用项目已保存的目标品牌名称和别名，直接对完整原回答做 NFKC、大小写折叠和边界感知的确定性扫描；该结果不依赖开放实体目录的召回。
- 回答未出现任何目标品牌名称或别名时，`target_entity_id` 必须为空，品牌未提及、未推荐、无排名，情绪状态为不适用。
- 模型给出的标准显示名不能单独证明目标品牌出现，防止把其他实体错误归一为目标品牌。

### 三轨结果状态

| 轨道 | 最小状态 | 可用于什么指标 | 不得表达成什么 |
| --- | --- | --- | --- |
| `target_fact` | `complete / ambiguous / invalid_input` | `complete` 时可计算是否提及、提及次数及证据位置 | 开放竞品漏抽不能让它失败 |
| `target_semantics` | 总状态 `complete / partial / unavailable`；推荐、排名、情绪各自为 `assessed / not_applicable / unresolved / invalid` | 只有单字段 `assessed` 才进入该指标分母 | `unresolved` 不得当作未推荐、中性或无排名 |
| `competition_analysis` | `complete / partial / unavailable`，且固定携带 `scope=open_discovery`、`completeness=not_proven` | 只使用已验证实体和已证明关系；保存未解决与隔离数量 | 不得宣称完整发现全部竞品 |

整条记录的“可用”不再等于所有轨道全成功。只要输入有效且 `target_fact.status=complete`，目标提及事实即可使用；目标语义和开放竞品各自按状态参与对应聚合。只有原回答缺失/无效、source map 与原文哈希不一致、目标别名发生不可判定歧义、目标事实无法安全计算或事务写入失败，才把目标事实轨判为失败。

### 语义判断

- 第二阶段收到当前问题、已验证实体目录和原文片段，只能引用 `entity_id` 与 `source_id`。
- 竞品关系是尽力而为的增强结果。已经返回的关系必须引用唯一、已验证实体和有效证据；未返回关系的已发现实体进入 `unresolved_entity_ids`，不使整条分析失败，也不进入竞品指标分母。
- 候选集合按回答真实分组保存；并列列举不产生排名，只有明确表达先后时才产生组内顺序。
- 明确推荐必须同时引用实体 ID 和支持推荐的原文片段 ID。
- 目标品牌未出现时不要求模型生成目标情绪；目标品牌出现时才返回正面、中性或负面及证据片段。
- 程序只做 schema、ID、原文证据和业务不变量验证，不得自动补语义证据、从仅含实体名的片段推导推荐/竞品关系，也不得把模型的中性情绪程序性改写为正面。

### 重试与失败

- 实体抽取失败时，只重试实体抽取；语义判断结构或已返回事实无效时，只重试对应阶段或字段。没有发现某个竞品或没有返回某个竞品关系不是结构错误，不触发整条失败。
- 已通过的原文锚定结果不得在后续重试中被重新生成。
- 每个 AI 阶段最多尝试 2 次。超过上限、输出截断、字段不完整或证据失效时，仅将受影响的目标语义字段标为 `unresolved/invalid`，或将受影响的竞品项标为未解决/隔离；已经完成的目标事实继续可用。
- Flash 整体超时或暂时不可用时，程序仍保存确定性的目标事实，并将目标语义和竞品轨标为 `unavailable`；不得回退 v4、Pro 或另一套提示词。
- 失败报告展示稳定错误代码、失败阶段、尝试次数、实际模型、结束原因、输出长度和 Token 用量，不展示密钥或无界原始输出。
- 分析失败保留完整原回答和引用，可继续使用 analysis-only 重试；不得消耗新的监测配额。

### 报告和历史兼容

- 新记录显示 v5 契约、Flash 模型、分阶段诊断和可定位证据。
- 历史 v4 记录按原契约读取，不用 v5 规则重新解释或静默重算。
- 新旧结果可在报告中按版本区分；目标提及聚合使用 `target_fact.status=complete`，推荐、排名和情绪分别只使用对应字段 `status=assessed`，未解决不进入分子也不进入分母。
- 页面、API、CSV 和运行报告必须展示各轨状态、开放竞品范围、未解决数量和隔离数量；开放 SOV 必须标注“仅基于本次已发现实体”，不得显示为完整市场份额。
- 新方案通过正式门禁前，生产仍走 v4；方案文档和单次试验不代表已切换。

### 对比测试与上线决策

对比测试至少包含 40 条去重后的真实完整回答，每个方案对每条回答重复 3 次。语料必须包含用户本次暴露的六类真实问题：

1. 学校项目要用张力电子围栏，有哪些有经验的厂家？
2. 脉冲电子围栏国内哪几家做得比较成熟？
3. 激光对射报警器有哪些质量比较稳定的国产品牌？
4. 想采购电磁感知电缆，国内有哪些专业厂家可以选？
5. 国内做振动光纤周界报警的厂家，哪些比较靠谱？
6. 大工业园区用什么安防设备比较好？

至少比较以下方案，且全部使用完全相同的 `deepseek-v4-flash`：

- A：当前 v4 和当前实际请求参数，作为生产基线。
- B：当前 v4，但显式 `temperature=0`，用于隔离温度影响。
- C：v5 分阶段、普通 JSON mode、显式 `temperature=0`，作为主候选。
- D：v5 分阶段、严格工具调用，只有官方接口能力试验通过时才纳入候选；不支持或不稳定时明确记为“能力不满足”，不得伪装成已比较成功。

上线决策必须同时看结构有效率、原文锚定、语义正确性、重复稳定性、Token 和延迟。任何候选未通过硬门槛时，结论必须是“尚不可切换”，不得只挑成功样例发布。

## Acceptance Criteria

- AC-001：正式候选和最终生产配置的模型均为 `deepseek-v4-flash`；没有 Pro、其他模型或 v4 运行时 fallback。
- AC-002：第一阶段请求不包含目标品牌、目标别名、竞品配置或人工真值。
- AC-003：目标事实由程序直接扫描完整原回答，不依赖第一阶段实体召回；第二阶段不能创建实体，只能引用程序生成的实体 ID 和原文片段 ID。
- AC-004：任何进入指标的实体表面词和语义证据均可在完整原回答精确定位；该门槛为 100%。
- AC-005：目标品牌未在原回答中出现时，目标品牌假阳性为 0，且不产生推荐、排名或有效情绪样本。
- AC-006：模型不输出提及次数、品牌排名数字或 SOV；程序从验证后的表面词、候选顺序和关系计算指标。
- AC-007：目标事实或已返回语义事实无效时不得写入相应指标；竞品发现遗漏或关系覆盖不完整时仍可写目标品牌指标，同时保存 `open_discovery / not_proven`、`partial`、未解决实体 ID 和隔离项。
- AC-008：重试只修复失败阶段或失败字段，已验证实体目录不可被语义修复覆盖。
- AC-009：至少 40 条去重真实回答完成 A/B/C 同题对比，每条每方案重复 3 次；全部原始输出、解析结果、请求参数摘要和人工真值可追溯。
- AC-010：对所有输入有效且完整的冻结回答，`target_fact` 可用率必须为 100%，目标出现与提及次数的重复一致率必须为 100%；不得因开放竞品遗漏或语义未解决降低该完成率。
- AC-011：自动补写语义证据的数量必须为 0；未经确认的派生别名影响目标提及、竞品提及或 SOV 的数量必须为 0；`unresolved/invalid` 被当作已判断业务值参与聚合的数量必须为 0。
- AC-012：任何被保留的实体表面词和关系证据 grounding precision 为 100%，目标品牌出现判断准确率为 100%。开放竞品实体 precision、recall、micro-F1、归一准确率均报告，其中 recall/F1 为诊断项而非整条完成门槛。
- AC-013：已输出竞品关系的 precision 不低于 0.95；推荐 F1 不低于 0.95、目标情绪准确率不低于 0.90、明确排名 exact-match 不低于 0.95，每项作结论的人工真值实例不少于 20 个。竞品召回率、竞品集合 Jaccard、未解决率和隔离率必须报告但不作为目标事实完成门槛。
- AC-014：同一回答 3 次重复运行的目标核心签名一致率不低于 99%，其中目标品牌出现和提及次数一致率为 100%。目标核心签名不包含开放竞品集合和依赖该开放集合的 SOV 分母；后两者单独报告波动。
- AC-015：v5 单条分析的中位总 Token 不超过基线 A 的 1.5 倍，P95 总耗时不超过基线 A 的 2 倍；超过任一门槛不得上线，需先优化或重新批准取舍。
- AC-016：对比报告分别呈现普通样本、历史失败富集样本、目标出现/未出现、长回答、多实体、英文别名和各采集平台分层结果，不用总平均掩盖局部失败。
- AC-017：单问题、问题集、自动监测和 analysis-only 重试均从真实公开入口证明写入 `ai_structured_v5`，且请求证据证明实际调用 Flash v5、没有调用 v4 或 Pro。
- AC-018：正式硬切后，所有新记录和 analysis-only 重试只走 v5；历史 v4 只读，旧运行时代码、默认值、隐藏开关、fallback 和误导文档完成清理。
- AC-019：自动化单元测试、集成测试、全量回归、真实 Flash 基线和正式入口验收全部通过后，需求目录才可从 `draft/active` 进入 `closed`。
- AC-020：开放发现 SOV 使用 `contextual_competitor_mentions_sov_v2_scoped` 并返回 `observed_only / open_discovery / not_proven`；历史 v1 与 v2 不得在同一趋势中静默混算。若未来启用封闭竞品范围，必须使用新的范围和语义版本。

## Metrics / Success

### 质量指标

- `target_fact` 可用率，以及目标语义、开放竞品各自的 `complete / partial / unavailable` 分布；不得只给单一“分析完成率”。
- JSON 可解析率、结构校验通过率、原文锚定通过率；三者分开统计。
- 目标品牌假阳性率和假阴性率。
- 被保留实体表面词的 grounding precision；开放竞品实体 precision / recall / micro-F1 与归一准确率，其中召回只作诊断。
- 已输出竞品关系 precision、未解决率、隔离率和关系覆盖率。
- 候选集合及顺序 exact-match、明确推荐 precision / recall / F1。
- 目标情绪准确率与混淆矩阵。
- “结构合法但语义错误”的错误率。

### 稳定性与成本指标

- 三次重复运行的核心指标签名一致率。
- 首次通过、字段级修复、最终失败的次数分布。
- 每阶段及总 Token 用量、中位与 P95 延迟、模型调用次数。
- 每个有效分析的估算成本，而不是只看每次调用成本。

### 业务保护指标

- 无效分析写入品牌指标的数量必须为 0。
- 目标未出现却被计为已提及的数量必须为 0。
- analysis-only 重试重新调用监测平台或消耗监测配额的数量必须为 0。

## Constraints

- 正式分析必须使用 `deepseek-v4-flash`；不以 Pro 更稳定为理由改变模型。
- 不降低已输出事实的精确证据校验；不要求竞品开放发现完整覆盖，也不用自动补证据把遗漏伪装成已解决。
- 不截断完整原回答，不把长回答拆成彼此独立并直接聚合的多份指标。
- 目标品牌、竞品清单和人工真值不能污染开放实体抽取。
- 对比实验必须冻结相同输入、固定模型和参数，并保留失败输出；不得只重跑失败的候选而不重跑基线。
- 真实回答语料必须脱敏，不保存 API Key、Cookie、浏览器 Profile、联系人信息或服务器绝对证据路径。
- 对模型供应商的 JSON/工具调用能力只视为传输约束，不视为语义正确性证明。
- 程序可以拒绝、隔离和记录坏项，但不得补造模型没有给出的语义证据、推导未注册别名或覆盖模型语义判断来制造表面完成。
- 新实现通过入口验收前不得改为生产默认；通过后必须硬切，不保留静默回退。
