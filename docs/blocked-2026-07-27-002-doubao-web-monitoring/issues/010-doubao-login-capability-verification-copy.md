# 修正豆包登录验证与设置页刷新文案

## Parent

- PRD：`../prd.md`
- Tech Spec：`../TECH-SPEC.md`

## What to build

2026-07-29 产品决策已替代原“深入研究”能力门槛：豆包 Web 正式采集只使用普通模式。设置页的“验证登录”检查明确登录入口、人工验证、页面输入区和普通模式可用性；不得为验证而开启“深入研究”。

保留用户可见按钮名“验证登录”。将只重新读取后端缓存状态的操作命名为“刷新配置信息”，并明确说明该操作只读取浏览器配置、Profile 初始化状态和上次验证结果；真正检查当前网页登录是否仍有效必须点击“验证登录”。

## Acceptance criteria

- [x] 页面存在明确“登录”入口时，“验证登录”返回需要登录；无登录入口且普通输入区和普通模式可用时可验证成功。
- [x] “验证登录”和正式采集均不会主动开启“深入研究”。
- [x] 验证失败不会发送问题，也不会回退豆包 API。
- [x] “验证登录”按钮名称保持不变。
- [x] 只读状态操作命名为“刷新配置信息”，成功提示明确标注“未验证登录”。
- [x] 页面明确说明“刷新配置信息”读取的字段，“验证登录”才检查当前登录。
- [x] DeepSeek Web 既有登录验证行为保持兼容。
