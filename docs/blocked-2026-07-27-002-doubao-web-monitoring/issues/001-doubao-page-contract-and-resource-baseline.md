# 验证豆包页面契约与双浏览器资源基线

## Parent

- PRD：`../prd.md`
- Tech Spec：`../TECH-SPEC.md`

## What to build

在目标虚拟机和已获许可的豆包服务账号中完成一次脱敏技术侦察，形成可供实现和自动化测试使用的豆包页面契约。

契约需要确认豆包正式会话入口及允许源站，并为登录、人工验证、正常会话、新建会话、输入区、普通模式、回答生成状态、当前回答、引用和检索候选定义稳定、可唯一验证的页面特征。

同时运行豆包和 DeepSeek 两个独立的有头 Chrome，记录空闲、单平台采集和双平台采集时的 CPU、内存、响应稳定性与桌面会话表现，形成后续发布验收采用的资源基线。

侦察资料必须脱敏，不保存账号标识、Cookie、Authorization、Token、完整请求头、完整网络响应或可复用的登录资料。若核心搜索状态、新会话隔离或当前最终回答无法可靠识别，应停止后续正式接入并记录阻塞原因。

## Acceptance criteria

- [x] 已确认豆包正式会话入口、允许源站和登录后的稳定页面范围。
- [x] 可以区分正常会话、未登录、需要人工验证和页面结构不匹配状态。
- [x] 可以唯一识别新建会话控件和空白新会话状态。
- [x] 可以确认普通模式，且在“深入研究”残留选中时只关闭一次并再次观测。
- [x] 可以区分回答生成中与生成结束，并唯一识别本次发送后新增的最终回答。
- [ ] 已分别验证有引用和无引用回答，确认引用地址的页面呈现与跳转形式。
- [ ] 已确认普通正文链接、平台引用和页面可见检索候选能够按现有口径区分。
- [ ] 已记录两个独立有头 Chrome 同时运行时的 CPU、内存和稳定性基线。
- [x] 所有留存资料均已脱敏，不包含账号凭据、会话凭据或完整私有响应。
- [x] 已给出“可以继续实现”或“需要阻塞”的明确结论及证据。

阻塞说明：目标 VM 上的有引用/无引用真实回答形态和双 headed Chrome CPU、内存、稳定性基线尚未采集；当前结论为“实现可以继续，但正式启用必须阻塞”。

## 已脱敏页面契约

- 正式入口与允许源站：`https://www.doubao.com/chat/`、`https://www.doubao.com`。
- 登录态唯一输入区：`textarea[placeholder="发消息..."]`。
- 新会话入口：页面可见文案“新对话”的唯一可点击侧栏祖先；空白态路径为 `/chat/`，且不存在回答消息。
- 普通模式：`[data-input-engine-action-source="actionbar"][data-value="25"]` 表示“深入研究”已选中。正式采集不得主动开启；若新会话残留该选中态，只在 `button[data-skill-id="skill_bar_button_25"]` 唯一时点击一次关闭，并在选中态数量为 `0` 后发送问题。
- 回答归属：消息容器使用 `data-message-id`；用户消息具有 `justify-end`，回答消息不具有该类并包含 `.md-box-root`。
- 生成结束：本次新增回答的 `.md-box-root[data-streaming="false"]`、页面无 busy、正文非空且经过稳定窗口。
- 检索候选块：`data-plugin-identifier` 包含 `search_query_result_block.search_type:1`。它不是平台引用，不能进入引用 KPI。
- 平台引用：普通模式最终回答根中的 `a[href]` 指向 `https://link.wtturl.cn/` 安全跳转，真实外部来源位于 `target` 参数。采集器只对该已验证跳转域解析 `target`，并只接受无账号凭据的 HTTP/HTTPS 目标 URL；搜索进度块中的链接不计为最终回答引用。
