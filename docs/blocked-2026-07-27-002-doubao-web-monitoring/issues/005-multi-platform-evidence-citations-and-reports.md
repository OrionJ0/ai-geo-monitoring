# 接入多平台证据、引用、历史与报告

## Parent

- PRD：`../prd.md`
- Tech Spec：`../TECH-SPEC.md`
- 覆盖用户故事：US-002、US-005、US-010

## What to build

让豆包 Web 的回答、引用和截图完整进入现有证据访问、结构化分析、历史记录、运行报告、平台筛选和导出链路，并建立多 Web 证据目录的统一协调能力。

证据读取必须根据数据库记录的平台选择正确 Store。重试记录引用原记录证据时，原记录与当前记录的平台必须一致。删除历史、清理分析或永久删除项目时，相关平台证据应以可恢复的隔离流程同步处理；多个 Store 中任一步骤失败都不能留下数据库已回滚但证据未恢复的状态。

平台引用继续使用现有内部角色进入引用 KPI；回答正文中的普通链接由现有分析逻辑归为正文链接，页面检索候选保持非 KPI。用户界面和新文档只显示“引用”或“引用源”。

## Acceptance criteria

- [x] 豆包 Web 证据只从豆包证据 Store 读取，DeepSeek Web 证据只从 DeepSeek Store 读取。
- [x] artifact id、记录归属、用户权限和 owner 记录均在访问 Store 前完成校验。
- [x] 跨平台 artifact owner 关系被拒绝，不能通过豆包记录读取 DeepSeek 证据或反向读取。
- [x] 删除多个平台记录时按平台隔离证据，任一 Store 失败会恢复此前已隔离内容。
- [x] 数据库提交后发生物理清理失败时保留现有不完整清理错误语义，并能定位涉及的平台。
- [x] 应用启动会恢复或清理全部注册 Web 平台的隔离证据。
- [x] 终态栅栏拒绝和 Worker 异常会按记录平台丢弃本次新证据。
- [x] 豆包平台引用进入引用 KPI，普通正文链接和检索候选不进入。
- [x] 搜索已验证但没有平台引用的记录进入可验证样本口径，引用数量为 0。
- [x] Web 采集成功但结构化分析失败时保留原回答、引用、截图和采集信息。
- [x] 仅分析重试不重新访问豆包页面。
- [x] 历史、筛选、报告、CSV 和 PDF 始终区分 `doubao`、`doubao-web` 与 `deepseek-web`。
- [x] 报告可以查看豆包联网状态截图和最终回答截图。
- [x] 删除普通历史记录或永久删除项目后，对应豆包证据被物理清理。
- [x] 用户可见术语统一为“引用”或“引用源”。
