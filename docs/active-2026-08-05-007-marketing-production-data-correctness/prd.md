# 营销生产数据正确性与双周期回归 PRD

## Problem Statement

2026-08-05 真实浏览器和接口审计证明，百度推广与百度统计已经在生产提供真实数据，但仍有三类未关闭的页面正确性问题：

1. 广告表现页和关键词页只请求本期，没有请求等长上期；前端因此把有可能存在的上期数据显示为 `0` 或 `—`。搜索词页能够读取上期，已证明问题不等同于“百度上游没有上期数据”。
2. 百度统计全站访问数与页面展示的来源分类合计没有完成诚实对账。审计样本为全站访问 `83`、可见来源合计 `82`；现役校验在任一来源指标为空时会跳过整个分区校验，页面却没有明确说明分类覆盖不完整。
3. 入口页报告保留多个上游页面事实，但规范化展示后可能出现相同路径，例如多条记录都显示为首页 `/`。用户无法判断它们是重复展示、不同上游页面事实，还是应当合并的数据。

同一轮审计发现的市场总览“营销指标必须是十进制字符串”崩溃已经由独立需求修复并验收，不在本需求重复实施。官网生产接入、53KF、线索入池、成交订单和营销 AI 也已有独立需求或明确的未接入状态，不纳入本需求。

这些问题不是凭据或上游接入问题，而是内部 API 消费、后处理、完整性表达和回归样本不足。若先执行 005 Provider 模块化，就会把已知错误行为冻结成“等价基线”，随后还要再次搬动统计 parser 和页面语义。因此正确顺序是先稳定凭据和公开读 API，再修正数据行为，最后做纯等价重构。

## Solution

本需求在 003 和 006 关闭后实施，在 005 之前完成：

```text
003 统一 OAuth
  → 006 广告 API 资源化
  → 007 生产数据正确性与回归
  → 005 Provider 模块化等价重构
```

007 使用 006 最终的轻量 Dashboard、广告层级和关键词资源完成本期/上期双周期读取；为百度统计来源分区增加可机读的完整性状态；为同路径页面事实提供稳定消歧；并用脱敏后的内部标准响应建立生产形状回归。

原则：

- 不把缺失上期当成零；
- 不靠“总量减已分类量”创造新的业务来源；
- 不在缺少可加分母时合并比率指标；
- 不复制生产 Token、数据库或个人信息到本地；
- 页面、接口、自动化和真实生产证据必须彼此对得上。

## User Stories

1. As a 市场负责人, I want 广告和关键词指标显示真实等长上期, so that 环比不会把未请求的数据误认为零。
2. As a 流量分析人员, I want 来源分类明确说明是否覆盖全站访问, so that `83` 与 `82` 的差异不会被伪装成完整分类。
3. As a 网站分析人员, I want 相同展示路径的入口页记录可以被区分, so that 我不会误以为页面重复渲染或错误合并。
4. As a 开发人员, I want 本地有脱敏的生产响应形状回归, so that 无需生产 Token 也能复现空值、双周期和同路径记录。
5. As a 运维人员, I want 正式入口逐页验收并保留接口证据, so that “测试通过”不会替代生产行为验证。

## Scope

### In scope

- 广告表现页本期与等长上期读取、汇总和比较；
- 关键词页本期与等长上期读取、汇总和比较；
- 双周期请求使用同一成功 `revision`、同一币种和 cost scale；
- 上期不可用时展示不可用状态，不展示伪造的 `0`；
- 百度统计来源分类的完整、部分、无效三类判断与用户提示；
- 保留总访问、已分类访问、未覆盖差额和原因码等对账证据；
- 百度统计页面事实保留上游稳定身份，并为相同规范化路径提供稳定消歧；
- 脱敏的内部标准 API fixture，覆盖生产发现的边界形状；
- 后端合同测试、前端 hook/adapter 测试、浏览器回归和正式入口复验；
- 更新现役文档，明确修复结果和仍未接入的数据源。

### Out of scope

- 重做已关闭的市场总览十进制字符串修复；
- 修改 003 的凭据统一、Token 迁移、授权或产品状态；
- 修改 006 的资源边界、revision 选择原则或旧 Dashboard 退役目标；
- 执行 005 的 Provider 物理拆分；
- 向本地复制生产 Access Token、Refresh Token、数据库或服务器 `.env`；
- 启用官网生产模块；该工作属于 004；
- 接入 53KF、销售线索、成交订单或营销 AI；
- 把百度推广、百度统计、官网或销售同期数据拼成归因事实；
- 把单次短暂 `502` 直接定义为新稳定性项目；只有复现并定位后才另立需求；
- 新增多账号、多统计用户名、URL API 版本或上游合同漂移平台。

### Later

- 若 `502` 能稳定复现或监控证明持续发生，再建立独立 SRE 需求；
- 若未来出现真实的仓库外消费者，再评估公开 API 弃用和版本治理。

## Product Behavior

### 1. 开始与实施门禁

文档可以现在建立。代码实施必须等待：

- 003 完成 A2、生产验收并关闭；
- 006 完成 R2、轻量 Dashboard 成为唯一合同并关闭；
- 006 已为广告层级和关键词资源提供“全部筛选结果汇总”，不要求前端下载全部分页记录计算指标。

007 完成、生产观察且关闭前，005 不得冻结 Provider 等价合同或开始搬移统计 parser。

### 2. 广告表现双周期

页面以用户所选本期计算等长、紧邻的上期。先读取轻量 Dashboard 得到成功快照 `revision`，再用同一 revision 分别请求本期和上期广告层级资源。

- 本期成功、上期成功：展示真实环比；
- 本期成功、上期无数据或超出 coverage：本期正常展示，上期与环比显示不可用；
- 本期失败：页面进入现役错误状态，不能用上期代替本期；
- 切换日期或项目后，过期响应不得覆盖新选择；
- 本期和上期必须使用同一币种、cost scale 和 revision。

### 3. 关键词双周期

关键词列表继续只分页读取本期明细；指标卡分别读取本期和上期资源返回的全筛选范围 `summary`。上期比较不能通过下载全部关键词页、读取当前可见页或用 `0` 补齐实现。

筛选条件应在可比较范围内保持一致。若某个筛选键在上期不存在，合法结果是空集合；若资源或快照不可用，则显示不可用，不将二者混为一类。

### 4. 来源分类完整性

来源比较明确返回以下状态：

- `COMPLETE`：所有必需来源指标可用，已分类访问合计等于全站访问；
- `PARTIAL`：至少一个来源不可用，或已分类访问小于全站访问；页面明确提示分类覆盖不完整；
- `INVALID`：已分类访问大于全站访问、出现负数或合同不可能成立；接口拒绝把结果作为可信数据返回。

当总访问和已分类访问都精确可用时，可以计算差额作为“未被当前分类覆盖的访问数”。该差额只是数据覆盖证据：

- 不新增为一个业务来源行；
- 不命名为“直接访问”“其他”“百度自然搜索”等未经证明的渠道；
- 不参与跨系统归因；
- 页面同时展示总量、已分类量和覆盖状态。

### 5. 同路径页面事实

页面报告继续以百度上游稳定页面身份区分事实，路径只作为展示字段。若多条事实规范化为相同路径：

- 保持多条记录，不静默删除；
- 使用稳定顺序展示“同路径记录 1/3、2/3、3/3”等消歧信息；
- 消歧计数基于完整过滤结果，在分页前计算；
- 不直接把浏览量、退出率、平均停留等记录合并；只有未来证明所有加总分母和语义后才能另行设计聚合。

### 6. 本地生产形状回归

本地只保存系统已经规范化后的脱敏 API fixture，不保存百度原始报文或生产凭据。fixture 至少覆盖：

- 全站访问 `83`、已分类访问 `82`；
- 相同规范化路径的多个页面事实；
- 本期与上期同 revision 且都有数据；
- 本期存在、上期不可用；
- 趋势部分日期或指标为空；
- 精确十进制字符串、零值和缺失值同时出现。

fixture 不得包含 Token、Secret、统计用户名、真实关键词、真实搜索词、联系人、电话、邮箱、IP 或会话标识。

### 7. 正式入口验证

从 `https://insight.guangtuo.com` 登录后真实查看市场总览、广告表现、关键词、搜索词、网站流量和入口页。验收必须同时记录：

- 目标前后端 revision；
- 浏览器请求路径、日期、revision 和状态码；
- 本期/上期是否实际请求；
- 来源总量与分类合计；
- 同路径记录的消歧结果；
- 官网、53KF、销售和 AI 的真实模块状态。

不能把 fixture、单元测试或本地假数据描述为生产已修复。

## Acceptance Criteria

- AC-001：003 或 006 未关闭时，007 保持草案，不修改代码或生产合同。
- AC-002：广告表现页实际请求本期和等长上期，并使用同一成功 revision、币种和 cost scale。
- AC-003：关键词页的本期和上期指标来自对应完整筛选范围 summary，不来自当前页、全量客户端下载或补零。
- AC-004：上期不可用时，本期仍正常展示，上期和环比为不可用而不是 `0`。
- AC-005：切换项目、日期或筛选时，旧的双周期响应不能覆盖新状态。
- AC-006：来源分类完整时，已分类访问精确等于全站访问；不完整时返回 `PARTIAL` 和可解释的覆盖证据。
- AC-007：已分类访问大于全站访问或出现其他不可能合同值时，接口返回稳定错误，不展示为可信报表。
- AC-008：未覆盖差额不成为业务来源、不参与归因，也不被命名为未经证明的渠道。
- AC-009：相同规范化路径的页面事实保留稳定身份和消歧信息，分页、排序或刷新后标签稳定。
- AC-010：同路径记录不在缺少可加分母时合并比率指标。
- AC-011：脱敏 fixture 覆盖审计发现的生产形状，且凭据、个人信息、真实查询词和原始上游响应扫描为零。
- AC-012：后端合同、前端 hook/adapter 和浏览器回归覆盖双周期、83/82、同路径、空值和过期响应。
- AC-013：从正式域名逐页验证生产响应与页面语义正确后，007 才可关闭。
- AC-014：004、53KF、销售与营销 AI 的未接入状态继续诚实显示，不因本需求补零或伪造指标。
- AC-015：007 关闭后，005 才能以修正后的行为作为等价基线开始实现。

## Metrics / Success

- 广告表现和关键词页面的上期实际请求覆盖率为 100%；
- 可用上期被显示为伪造零值的次数为 0；
- 来源报表中“总量与分类不一致但仍标记完整”的次数为 0；
- 相同路径但无法区分的页面记录数为 0；
- 双周期跨 revision 混读事件为 0；
- 生产形状回归覆盖本需求列出的六类边界场景；
- 本地或 Git 中新增生产秘密和个人信息数量为 0；
- 正式入口遗留的本需求 P0/P1 数量为 0。

## Constraints

- 正式入口固定为 `https://insight.guangtuo.com`；
- 生产 Token 只保留在服务器数据库密文和服务端内存；
- 精确数值继续使用十进制字符串，不经过浮点计算；
- 006 的 revision、权限先行、coverage 和资源边界继续是正式合同；
- 百度统计、百度推广和官网的数据源边界继续遵循 ADR 0001；
- 不修改已应用迁移；预期无需数据库迁移；
- 不建立长期 feature flag、第二套 API 或失败后的旧 Dashboard fallback；
- 007 与 005 的实现和生产观察窗口不得重叠。

## Open Questions

以下问题在 007 实现前由脱敏生产样本和现役合同测试回答，不改变需求方向：

1. 审计样本中未覆盖的 `1` 次访问具体来自上游空指标、未映射来源还是分页/过滤边界？
2. 同路径记录的稳定排序应优先使用数字 page ID 还是原始不透明字符串顺序？
3. 广告层级和关键词 summary 应包含哪些现役指标，才能覆盖页面卡片而不扩大合同？

无论答案如何，都不得通过猜测渠道、合并不同比率事实或复制生产 Token 解决。
