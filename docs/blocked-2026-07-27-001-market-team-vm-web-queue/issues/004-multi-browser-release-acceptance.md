# 完成多浏览器共享队列的真实入口发布验收

## Parent

- PRD：`docs/blocked-2026-07-27-001-market-team-vm-web-queue/prd.md`

## User stories covered

- US-1 至 US-10。

## What to build

从市场部实际使用入口验证“多个个人浏览器同时提交、虚拟机单浏览器串行消费”的完整闭环。自动化测试先证明不同幂等键分别建档、同一幂等键防重、所有 Web 记录进入同一 FIFO、最大页面采集并发为 1，并证明 API 平台不受 Web 队列阻塞。

随后在目标虚拟机使用两个真实浏览器会话和同一个共享 admin，分别提交单问题与问题集，核对公共通道状态、暂停/恢复口径、持续轮询、独立运行报告、浏览器进程、profile lock、异常恢复和无 API fallback。发布证据必须脱敏；如果新状态接口或组件失败，只回滚本期状态展示，不恢复旧项目级手动入口或改变既有 Web Adapter、FIFO、报告与重试链路。

## Acceptance criteria

- [ ] 两个浏览器同时提交不同问题时返回两个独立运行报告，两次运行均不会丢失。
- [ ] 两个浏览器主动提交同一个问题且使用不同幂等键时创建两次独立样本，不被静默合并。
- [ ] 同一幂等键的并发重复请求只创建一次运行、配额预留和任务记录。
- [ ] 一个问题集与一个单问题同时提交时，所有 Web 记录进入同一 FIFO，页面采集最大并发为 1。
- [ ] DeepSeek API 和其他 API 平台可以与 Web 任务并行完成，不等待 Web FIFO。
- [ ] 公共状态在真实排队期间展示 `busy`、活动数量和等待数量，不显示精确位置或 ETA。
- [ ] 暂停问题集后，无有效租约的休眠 pending 不计入公共等待数；暂停前已取得有效租约的记录允许完成，租约过期后排除，恢复后休眠记录重新计入。
- [ ] 暂停提示为“已开始调度的任务完成后暂停”，即使多个 worker 已取得租约，真实页面采集最大并发仍为 1。
- [ ] 两个浏览器持续查看状态和运行报告至少 15 分钟时，正常轮询不返回 429；running/paused 报告分别按 10/30 秒刷新。
- [ ] 打开历史抽屉后，历史列表不随每次报告定时轮询重复刷新，只在打开、主动刷新或当前报告终态转换时刷新。
- [ ] 用户关闭个人浏览器或离开报告页后，虚拟机中的已提交任务继续执行并更新持久报告。
- [ ] 连续处理不同浏览器提交的问题时，每条 Web 记录使用新对话，不发生上下文串扰。
- [ ] 登录失效或需要验证时，公共状态提示联系虚拟机运维负责人，已有失败运行保留重试入口。
- [ ] 完成人工登录、验证或账号切换后必须重启后端，旧进程内熔断清除后才能从正式入口恢复运行。
- [ ] Chrome 异常回收后，下一条允许执行的任务可以启动新会话；已经发送的问题不会自动重发。
- [ ] 任意 Web 失败都不调用 DeepSeek API、不生成替代回答、不写入假成功指标。
- [ ] `deepseek` 与 `deepseek-web` 在运行、历史、报告、筛选、聚合和导出中保持独立。
- [ ] 重复执行生产启动不会产生第二个受管后端；停止服务后 Chrome 关闭且 profile lock 释放。
- [ ] 后端完整测试、前端工具测试、lint 和 production build 全部通过。
- [ ] 发布证据包含脱敏的状态响应、两次运行报告、最大 Web 并发断言和 VM 浏览器进程证据，不含账号、密码、Token、Cookie、Authorization 或 profile 内容。

## Blocked by

- 需要目标虚拟机访问、共享 `admin` 登录态、已登录的 DeepSeek Web 服务账号，以及两个独立真实浏览器会话。

## 已完成的自动化验收

- 不同幂等键并发提交会创建两次独立运行；同一幂等键并发重放只创建一次运行、任务和配额记录。
- 单问题、问题集与定时入口共享同一个 Web FIFO，自动化观测到的页面采集最大并发为 1。
- 活动 Web 查询不会串行阻塞 API 平台查询；Web 失败不会回退 DeepSeek API。
- 数据库集成测试覆盖 active、paused、有效租约、过期租约、孤儿父记录和无父运行记录的公共等待数。
- 后端完整测试、前端完整工具测试、lint、production build、部署与生产进程管理测试均已通过。

## 目标虚拟机待验收

- [ ] 使用两个真实浏览器和同一共享 `admin`，分别提交单问题与问题集并保存两份脱敏报告证据。
- [ ] 连续观察状态与报告至少 15 分钟，确认无正常轮询 429，且 running/paused 为 10/30 秒。
- [ ] 核对真实排队、暂停/恢复、浏览器关闭后任务继续、每条记录新对话以及无上下文串扰。
- [ ] 实际执行 `prod:stop → web:login → prod:start`，确认登录/验证状态恢复、旧熔断清除、失败运行仍可显式重试。
- [ ] 重复生产启动并停止服务，保存单后端 PID、专用 Chrome 关闭和 profile lock 释放的脱敏证据。
- [ ] 核对真实响应和证据中不含账号、密码、Token、Cookie、Authorization 或 profile 内容。
