# 单品牌配置与 AI 平台运行范围收敛技术方案

## 1. 背景与目标

正式产品已经使用默认项目提供单品牌上下文，但品牌管理 UI、平台范围和运行前置检查仍沿用多项目设计。本方案把正式入口硬切到“默认品牌 + 全局启用平台”，同时保护历史数据和生产默认项目。

## 2. 范围与非目标

- 范围：
  - 管理员单品牌资料与竞品管理。
  - 全局启用平台成为新运行唯一范围。
  - 平台不可用时部分执行和原运行快照重试。
  - 默认品牌生命周期、权限和历史数据保护。
  - 正式入口、测试与文档同步切换。
- 非目标：
  - 数据库物理删除遗留平台 JSON 字段。
  - 历史指标追溯重算。
  - 多品牌工作区重新设计。
- 延后事项：
  - 旧导入格式完全退役后再做遗留字段迁移。

## 3. 当前系统认知

- 相关入口：
  - `nextjs-frontend/src/app/admin/settings/WorkspaceSettings.tsx`
  - `nextjs-frontend/src/app/geo/projects/page.tsx`
  - `nextjs-frontend/src/app/geo/prompts/page.tsx`
  - `backend/routes/geoProjects.js`
  - `backend/services/ProjectRunService.js`
  - `backend/services/SchedulerService.js`
- 现有数据流：
  - `AIPlatformConfig.enabled`、`BrandProject.platforms`、`TrackedPrompt.platforms` 三层交集形成候选任务。
  - `ProjectRunService.planProjectRun` 对候选平台做实时可用性检查。
  - 受管 Web 预检失败通过 `buildWebPreflightFailure` 阻断整次运行。
  - 运行报告已经持久化 `planned_platforms`、`skipped_platforms` 和逐条 `QuestionRecord.platform`。
- 现有测试：
  - 后端 Node test 覆盖平台配置、运行计划、问题集幂等、重试、调度和项目生命周期。
  - 前端 Node contract test、ESLint、Next.js production build。
- 需要沿用的模式：
  - `DefaultProjectContextService` 提供稳定错误码。
  - `AIPlatformService.getPlatformAvailability` 统一结构配置和 Web 实时探测。
  - 配额和问题集记录在同一事务内创建。
  - 生成报告可失效，已保存的来源证据和指标不可静默重写。

## 4. 需求、约束与规则

- REQ-001：品牌配置正式入口必须位于管理员设置中心。
- REQ-002：全局已启用、具备 `monitoring` 能力的平台是新运行唯一候选范围。
- REQ-003：实时不可用平台只影响自身；至少一个可用平台时继续运行。
- REQ-004：重试保持原运行的记录平台集合。
- REQ-005：默认品牌不可归档或删除。
- REQ-006：品牌资料变更不删除历史记录和指标。
- CON-001：生产数据库、Token、浏览器 Profile 不进入 Git。
- CON-002：遗留平台字段可读但不得参与正式入口决策。
- PAT-001：所有品牌配置写操作必须校验管理员身份。

## 5. 接口与数据契约

### 输入

- 品牌资料更新继续使用 `PUT /api/geo-projects/:id`，只接受现有标准字段；`platforms` 不再作为正式配置输入。
- 问题创建和更新继续使用现有接口；客户端不再发送 `platforms`，服务端新写入使用空数组以保持当前 schema。
- 平台启停继续使用 `/api/admin/ai-platforms/:id/enabled`。
- 运行接口不再接受或解释项目/问题平台范围。

### 输出

- 默认项目读取继续返回品牌基本信息，避免影响现有工作台上下文。
- 运行结果继续返回：
  - `planned_platforms`：本次实际创建任务的平台。
  - `skipped_platforms`：已启用但实时不可用的平台和稳定原因。
- 历史运行继续从运行/记录快照读取平台，不从当前配置反推。

### 状态与错误

- `platform_not_configured` / 409：平台基础配置不完整，拒绝启用。
- `default_project_lifecycle_protected` / 409：默认品牌不能归档或删除。
- `all_platforms_unavailable` / 400：没有可执行平台；不扣配额、不创建记录。
- 部分平台不可用不返回全局错误，成功响应中携带 `skipped_platforms`。

### 兼容性

- `BrandProject.platforms`、`TrackedPrompt.platforms` 保留为历史 schema 字段，新写入为空数组。
- 旧记录、旧报告和导入数据中的平台值继续按历史事实展示。
- 不保留旧平台交集逻辑、Web 全局阻断逻辑或隐藏 UI 作为 fallback。

## 6. 关键技术决策

- KTD-001：新增“已启用监测平台代码”查询，与“可选择平台”区分。前者包含启用但配置异常的平台，以便运行报告能说明跳过原因；后者仍服务于其他需要可用配置的功能。
- KTD-002：运行计划先取全局已启用监测平台，再对全部代码统一调用实时 availability；仅可用项构建记录和扣配额。
- KTD-003：删除 Web 平台专属的整批阻断分支。Web 与 API 平台采用相同的跳过语义。
- KTD-004：问题集幂等指纹只描述用户请求（项目、问题集、问题内容），不包含会随管理员设置变化的平台范围；同一幂等键始终重放原运行。
- KTD-005：品牌资料更新只删除可再生成的 `ReportSnapshot`，不调用项目分析数据清理。
- KTD-006：默认品牌保护在领域服务中执行，路由必须处理服务返回，避免其他调用方绕过。

## 7. 实现切片

### U1. 管理员单品牌配置入口

**目标：** 设置中心直接维护默认品牌、自动监测和竞品，退役 `/geo/projects` UI。
**依赖：** 无。
**涉及文件：** 设置中心组件、项目路由、默认上下文和前端 contract tests。
**方案：** 默认品牌存在时直接加载项目详情；未配置时保留一次性迁移选择。品牌与竞品写接口增加管理员校验，项目页重定向到工作台设置。
**测试场景：** 管理员读取/保存、普通用户拒绝、旧入口跳转、页面无品牌平台选择。
**验收方式：** 设置中心可完成广拓资料与竞品维护。

### U2. 全局启用平台成为唯一范围

**目标：** 新运行不再读取品牌/问题平台字段。
**依赖：** U1。
**涉及文件：** 平台配置服务、运行计划、问题路由、调度入口、问题库 UI 和服务测试。
**方案：** 增加全局启用监测平台查询；平台启用前验证基础配置；运行目标为“启用问题 × 全局启用平台”；新品牌/问题平台字段写空数组。
**测试场景：** 遗留字段互相冲突、新平台启用、未配置平台启用拒绝、自动监测入口。
**验收方式：** 测试证明新运行覆盖全部全局启用平台且不引用遗留范围。

### U3. 部分失败与原运行快照重试

**目标：** 单个平台不可用不阻断其他平台，重试不受当前品牌范围影响。
**依赖：** U2。
**涉及文件：** 运行计划、重试逻辑、运行报告测试与前端提示。
**方案：** 删除 Web 整批 preflight error；availability 不可用项写入跳过快照；重试候选来自失败记录本身，并重新检查该原平台当前可用性。
**测试场景：** Web 登录失效 + API 可用、全部不可用、部分任务配额、原平台重试、新启用平台不追加旧运行。
**验收方式：** 部分运行成功并携带跳过项，配额与记录数等于可执行目标数。

### U4. 默认品牌和历史数据保护

**目标：** 防止默认工作台失效和历史证据丢失。
**依赖：** U1。
**涉及文件：** 默认项目服务、归档/删除服务、项目更新路由和生命周期测试。
**方案：** 归档/删除服务读取默认项目设置并返回稳定 409；品牌分析字段更新只失效生成报告。设置 UI 提示新配置仅影响未来运行。
**测试场景：** 默认品牌归档、删除、品牌资料修改后的记录/指标保留、报告失效。
**验收方式：** 生命周期误操作被拒绝，历史表无删除调用。

## 8. 验收标准

- AC-001：Given 已有默认品牌，When 管理员打开工作台设置，Then 可编辑全部品牌资料、自动监测和竞品。
- AC-002：Given 旧项目地址，When 用户访问，Then 跳转到设置中心工作台。
- AC-003：Given 品牌和问题遗留平台字段不含新平台，When 管理员启用该平台并运行，Then 新平台进入候选。
- AC-004：Given 一个 Web 平台预检失败且一个 API 平台可用，When 运行，Then API 任务创建且 Web 平台列为跳过。
- AC-005：Given 全部启用平台不可用，When 运行，Then 不创建任务且不扣配额。
- AC-006：Given 原运行平台后来不在遗留项目范围，When 重试失败项，Then 仍按原记录平台检查并在可用时重试。
- AC-007：Given 目标是默认品牌，When 归档或删除，Then 返回 409 且品牌保持活动。
- AC-008：Given 品牌资料变化，When 保存，Then历史记录和指标保持，生成报告失效。

## 9. 测试与验证计划

- 单元测试：
  - 平台启用配置门禁。
  - 运行目标构造、部分跳过、全部不可用和配额。
  - 原运行平台重试。
  - 默认品牌归档/删除保护。
- 集成测试：
  - 项目路由权限、问题写入和问题集运行计划。
  - 调度入口调用统一运行范围。
- 前端测试：
  - 单品牌设置入口和旧入口重定向 contract。
  - 问题库无平台选择和使用全局目录状态。
- 构建/脚本/日志证据：
  - 后端全量测试、前端 Node tests、lint、Next production build。
  - 部署前检查、服务状态、公开 `/api/ready` 与生产日志。

## 10. 风险与缓解

- 风险：启用平台数增加会放大每次任务数和配额消耗。
  - 缓解：运行响应展示实际计划数；配额仅按实时可用任务数计算。
- 风险：Web 登录失效会产生不完整跨平台样本。
  - 缓解：报告明确保存跳过平台快照，不伪造完整覆盖。
- 风险：品牌资料修改后新旧结果使用不同实体词。
  - 缓解：不追溯改写历史；设置页明确生效边界，历史结果保留生成时事实。
- 风险：旧调用方继续发送 `platforms`。
  - 缓解：服务端忽略该遗留输入且不将其用于决策；正式 UI 不再发送。

## 11. 假设与开放问题

- 假设当前共享管理员模式继续有效。
- 假设生产默认品牌已配置为广拓；首次安装仍允许管理员创建并选择第一个项目。
- 无阻塞开放问题。
