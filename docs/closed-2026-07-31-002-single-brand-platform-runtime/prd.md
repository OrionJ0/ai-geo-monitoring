# 单品牌配置与 AI 平台运行范围收敛 PRD

## Problem Statement

当前系统已经按内部单品牌方式使用，但正式界面和运行逻辑仍保留多项目时代的残余：

- 管理员设置中心只能选择默认项目，无法直接维护品牌名称、别名、官网、行业、核心关键词和竞品；完整配置藏在已移出导航的 `/geo/projects`。
- AI 平台设置、品牌项目和单个问题分别保存平台范围。管理员在“AI 平台”中启用平台后，运行仍可能因为项目或问题旧字段未包含该平台而不执行。
- 任一受管 Web 平台登录失效会阻断整次运行，即使其他启用平台仍可运行。
- 默认品牌仍可被归档或删除；品牌资料变化还会清空已有监测记录和指标。

这些行为与“内部单品牌、管理员启用哪些平台就运行哪些平台”的实际使用方式不一致，也会让历史数据和默认工作台失效。

## Solution

将产品正式行为收敛为：

1. 管理员在设置中心直接维护唯一默认品牌的资料、自动监测和竞品。
2. “AI 平台”中的启用状态是新运行唯一的平台范围来源。问题和品牌不再单独选择平台。
3. 每次运行对全部已启用、具备监测能力的平台做实时可用性检查；可用平台继续执行，不可用平台在报告中明确列为跳过。
4. 默认品牌不可归档或删除；品牌资料修改仅影响后续运行，既有记录和指标保持不变。

## User Stories

1. As an 管理员, I want 在设置中心直接维护广拓品牌资料和竞品, so that 不需要寻找隐藏的项目管理页。
2. As an 管理员, I want 只在 AI 平台设置中控制平台启停, so that 不需要在品牌和每个问题上重复配置。
3. As an 市场人员, I want 一次运行覆盖所有当前启用平台, so that 新启用的平台会自动进入后续监测。
4. As an 市场人员, I want 某个平台不可用时其他平台继续运行, so that 一个网页登录失效不会让全部数据停止更新。
5. As an 管理员, I want 默认品牌及历史数据受到保护, so that 配置调整不会破坏工作台或清空既有证据。

## Scope

- In scope:
  - 设置中心“工作台”页签改为单品牌资料、自动监测和竞品配置入口。
  - `/geo/projects` 正式入口退役并跳转到设置中心。
  - 品牌、问题的正式 UI 和新写入不再配置平台范围。
  - 新的单问题、问题集和项目自动监测统一使用全局已启用监测平台。
  - 启用未完成基础配置的平台时给出明确拒绝。
  - 平台实时不可用时部分执行、记录跳过原因，并只对实际创建的任务计费。
  - 失败重试以原运行记录的平台为目标，不因品牌或问题旧平台字段变化而丢失。
  - 默认品牌禁止归档和删除。
  - 品牌资料更新保留历史记录与指标，仅使已生成的汇总报告失效。
- Out of scope:
  - 删除数据库中历史 `brand_projects.platforms`、`tracked_prompts.platforms` 字段。
  - 追溯重算品牌资料修改前的历史指标。
  - 自动修复 Web 平台登录、验证码或第三方账号状态。
  - 多品牌、多工作区和人员级审计。
- Later:
  - 在完成旧 CSV/历史兼容淘汰后移除遗留平台字段。

## Product Behavior

- 管理员打开“设置中心 → 工作台”时：
  - 已配置默认品牌：直接显示并允许编辑品牌名称、别名、官网、行业、核心关键词、自动监测开关、每日监测时间和竞品。
  - 未配置默认品牌：显示迁移用的活动项目选择器，设置后进入单品牌模式。
- 品牌资料保存后显示“仅影响后续运行，历史数据不会重算或删除”的说明。
- “AI 平台”中的启用操作：
  - 平台基础配置完整时允许启用。
  - API 平台缺少密钥、地址或模型，或受管平台预置结构无效时拒绝启用，并提示先完成配置。
  - Web 平台之后出现登录失效时仍保持“已启用”，但运行时会被跳过并显示原因。
- 新运行：
  - 每个启用问题对全部全局已启用且具备监测能力的平台生成候选任务。
  - 实时检查后至少一个平台可用：只创建可用平台任务；不可用平台进入 `skipped_platforms`。
  - 全部平台不可用：不创建记录、不消耗配额，并返回明确错误。
  - 报告保留本次实际运行平台和跳过平台快照。
- 重试：
  - 只针对原运行中的失败记录。
  - 当前仍可用的原平台可以重试；当前不可用的原平台保留失败记录并列为跳过。
  - 不把本次新启用但不在原运行中的平台追加到旧运行。
- 默认品牌：
  - 归档和永久删除均返回稳定的 409 错误。
  - 品牌资料更新不删除 `QuestionRecord`、`ResultDetail` 或 `VisibilityMetric`。
- 权限：
  - 品牌资料、竞品、默认项目、项目创建/归档/删除只允许管理员操作。
  - 普通登录用户继续读取默认品牌并使用监测功能。

## Acceptance Criteria

- AC-001: 管理员可在设置中心完整查看并保存默认品牌资料、自动监测和竞品，页面不存在品牌级平台选择器。
- AC-002: `/geo/projects` 会跳转到 `/admin/settings#workspace`，不再提供第二套项目管理 UI。
- AC-003: 普通用户不能修改品牌资料、竞品或项目生命周期。
- AC-004: 未完成基础配置的平台不能被启用；错误码和提示稳定可识别。
- AC-005: 新运行忽略品牌和问题的遗留平台字段，并为每个启用问题使用全部全局已启用监测平台。
- AC-006: 至少一个平台可用时运行继续，跳过项进入报告且配额只按实际任务数扣减；全部不可用时不创建任务、不扣配额。
- AC-007: 失败重试只使用原运行记录的平台快照，并按重试时可用性决定执行或跳过。
- AC-008: 项目自动监测与手动运行使用相同的全局启用平台规则。
- AC-009: 默认品牌不能归档或删除；品牌资料更新不会删除历史记录和指标。
- AC-010: 正式入口级测试、后端回归、前端测试、lint 和生产构建全部通过。

## Metrics / Success

- 管理员完成品牌资料维护不需要访问 `/geo/projects`。
- 新启用且配置完整的平台在下一次运行自动进入计划。
- 单个平台不可用时，其他可用平台仍能创建任务并形成报告。
- 品牌资料保存前后的历史记录数和指标数不减少。
- 默认品牌生命周期误操作被 100% 拒绝。

## Constraints

- 系统为内部单品牌软件，现有默认品牌和生产 Token 必须保留。
- 运行时仍需实时验证受管 Web 平台登录和浏览器状态。
- 遗留平台字段暂留数据库以读取历史数据和兼容旧导入，不得再参与正式运行决策。
- 修改、测试、提交和推送均先在本地完成，再通过仓库部署入口发布；不得直接编辑服务器源码。
